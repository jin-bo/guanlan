# P5.6 — 快速收录（`guanlan ingest --flash`）

> **状态**：第一期已实现（2026-11-23）：CLI `ingest --flash`、完整 ingest 加深时清标记、`health` 列「待加深」。对照实验见 §6。
> **来源**：入库性能调研（[`backlog/notes/ingest-performance-research.md`](backlog/notes/ingest-performance-research.md)、[`ingest-next-optimizations.md`](backlog/notes/ingest-next-optimizations.md)、[`ingest-history-and-batching.md`](backlog/notes/ingest-history-and-batching.md)）。
> **目标**：资料先「收录」、以后再「融入」。一篇资料几十秒进库、可被检索与问答召回；跨页整合留给以后的完整 ingest。
> **分期**：
> - **第一期（本稿）**：CLI `guanlan ingest --flash`；完整 ingest 识别并加深 flash 页；`health` 列待加深。
> - **第二期**：`guanlan import --flash`（模式写进任务清单，续跑沿用）；Web 一键入库开关、Web 体检显示待加深。见 §7。
>
> **不做**：批量 `--deepen` 入口（积压场景验证后再定）；flash 对既有非 flash 页的覆盖；在 flash 里建实体/概念页。

## 1. 为什么

入库耗时取决于**触及多少页**，与资料字数关系不大：一次完整 ingest 22–49 次模型请求，每次带 6–11 万 tokens 上下文，请求区间占主循环 99.7%。已试过的杠杆都没有稳定收益：收尾措辞、限建页数（运行间波动更大）、index 交 wrapper 登记（上限 12%）、首包附资料（上限 1.3%）、同会话多篇（总输入 1.6 倍）。推理档位 low 快 27–39%，但产出薄约三成。

剩下唯一的大杠杆是**缩小写集**。用措辞「劝」模型少建页不稳定，所以 flash 把写集作为**硬约束**，由 wrapper 确定性执行。

## 2. 契约

| | 完整 ingest | flash |
|---|---|---|
| Agent 可写 | 整个 `wiki/` | 只有暂存候选 `workspace/flash/<slug>.md`；`wiki/` 有任何变动即逐字还原、判失败 |
| 实体/概念 | 建页、合并、补 aliases | 只写 `[[X]]`：名录里有的链既有页，没有的写前向引用；不读、不建 |
| source 页 | Agent 写 | wrapper 校验候选后提交 |
| index / log | Agent 写 | wrapper 确定性登记，重试不重复 |
| overview | 有新角度才改 | 不碰 |
| 冲突标记 | 跨资料 | 只标本篇内部的缺口 |
| 标记 | `raw_digest` | `raw_digest` + `ingest_depth: flash` |

## 3. 决策

- **D1 算「已收录」。** 由 wrapper 同时写 `raw_digest` 与 `ingest_depth: flash`：前者让 audit 照常检测原文漂移，后者标「待加深」。没有标记的页一律视为完整入库（兼容既有库）。
- **D2 先暂存、后提交。** heal 的越界写检查在运行结束后才算差异，只能报告。flash 改为 Agent 只写暂存候选；wrapper 校验 frontmatter 可解析、`type: source`、`sources` 含本篇、正文实质内容 ≥80 字后才写进 `wiki/sources/`，再跑与 ingest 同一个增量门禁（`gate.enforce`）。不过就回滚正式页、把问题回喂 Agent 改候选，最多 2 轮。
- **D3 `wiki/` 越界写逐字还原。** 运行前取 `wiki/` 全部文件的字节快照，运行后有任何变动就还原并判失败（退出码 3）。flash 的契约是「`wiki/` 只由 wrapper 写」，不像 heal 那样只报告。
- **D4 index 一句话由 Agent 写在候选里。** 候选 frontmatter 带 `index_summary`，wrapper 取走、压成单行（≤200 字）、不落进正式页。不采信 Agent 最终回复里的说明。index 已有指向本页的链接就不再登记；log 末条已是同一行就不再追加——中途失败后重跑不会重复。log 每条一行：`## [日期] ingest | <标题>（快速收录）`。
- **D5 不覆盖已整合的内容。** 本篇已有非 flash 的 source 页（完整入库过、手写或桩页）→ 跳过、退出码 0，提示跑完整 ingest。只定位到候选、认不准同源页 → 拒绝（退出码 1），交给完整 ingest 判断。已有 flash 页 → 重新收录，`sources` 并集保留。
- **D6 加深就是普通 ingest。** 完整 ingest 遇到 flash 页时，prompt 写明「这是快速收录页，本次整合进实体/概念页」；成功后 wrapper 清掉 `ingest_depth`。不另设 `--deepen`。
- **D7 名录有上限。** flash 名录只用来选链接名、不做查重，预算 4 万字（ingest 为 12 万）；超了就不附，让 Agent 按原文措辞写前向引用。
- **D8 待加深是状态，不是问题。** `health` 在报告末尾列出 flash 页，JSON 多一个 `flash_pending` 字段（没有 flash 页时逐字节不变）；不进 findings，不影响 `ok` 与 `--strict`。
- **D9 仍激活 `guanlan-wiki` skill。** 页面格式、直接引语、时间换算等规则都在 conventions 里，flash prompt 明确声明「不走完整 ingest 工作流」，只写候选页。

## 4. 红线

- `raw/` 只读不变：前后快照照查，变了判 `raw_mutated`。
- 不新增 LLM 客户端：仍经 `agentao run` 子进程。
- 单写者不变：`ingest --flash` 走与 ingest 相同的 CLI 入口锁。

## 5. 能力上限

- **没有跨页整合**：不建实体/概念页，不更新 overview，不做跨资料冲突比对。这是 flash 放弃的部分，以后靠完整 ingest 补。
- **前向引用增多**：§6 实验中每篇新增断链 5–45 条（完整模式 0–17 条）。批量 flash 后可以跑 `heal`（被 ≥2 页引用的缺失实体会物化成页），但同一概念若写成不同名字会被分散计数。
- **index 一句话只取自候选**：没写 `index_summary` 时登记行只有标题。
- **暂存区在 `workspace/flash/`**：失败或越界时由 wrapper 删除；进程被强杀时可能残留，下次同篇运行会先清掉。

## 6. 对照实验（2026-11-23）

丙库（119 页）按长度分层随机抽 4 篇确实未入库的资料（1.7k / 3.2k / 6.5k / 9.6k 字），每篇 flash 与完整 ingest 各 3 次，每次从同一快照克隆独立副本、按次交替先后。agentao 0.5.23、默认推理档位。资料名与内容不在此记录。

| 篇 | flash 耗时 / 请求 | 完整耗时 / 请求 |
|---|---|---|
| 1.7k 字 | 31–59s / 4–9 | 106–110s / 19–26 |
| 3.2k 字 | 29–39s / 3–8 | 89–120s / 15–25 |
| 6.5k 字 | 32–54s / 3–7 | 116–145s / 19–23 |
| 9.6k 字 | 58–86s / 7–8 | 175–193s / 26–41 |
| 合计 | 9.9 分钟 / 12 次 | 26.1 分钟 / 12 次 |

- 24 次全部成功，没有自愈、没有越界写。每篇 flash 的范围都与完整模式不重叠。
- 输入 tokens：flash 每次 0.10–0.35M，完整 0.72–2.76M。
- flash 的 source 页字数为完整模式的 1.4–1.8 倍（知识集中在一张页上）。
- 质量：每篇 6 条核心事实/限定条件与 2 条固定查询，24 次全部满分（清单偏易，区分度不足）；`guanlan quotes` 核对，flash 无新增问题，完整模式 3 次各新增 1–2 条。人工抽读：数字、表格与原文一致，药物剂量 6 次均无误。
- 剩余波动：Agent 仍会在候选页上边写边 `replace` 修订，单次工具调用 4–21 次。

## 7. 第二期（只列问题）

- `import --flash`：模式在建任务时写进清单，暂停与续跑沿用原模式。续跑以 `raw_digest` 判完成项，flash 页也有 digest，需确认两种模式不会在一次导入里混用。
- Web：一键入库加开关；Web 体检（P4.34）显示待加深数，是否给「加深」按钮另议。
- 批量 `--deepen`：积压场景验证后再定。
