# P4.19 Web MCP 配置诊断（只读，可选叠加层）· **已实现**（落点见 §8）

> P4 Web 宿主的**诊断增强**：把本知识库的外部 MCP server 配置在浏览器里如实显示出来，并允许用户
> **显式点一次**做连接检查。零 LLM、零策略、零管理。
>
> **背景（本相位存在的理由）**：agentao 的 `build_from_environment` 在调用方不传 `mcp_registry=` 时
> **默认注入** `FileBackedMCPRegistry`（`embedding/factory.py:244`），读 `<kb>/.agentao/mcp.json` +
> `~/.agentao/mcp.json`。观澜的 CLI 子进程（`cli/run.py:527`）与 Web 嵌入（`conversation.py:249`）
> **都吃这个默认**。也就是说外部 MCP 工具已经在注入 ingest/query/heal/audit/Web 问答，而用户在观澜里
> 看不到任何痕迹。本相位补的就是这个可见性，**不改变**这一行为。

## 1. 范围

**做**：展示配置 + 显式连接检查，两件事。**不做**：见 §5 非目标。

**时点语义（决策P4.19-8，必须逐字照用）**——MCP 是**构造期**加载的（`conversation.py:249` 建 `Agentao`
时一次性 `init_mcp`），故本面板显示的是：

> **当前磁盘配置的解析结果；新建 Web 会话或下一次 CLI 作业将使用这些配置。已有会话需新建后生效。**

连接检查同理，**只证明当前磁盘配置可连接，不代表已有会话正在使用它**。措辞含糊（如"当前实际生效"）会让
用户以为改完 `mcp.json` 就对手上这个会话生效——事实相反。

**归 P4.19 而非新里程碑**：既有 Web 宿主的一个只读诊断面板，与 `/api/info`、check/health/lint 报告同位阶；
不引入新数据模型、不新增退出码、不碰任何写路径。

## 2. 接口

### 2.1 `GET /api/mcp` —— 纯读盘，零网络

```jsonc
{
  "servers": [
    {"name": "upstream-kb", "scope": "user",    "transport": "http",  "endpoint": "https://api.example.com/mcp", "trusted": true},
    {"name": "local-tool",  "scope": "project", "transport": "stdio", "endpoint": "some-server",                  "trusted": false}
  ],
  // name：文件级错误为 null，per-server 错误（transport_unresolvable）点到具体条目。
  // 只此一条错误通道，不为 per-server 再开第二个字段。
  "config_errors": [{"path": ".agentao/mcp.json", "name": null, "kind": "json_unparsable"}]
}
```

- **合并口径**：server 集合取 agentao `load_mcp_config(project_root=kb, user_root=~/.agentao)` 的结果——
  它就是 agent 实际会连的那一份，**含用户级配置**（漏掉它等于漏掉最常见的一半）。传输判定调
  `resolve_transport`，不另立口径。
- **`scope` 怎么来**：`load_mcp_config` 返回已合并、无来源标记的字典，故 `scope` 由观澜**另行读两个文件的
  原文**判定（仅用于展示）。**同名冲突时 `scope = "user"`**（决策P4.19-9）——上游合并策略是「project 只能
  新增名、不能覆盖 user 同名」，冲突时 project 条目被整条 `continue` 忽略（`mcp/config.py:317-328`），
  故标 user 即是实情。
  > 可选（一行成本，非本期必须）：同名时在 `config_errors` 里附一条 `level:"info"` 的
  > `name_shadowed_by_user`，正面解释「我改了项目里的配置却没生效」——这恰是本面板该回答的问题。
- **静态检查三项**（决策P4.19-1，实现期由两项补到三项；判据只有一条：**上游会静默丢掉的输入，
  面板必须说出来**——渲染成"没有配置"与真空配置一字不差，正是本相位要消灭的那种沉默）：
  1. `json_unparsable` —— 文件存在但 JSON 解析失败 / 顶层不是对象（`_load_json_file` 对坏 JSON
     **静默返回 `{}`**，`mcp/config.py:259-266`）；
  2. `config_shape_invalid` —— 文件能解析，但**形状过不了上游归一**：`mcpServers` 不是对象（写成
     数组等），或某条目不是对象、或它的 `env`/`headers` 值 / `args` 元素不是字符串。上游
     `_expand_config_env` 对此**直接抛**（`dict(entry)` → `ValueError`、`expand_env_vars(非串)` →
     `TypeError`），**一条坏条目让整份配置消失**，故错误须点名到具体条目；
  3. `transport_unresolvable` —— `resolve_transport` 抛 `McpTransportConfigError`（fail-closed），
     **或**它返回了 `"unknown"`。后半句必要：「既无 `type`、又无 `command`、又无 `url`」上游**不抛**、
     直接返回 `"unknown"`（`config.py:217`），`command` 拼成 `comand` 这类最常见的错配正落在这里；
     不补这条，面板上只有一行孤零零的 unknown。该行的 `transport` 落 `"unknown"`——**与 agentao
     自己的展示口径一致**（`McpClient.transport_type` 同样回落 `unknown`），不另立第三种表示。

  **不做 `field_empty_after_expansion`**（决策P4.19-1 v2 更正）：agentao 的 `_expand_config_env`
  **只展开 `env` 值、`headers` 值和 `args`**，`command` / `url` **根本不展开**（`mcp/config.py:241-250`）——
  原先那条检查建立在错误事实上。认证 / 参数 / 端点类错误一律交给显式连接检查（§2.2）。
  > 顺带一个已知 footgun（本期不检、仅记录）：在 `url` 里写 `$TOKEN` 不会被展开，会原样发出去。
- **`readOnlyHint` 等 annotations 不做静态判定**（决策P4.19-2）——它只存在于连接后的 `tools/list` 响应里，
  离线判不出来。要看就点检查。

### 2.2 `POST /api/mcp/check` —— 用户显式触发，唯一非离线端点

```jsonc
// 请求：`{}`（查全部）或 {"name": "upstream-kb"}（名字必须已在配置里，否则 404）。
// **请求体必填**（最简 `{}`，决策P4.19-13）：无体 POST 与 text/plain 体都是浏览器「简单请求」、
// 不触发 CORS 预检——放行无体等于让任意网页驱使本机观澜连一遍全部配置的 MCP server（起子进程 +
// 对外发请求；响应虽读不到，副作用照发）。与 ingest/heal 等既有端点同姿态，不是新规矩。
{
  "results": [
    {"name": "upstream-kb", "status": "connected", "transport": "http", "error": null,
     "tools": [{"name": "search", "description": "…", "annotations": {"readOnlyHint": true}}]},
    {"name": "local-tool", "status": "error", "transport": "stdio", "error": "…（已脱敏）", "tools": []}
  ]
}
```

- **只检查当前 KB 的实际配置**：端点**不接受**前端传入的 server 定义、URL 或 header（决策P4.19-3）——
  否则这个面板就成了一个任意 MCP / SSRF 客户端。请求体最多带一个已存在的 `name`。
- **不在启动或页面加载时自动探测**：连接会真的**起 stdio 子进程 / 发网络请求**，必须是用户点击的结果。
- **复用 agentao 公开面**：`McpClientManager(configs)` → `connect_all()` → `get_server_status()` +
  `get_all_tools()`（`mcp/client.py:639/696/668`），**`finally: disconnect_all()`** 无论成败都断。
- **两个必须遵守的运行时事实**（决策P4.19-4）：
  1. `McpClientManager._run` 是 `loop.run_until_complete`（`client.py:626-629`），**在 FastAPI 的运行中
     事件循环里直接调会崩** → 整个检查经 `anyio.to_thread.run_sync` 卸离事件循环（同决策P4-2 既有姿态）。
  2. `disconnect_all()` 会 `close()` 掉那个 loop → **manager 是单次使用对象**：每次检查新建、用完即弃，
     **不长驻、不复用**（与 P5.1 长驻 `CorpusCache` 正相反，别照抄那个模式）。
- **超时：不设端点级总墙钟**（决策P4.19-10）。`anyio.to_thread` 的线程**不可取消**——外层 async 超时要么
  仍等线程结束（墙钟形同虚设），要么放弃等待而把线程与它拉起的 stdio 子进程留在后台跑、`finally` 清理时序
  也失控。直接沿用 agentao **每个 server 的 startup timeout** 即可：它用
  `asyncio.wait_for(self._handshake(), timeout=startup_timeout)` **统一兜住所有传输、含 stdio**
  （`client.py:246-256`，其注释明写 "stdio has no transport-level connect bound at all" 正是为此），
  默认 60s；`connect_all()` 本身并发连接，故一次检查的上界 ≈ 各 server startup 的最大值。
- **并发：单飞 + `409`**（决策P4.19-10）。同一进程内已有检查在跑时，后续请求**直接返回 409，不排队、
  不重复执行**——排队只会让用户连点变成 N 次真实连接。
- **诊断不执行任何工具**：只 `initialize` + `tools/list`。故不需要 trust / 只读判定，也**不改变任何注入行为**。
- **缺 MCP SDK → `501` + 安装指引**（决策P4.19-12，实现期补的契约缺口）：`guanlan web` 只装 `[web]` extra，
  而 MCP **客户端**栈（`agentao.mcp.client` → `from mcp import ClientSession`）随 `[mcp]` extra 才到位。
  故检查端点在 SDK 缺席时回 501 并指向 `pip install 'guanlan-wiki[mcp]'`，**不是 500**；`GET /api/mcp`
  只依赖 `agentao.mcp.config`（纯 stdlib），**不受影响**——"看得见配置"这件事不该被一个可选依赖绑架。

## 3. 脱敏与边界

- **只回**：`name` / `scope` / `transport` / 脱敏后的 `endpoint` / `trusted` / 连接结果 / 工具名与 annotations。
- **绝不回**（决策P4.19-5）：`headers`、`env`、任何 token，以及 URL 里的凭据。
  - URL 传输 → 保留 `scheme://host[:port]/path`，**去掉 userinfo 与整个 query 串**（`?token=` 是最常见的凭据位），
    **并遮掉路径里 ≥16 字符的段**（决策P4.19-14）——托管 MCP 的标准形态就是把 key 放在路径里
    （`/api/mcp/s/<token>/mcp`、UUID 段）；只去 query 会让活密钥原样打在面板上。纯长度判据、不猜熵值：
    遮错一段只少显示几个字符，漏一段就是泄漏凭据；
  - stdio 传输 → 只回 `command` 的 basename，**不回 `args`**（args 常含 token 与本机路径）。
- **`error` 文本必须走同一道脱敏**（决策P4.19-5 扩展，v2 补漏）：agentao 的错误串会带**完整 URL**——
  例如 `NonMcpEndpointError` 把 `url` 原样写进消息（`mcp/client.py:381-388`），URL query 里的 token 会
  经 `error` 泄漏。**做法**：对每个 server 的 error 串做**已知敏感值定向擦除**——把该 server 配置里出现过的
  完整 `url`、userinfo（只取密码那半）、query 串**及其每个值**、路径里的长段、`headers` / `env` 的每个值
  （及 `Bearer <token>` 的裸 token 部分）逐一替换（这些值我们手里正好有，比通用正则可靠），再叠一道
  URL 正则兜底。两条实现期定的口径：
  - **替换文本不一律是 `***`，能保住可诊断性就保**：`url` → 脱敏后的同一条 URL、`command` → basename
    （`No such file: 'no-such-tool'` 仍可读，只是不再带 `/Users/<人名>/…`；`endpoint_of` 早就这么做，
    错误文本此前没跟上，等于配置表遮掉的本机路径从 `error` 原路漏回去）；
  - **`_MIN_SECRET_LEN = 8` 对 headers/env/userinfo/query 一视同仁**：短值不入表，否则 `user` 这种词
    会把面板唯一要展示的那段文本打成马赛克（实证："could not find the user manual" → "the *** manual"）。
- **日志同样脱敏**（决策P4.19-15）：`McpClient.connect` 的失败分支把**未脱敏的完整 URL** 写进
  `logger.error`（实测）。响应体擦干净而终端里留着 `?token=` 不叫脱敏——决策P4.19-5 要的是"不出进程"。
  故检查期间给 `agentao.mcp` 这个 logger 挂一个就地脱敏的 `logging.Filter`，用完即摘。
- **前端统一 `escapeHtml`**（决策P4.19-11）：工具 `description`、`error` 都是**外部不可信文本**，
  渲染前一律转义，与 P4.11 的信任边界口径一致。
- **reader 模式不注册这两个端点**（决策P4.19-6）：匿名只读部署下，连接检查能发网络请求、能拉起本机配置好的
  stdio 进程——是副作用与成本，不是读。复用 P4.9 既有的 `_writer_only` 裁剪装饰器（命中即 404、路由根本
  不存在），注释里写明「此处理由不是'写 KB'，而是'有外部副作用'」，避免为一个端点新造第二套裁剪机制。
- **诚实边界**：本面板**只反映**配置与连通性，**不保证**这些 server 安全、只读或可信；它不是闸。

## 4. 测试面

**连接检查是本相位的核心价值，故它进默认 `pytest` 面，不是 smoke**（决策P4.19-7）：

- **真 stdio 端到端**：拿仓库现成的 `guanlan mcp` 起一个真 server 当被测上游（零新依赖），走
  `POST /api/mcp/check` 断言 `status=connected`、工具枚举非空、**结束后子进程已被断开清理**。
  不需要先给它补 `readOnlyHint`——诊断不执行工具，annotations 缺失只是如实显示为空。
  > 「子进程已清理」这条断言**自身**要有正例控制：`pgrep -f` 的 marker 若以 `-` 开头，BSD/macOS
  > 把它当非法选项、空输出退出，断言便永远真空通过（实证）。故探测器对 rc 严格分档（非 0/1 即抛），
  > 另立一条用例证明它在本平台真能看见活进程。
- **错误面**：不存在的 `command` → `status=error` + `error` 非空且请求本身仍 200；坏 JSON → `json_unparsable`；
  坏 `type` → `transport_unresolvable`。
- **配置坏掉的各种形态都必须说出来**：坏 JSON → `json_unparsable`；条目/`mcpServers`/`env` 形状不合法 →
  `config_shape_invalid`（点名到条目）；`command` 拼错 → `transport_unresolvable`；同一份坏配置在检查端
  → **422 + 可执行原因**（不是 500）。每条都要断言**响应不是**「未配置任何 server」——那与真空配置无从区分。
- **脱敏反向用例（端到端三条 + 单元一组）**：
  1. 配一个带 `?token=…` 的 URL server 与带 `headers` / `env` 的条目，断言 `GET /api/mcp` 响应体里**不出现**这些串；
  2. **让那个带 token 的 URL 连接失败**（指向一个返回 HTML 的地址触发 `NonMcpEndpointError`），断言
     `error` 串里**同样不出现** token——只测配置展示会漏掉这条路径。脱敏漏出是沉默的，正例测不出来。
  3. 让一个**绝对路径的 stdio command** 连接失败，断言 `error` 里不出现目录部分、但仍出现命令名。
  4. **每个过滤分支各配一条单元用例**（直接打 `redact` / `endpoint_of`）：headers/env 值、裸 query token、
     command 路径、路径内嵌 token、短词不误伤。端到端只覆盖 agentao 今天恰好会拼进错误串的那几种形态，
     故 headers/env 分支曾被整段删掉而全套用例仍绿（实证）——这正是本仓「给过滤器加规则必须配漏报用例」
     那条规矩的适用场合。
  5. **日志侧**：断言那条 `agentao.mcp` 的 ERROR 里 token 也不在。用例须先断言日志里**确实含 URL**，
     否则换个连不上的端口就成了空转（初稿如此，删掉 filter 照样绿）。
- **`scope` 与碰撞**：只写在 `~/.agentao/mcp.json` 的 server 必须出现且标 `scope=user`（最容易被漏掉的一半）；
  user 与 project **同名**时断言 `scope=user`。
- **并发**：检查进行中的第二个请求返回 **409**。
- **reader**：两个端点 404。
- **不测**：真实远端网络、任何工具调用。
