## 2. 为什么是 `~/.guanlan/USER.md`，不是库内

上一轮讨论排除了 `<库>/USER.md`（与 `AGENTAO.md` 同级），理由不变：

1. 只读问答的 Agent 能读库内任何文件，画像会被当资料读到、引用。
2. 库可能被复制、同步、多人共用，画像是个人的。
3. 直接复制库目录会把画像带走（`zip` 白名单不含它，但不是唯一的分享方式）。
4. Web 可写姿态下，`USER.md` 不在 immutable 集里，可能被 Agent 改掉。

**库级的「读者与回答方式」已有去处**：写进库的 `AGENTAO.md`，CLI 与 Web 都会读进系统提示。本稿只处理个人级画像。

`~` 指**运行 guanlan 进程的用户**的主目录（`Path.home()`；Windows 为 `%USERPROFILE%`）。这一点决定了 D2：只有「运行进程的人 = 提问的人」的入口才能用默认路径。

`Path.home()` 确定不了主目录时会抛 `RuntimeError`（`HOME`、`USERPROFILE` 都缺失的服务环境里会出现；`web/app.py` 已有捕获它的先例）。此时按「默认文件不存在」处理，并在 stderr 打一行 `⚠ 找不到主目录，未查找默认画像`，不崩溃，也不静默。

## 3. 决策

### D1 机制：文件存在即启用，`--no-profile` 单次关闭

`guanlan query`（只读）按以下顺序决定画像：

| 参数 | 画像 |
|---|---|
| `--profile <路径>` | 用该路径（与 P5.5 相同） |
| `--no-profile` | 不带 |
| 都不给，`~/.guanlan/USER.md` **不存在** | 不带，行为与 P5.5 不给参数时逐字相同 |
| 都不给，`~/.guanlan/USER.md` **存在** | 用它 |

- `--profile` 与 `--no-profile` 同时给是用法错误（退出码 2）。argparse 的互斥组表达不了「`--profile` 与另两个都互斥、`--no-profile` 与 `--backfill` 可以同用」，所以**不把 `--no-profile` 加进现有的 `--backfill`/`--profile` 互斥组**，改为解析后手动检查、`parser.error(...)`，退出码仍是 2、仍早于取锁。
- **不加环境变量**：P5.5 的理由仍成立。多一个开关就多一处要查的配置（已有 `~/.env` 被 agentao 自动载入的先例，查问题时容易漏）。
- **不加「是否启用默认路径」的配置项**：文件本身就是开关。不想用就删掉或改名。
- 备选方案（用户 2026-11-23 否决）：要求用户先 `guanlan profile enable` 一类命令显式开启。收益只是防止「已有同名文件」时行为突变，D3 的首次提示已经覆盖这一点。

### D2 只在 CLI 层解析默认路径

是否认默认路径，由 CLI 决定；读取与校验只在 `run_query` 里做**一次**。

- `run_query` 增加关键字参数 `use_default_profile: bool = False`。只有 `_cmd_query` 在只读、未给 `--profile`、未给 `--no-profile` 时传 `True`；其它调用者不传，行为不变。
- `run_query` 内部顺序：`require_kb_root` → 若显式 `profile`，`load_profile`，失败 `EXIT_USAGE`；若 `use_default_profile`，查默认路径、`load_profile`，失败打 D4 警告并不带画像 → D3 提示 → 调模型。
- 这样画像只读一次：D3 的摘要与实际注入的是同一份文本；不会出现「CLI 先读一遍合格、`run_query` 再读时已坏、按显式路径报 `EXIT_USAGE`」违反 D4 的情况；「不是知识库」的报错也总在画像警告之前。
- 首稿写的是「CLI 自己解析，把路径作为 `profile=` 传入，`run_query` 签名不变」，评审指出会读两次，已改（§8）。

- **理由**：`run_query` 还被 Web 回填作业调用（`web/app.py`）。默认值是 `False`，只有 CLI 显式打开，Web、MCP、IM 不会无意间带上画像。
- **测试锁定**：Web 回填作业、MCP `ask` 在 `~/.guanlan/USER.md` 存在时，发出的 run spec 都不含 `instructions`。

### D3 提示只打一次：画像内容变化后首次生效时

默认画像生效时，若这份内容**与上次提示过的不同**，往 stderr 打一行；相同则不再打：

```
ℹ 已附提问者画像：~/.guanlan/USER.md（之后不再提示；本次不带：--no-profile）
```

- **「一次」按内容计**：记下最近一次提示过的画像内容的 SHA-256（对 `load_profile` 返回的去首尾空白全文取）。画像改过后再次生效，会再提示一次。理由：改了画像，回答的取向也会变，用户应当知道新版本开始生效。只改首尾空白不算改动。状态只存一份摘要，所以 A→B→A 改回 A 时也会再提示。
- **状态文件**：`~/.guanlan/profile-notice`，只存一行十六进制摘要（最近一次提示过的内容），不存画像原文。
  - **只在 stderr 是终端时记为已提示**（`sys.stderr.isatty()`）。stderr 被重定向时（`2>/dev/null`、cron、由别的 Agent 代为调用），提示照打，但不写状态：没人看到的提示不能算提示过，否则用户第一次在终端里用时就再也看不到。
  - 在模型调用前写入：提示一打出就算提示过，即使这次问答随后失败。
  - **读不了或写不进时，照打提示**（下一次仍会打）。加上上一条，失效方向只有「多提示」，没有「该提示没提示」。
  - 删掉这个文件即可重新看到提示；它不是配置，不影响画像是否生效。
  - 多个 `query` 并发首次生效时可能各打一次，可以接受，不加锁。写入用「临时文件 + `os.replace`」，避免读到半截。
- 只在**默认路径生效**时考虑提示。显式 `--profile` 仍不打（P5.5 D5 不变），也不读写状态文件；不带画像时不打。
- 打到 stderr，stdout 仍只有答案，管道和脚本不受影响。路径按用户熟悉的写法显示（主目录下为 `~/…`）。
- **理由**：P5.5 不打提示的前提是「用户显式给出、自己知道」。默认生效时，用户可能忘了这个文件，或按旧教程建过同名文件、升级后才开始生效，所以开始生效时要说一声；之后每次都打会成为噪音（用户决定）。
- **代价**：新增一份本地状态。按「新增状态要写明失效规则」的原则，上面已写明：缺失或损坏都只会导致多打一次提示，不影响问答。

### D4 默认文件不合格：警告后不带画像继续

默认路径上的文件**存在**但不合格时（不是普通文件、不可读、不是 UTF-8、空、超过 1,500 字、解析后落在当前库内、悬空符号链接），往 stderr 打警告，然后**不带画像**照常问答：

```
⚠ 默认画像未使用：画像 1,820 字，超过上限 1500 字（~/.guanlan/USER.md）；本次不带画像。修正或移走该文件可消除此警告
```

- 警告正文复用 `load_profile` 的报错原因，不另写一套判定。
- **每次都打，不受 D3「只打一次」影响**：文件一直坏着，用户就一直看得到。不写状态文件。
- 退出码由问答本身决定，不因警告变成非零：默认文件坏了不该让所有 `query` 失败（用户决定）。
- **与显式 `--profile` 不同**：显式给出的路径不合格仍以 `EXIT_USAGE` 退出（P5.5 D4 不变）。显式参数是用户这一次的明确要求，悄悄降级会让人以为带上了；默认文件是长期放着的，坏了降级并警告更合适。
- **会悄悄偏离用户预期的情况**：stderr 被丢弃（如脚本 `2>/dev/null`）时，用户看不到警告，会以为带了画像。这是本决策接受的代价。
- 「落在当前库内」出现在两种情况：知识库建在主目录本身或 `~/.guanlan/` 之上；或 `~/.guanlan/USER.md` 是指向库内文件的符号链接。沿用 `load_profile` 的判定。
- **符号链接**：`~/.guanlan/USER.md` 可以是指向别处的符号链接（例如同步盘里的画像），按解析后的目标校验。悬空链接按「存在但不合格」处理，打警告，不当作「不存在」静默跳过：链接本身表明用户想用它。

### D5 回填时不带默认画像，不报错，不提示

`guanlan query --backfill` 时**完全不看默认路径**：不读、不校验、不提示、不警告，行为与默认文件不存在时逐字相同（用户决定）。

- 回填内容进共享的 `wiki/syntheses/`，画像不应影响共享内容（P5.5 D4 的理由）。
- 默认文件存在时若照 P5.5 的互斥规则报错，有画像的用户就再也用不了 `--backfill`。
- 显式 `--profile` + `--backfill` 仍由互斥组拒绝，不变。`--no-profile` + `--backfill` 允许（无副作用）。实现上 `--backfill` 时 CLI 不传 `use_default_profile`。
- 帮助文本写明「`--backfill` 不带画像」，用户不必靠运行时提示得知。

### D6 隐私

P5.5 D6 全部沿用：画像随请求发给模型提供方，并以明文记入库根 `agentao.log`（写不进时 `~/.agentao/agentao.log`）。默认生效后，**每次** `query` 都会带上画像，而首次提示之后不再提醒，日志里出现的次数随之增加。帮助文本、CHANGELOG 和教程写明这一点。

D3 的状态文件只存摘要，不存画像原文。

## 5. 测试

全部用 fake runner。`HOME`/`USERPROFILE` 由 conftest 的 autouse 夹具统一指向空临时目录（§4），新旧用例都不读真实主目录。

- **测试隔离本身**：一条用例在夹具之外的另一个临时目录里放画像、把它冒充成「开发机主目录」，跑一条已有的 `main(["query", …])` 用例路径，断言 spec 不含 `instructions`。没有这条，夹具失效时 CI 照样全绿（CI 机器上本来就没有画像），只在作者本机挂。

- **默认文件不存在**：提示词、run spec 与 P5.5 不给参数时逐字相同；stderr 无画像相关输出；不创建状态文件。
- **默认文件存在且合格**：
  - run spec `instructions` 与显式 `--profile ~/.guanlan/USER.md` 时逐字相同；stdout 只有答案。
  - 首次（stderr 为终端，测试里猴补 `isatty`）：stderr 恰有一行 D3 提示，状态文件写入摘要。第二次：无提示。
  - stderr 不是终端：每次都提示，状态文件不写；之后切到终端时仍会提示一次。
  - 改动画像内容后：再提示一次；只改首尾空白：不提示；A→B→A 改回时再提示。
  - 主目录拿不到（`HOME`、`USERPROFILE` 都删掉，`Path.home()` 抛错）：不崩，stderr 有一行警告，spec 不含 `instructions`。
  - 状态文件不可写（目录只读）：每次都提示，问答照常成功。状态文件内容损坏：提示一次并改写。
  - runner 失败时：提示已打、状态已写，下次不再提示。
  - 画像只读一次：猴补 `load_profile` 计数，一次只读问答恰调用一次；D3 摘要与注入文本来自同一次读取。
  - 「不是知识库」时：只报库根错误，不打画像提示或警告。
  - `--no-profile`：不传 `instructions`，无提示，不碰状态文件。
  - 显式 `--profile 其它路径`：用其它路径，无提示，不碰状态文件。
- **D4 降级**：空文件、超长、非 UTF-8、目录、悬空符号链接、知识库根恰是 `HOME`（画像落在库内），各一条：stderr 有警告、runner **被调用**且 spec 不含 `instructions`、退出码等于问答结果；连跑两次都警告。符号链接用例不许 skip。
- **显式路径不变**：同样不合格的文件经 `--profile` 给出时仍 `EXIT_USAGE`、不调 runner（锁 P5.5 行为）。
- **D5 回填**：默认文件存在（合格与不合格各一）+ `--backfill` → 正常走回填、spec 不含 `instructions`、stderr 无画像相关输出、不碰状态文件。
- **互斥**：`--profile` + `--no-profile`、`--profile` + `--backfill` 均在解析时退出码 2，不调 runner、不取锁；`--no-profile` + `--backfill` 正常回填。
- **D2 隔离**：默认文件存在时，Web 回填作业（`run_query(backfill=True)`）与 MCP `ask` 发出的 spec 不含 `instructions`。
- 用例数据一律中性占位。

## 6. 第二期：Web 接入（已另起 [P5.5.2](P5.5.2-Web问答画像.md)）

Web 的 `~` 也是运行 `guanlan web` 的用户。P5.5 设计里的倾向是：嵌入式会话构造时传 `project_instructions`，与 CLI 同一通道。真要做时需要先回答：

1. **谁在提问**。默认 `127.0.0.1` 单人使用时，提问者就是运行进程的人；`--reader`（P4.9 只读多会话）可能经反向代理给多人用，画像不能是宿主机主人的。初步倾向：`--reader` 一律不带。
2. **可写姿态**。Web 会话可用 `/mode` 在只读与可写之间切换，可写轮会写共享的 `wiki/`，与 D5 的理由冲突。（首稿说「系统提示在会话构造时冻结」，与代码不符：agentao 每轮开头按 `agent.project_instructions` 重建系统提示。答案见 P5.5.2 W4。）
3. **快照还是实时**。画像在会话构造时读一次（与 Hermes 的会话快照一致），还是每轮重读？会话落盘恢复（`.agentao/sessions/`）后读的是哪一版？
4. **看得见**。CLI 首次在 stderr 提示；Web 没有 stderr，需要在对话界面上标明本会话带了画像（D3 的「只打一次」不适合照搬到界面），并给出单会话关闭的入口。
5. **IM、MCP 不接**。IM 的提问者是 `--allow-user` 里的他人；MCP 的客户端是另一个 Agent，它自己有用户上下文。两者都不该读宿主机主目录下的画像。

## 8. 修订记录

**2026-11-23 第一轮评审**（与 P5.5.2 同轮）。采纳：

1. **P1 测试隔离**：conftest 只隔离了 `GUANLAN_JOBS_HOME`，旧用例会读开发机上的真实画像，CI 上看不出来。改为 autouse 隔离 `HOME`/`USERPROFILE`，并加一条「夹具失效即红」的用例（§4、§5）。
