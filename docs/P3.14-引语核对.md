> 1. 写入纪律（§6，已在技能中落地）；
> 2. 按本稿的契约重跑度量（§7）；
> 3. 实现只读命令；

## 0. 一句话

`guanlan quotes`：零 LLM、只读。逐页取出引号内的文字，到该处出处所指的 raw 原文里逐字查找，对不上的按成因分类报告。默认退出码 0；哪些类别在 `--strict` 下退 6，由度量决定。改正不在本阶段。

## 1. 原型数据（动机，不是误报率）

一次性原型脚本，不进包，跑在一个中文真实库上：约 1,600 页、约 690 份 raw，其中约 96 份是 OCR 识别稿。

| 指标 | 数值 |
|---|---|
| 候选引语（引号内归一后 ≥8 字） | 约 9.5 万 |
| 原型规则下逐字见于所引原文 | 89.9% |
| 单次全库扫描 | 约 35 秒 |

原型规则下不符的部分（双引号类，≥15 字）：

| 原型档 | 处数 | 抽样所见 |
|---|---|---|
| 改字／拼接 | 2,066 | 缩写原句、改一两个字、把不相连的两句拼成一句；也混有 OCR 原文自身的错字 |
| 原文中找不到 | 511 | 多为转述或本库措辞被加了引号；少数是内容本身在原文中无据 |
| 逐字见于另一份 raw | 1,244 | 措辞对，出处标错，或该行只引了书的实体页 |

另有一个四字短语被模型系统性写错：13 页、32 处，raw 中一处都没有。这类错误 `check`、`lint`、`audit` 都看不见。

**这些数据不能当作误报率。**
- 原型的匹配规则比本稿宽松：没有剥 raw frontmatter，覆盖率跨 raw 合计，不要求片段顺序。
- 后来用 LLM 改正了一批页，「改正后通过核对」也不等于人工确认原来就是真问题。

误报率由 §7 的分层人工抽样给出。

## 2. 命令与范围

- **\[决策P3.14-1] 独立子命令 `guanlan quotes`**，独立于 `health`、`lint`、`audit`。理由：
  - **量**：全库数千条，会淹没 health 的记账类提示；
  - **形状**：每条要带引语、核对的 raw 与最接近的原文位置，不是一行 `page: detail`；
  - **耗时**：几十秒，不该拖慢日常体检；
  - **契约**：audit 是 LLM 档，本命令零 LLM、只读，二者契约不同。
- **\[决策P3.14-2] 候选集封闭，写进 docstring**（「新形态改 docstring，不改正则」）：
  - **收**：`“…”` 与 `"…"`，归一后 ≥15 字。
  - **另计**：`「…」` 默认不查，`--include-corner` 才收。
  - **不收**：
    - 围栏代码块内（含 mermaid）；
    - config 页；
    - 结构标签（见 §3.5）。
  - **日期、数字**：本阶段不扩展，另行度量。
- **参数**：`--page <名>`、`--min-len N`（默认 15）、`--include-corner`、`--json`、`--strict`。不写盘，不改任何文件。

## 3. 匹配契约

### 3.1 引号配对：逐字扫描、遇重复开引号重新同步

实测模型常在一句里混用直引号与弯引号，所以三种字符统一处理，但不能简单按出现顺序两两配对：那样一个未闭合的开引号会和后面引语的开引号配成一对，后面那条正常引语就被吞掉了。改用一个两态扫描：

- **在引语外**：遇 `“` 或 `"`，记为开引号，进入引语内；遇 `”`，是落单的闭引号，计一次「未闭合引号」，忽略。
- **在引语内**：
  - 遇 `”`，或者遇 `"`（无论开引号是哪一种），都闭合，收下这段引语，回到引语外；
  - 遇 `“`，说明上一个开引号没有闭合：放弃它，计一次「未闭合引号」，**以这个新的 `“` 重新开始**。
- **行尾仍在引语内**：放弃，计一次「未闭合引号」。

验证例：`“未闭合文字；“这里是一条完整的正常引语……”`。第一个 `“` 开始，第二个 `“` 触发重新同步，最后收下「这里是一条完整的正常引语……」，并计一次未闭合引号。未闭合引号只计数，不报为 finding。

已知局限：在引语内遇到 `"` 一律当闭合，所以直引号嵌在弯引号里的写法（`“甲"乙"丙”`）会被截断。这类写法计入度量的误报成因。

### 3.2 归一化：两侧共用一个函数

引语侧与 raw 侧**共用同一个文本归一函数** `norm()`。只有省略号切分是引语侧独有的，而且必须先于 `norm()`：

1. **（仅引语侧）按省略号切分**：`……`、`…`、`...` 及以上的点。必须在删标点之前切，否则省略号先被当标点删掉，片段边界就丢了。
2. **`norm()`，两侧相同，顺序固定**：
   1. NFKC；
   2. 链接语法：`[[x|y]]` 取 `y`，`[[x]]` 取 `x`；去掉 Markdown 强调符 `**`、`__`；
   3. 脚注编号：去掉 `[1]`～`[999]` 形式的方括号数字，以及上标数字（`¹²³` 等）。这样写入纪律要求删去的脚注编号，在核对时两侧对等，句中有脚注编号的原文仍能命中；
   4. 删去全部标点与空白。
3. 空片段丢弃。

raw 侧在 `norm()` 之前，先用 `pages.split_frontmatter` **剥掉 raw 自身的 frontmatter**。原型没有剥，实现时必须补上，并配漏报用例（§9）。

不做繁简转换，也不做中文数字与阿拉伯数字互换。这些差异就是该报的改写。

**版面噪声**：页眉、页脚、页码插在原文句子中间时，无法可靠识别。写入纪律要求不把它们带进引语，引用者应当把这段跳过视为省略、用「……」标出（§6）。这样切分后的片段在原文中依次出现，可以命中。没有用省略号标出的，会被报为 `altered`，作为已知限制计入度量的误报成因。

### 3.3 命中的定义

一条引语在**某一份 raw** 中命中，当且仅当它的全部片段在**这同一份 raw** 中**依次、不重叠**地出现：第 k+1 个片段的起点不早于第 k 个片段的终点。

- 片段倒序出现、分散在不同的 raw 里，都**不算命中**。拼接不同原文的引语，正要靠这一条识别。
- raw 正文中的换行已在归一时删去，所以跨行的原文句子可以命中。

### 3.4 覆盖率的定义

对**单份 raw** 计算：引语（各片段拼接后）的全部 4 字片段中，出现在该 raw 归一正文里的比例。一条引语的覆盖率取它在各候选 raw 上的**最大值**，并记下取得最大值的那份 raw。**不同 raw 的覆盖不合计**：在 A 中有一半、在 B 中有另一半，不等于这句话有出处。

### 3.5 结构标签过滤：只按明确的结构形态

过滤规则不能按「含某个字符」来定，否则含同样字符的正常引语会被一起吞掉。本阶段只启用一条按形态定义的规则：

- **序列标签**：引语按 `→`、`↔`、`⇒`、`—`、`／` 切开后有 **3 段及以上**，且**每段**归一后不超过 6 字、段内没有标点。例如「统一领导—顶层设计—需求统合」「推动→深入推动→全面推动」。只要有一段是完整句子，就不算标签，照常核对。

围栏代码块（含 mermaid）里的内容不收，这一条在 §2 已定，不属于标签过滤。

原型用过的另外几条（含 `<br`、含页码 `p.N`、数字字符超过三分之一）都是按字符判断，**本阶段不启用**。它们造成的误报计入 §7 的度量，再决定要不要换成按形态的规则。

用例要求见 §9：序列标签规则必须配反例，即含相同分隔符的正常引语，比如一句话里用了破折号，必须照常核对。

## 4. 出处范围

- **\[决策P3.14-3] 行内明确出处优先，按以下顺序确定一条引语的核对范围：**
  1. **行内明确出处**：本行 `[[链接]]` 中凡是 source 页的，以及本行反引号里写明的 `raw/...` 路径。有任何一个，就**只在这些 raw 里核**。
  2. **无行内出处时回退**：本页是 source 页的，用它自己的 raw；否则用本页 frontmatter `sources` 所指 source 页的 raw 并集。报告标 `scope: page`。
  3. 两者都没有：判 `no_source`。
- **出处到 raw 的映射复用既有原语** `sourcepage.claimed_raw_paths`，不写第五套按名查找。它已经同时认 `raw_digest` 与正文的 `> 原始资料：` 声明，所以一张 source 页只要有其中之一、且指向的 raw 可读，就照常核对。**缺少 `raw_digest` 本身不是问题。**
- **只有既有原语得不到任何可读 raw 时，才判 `source_unreadable`。** 比如行内链接的 source 页不存在，或者 `raw_digest` 与声明都没有，或者它们指向的 raw 文件读不到。这时**不回退**到页级 sources，也不到全库去找，免得为了让引语通过而扩大范围。

## 5. 分类与报告

### 5.1 判定顺序

| 步 | 条件 | 结果 |
|---|---|---|
| 0 | 出处无法确定 | `no_source` |
| 0 | 指定出处不可读 | `source_unreadable` |
| 1 | 在核对范围内的某份 raw 中命中（§3.3） | 通过，不报 |
| 2 | 在全库任一 raw 中命中 | `misattributed`（措辞对，出处不对），记命中的 raw |
| 3 | 核对范围内覆盖率（§3.4）≥ 阈值 | `altered`（改字、缩写或拼接），记覆盖率最高的 raw |
| 4 | 其余 | `unsupported`（原文中找不到） |

- 第 2 步要求全库 raw 都扫完。raw 遍历不完整（权限、断链）时，第 2～4 步一律改判 `scan_incomplete`，**不断言 `unsupported`**。沿用 `health.raw_walk_incomplete` 的口径：判不了就是未知。
- 覆盖率阈值暂取 0.6（原型值），由 §7 的度量校准。

### 5.2 报告字段

`--json` 沿用 `report_dict` 信封。每条 finding 带：

| 字段 | 含义 |
|---|---|
| `page`、`line`、`kind` | 位置与类别 |
| `quote` | 引号内原文 |
| `scope` | `line`（行内出处）或 `page`（回退） |
| `checked_raw` | 实际核对的 raw 列表 |
| `best_raw`、`coverage` | 覆盖率最高的 raw 及其覆盖率 |
| `hit_raw` | `misattributed` 时逐字命中的 raw |
| `ocr_hint` | 见 §5.4 |
| `strict`、`strict_reason` | 这一条是否计入 `--strict`，以及原因 |

- **`ok` 的定义**：不加 `--strict` 时恒为 `true`（只读建议）。加 `--strict` 时，`ok` 等于「没有任何 `strict: true` 的 finding」，退出码随之为 0 或 6。
- 每条 finding 自带 `strict` 字段，CI 与人读报告时不需要另查规则。
- 终端输出：各 kind 计数、按目录分布、不符最多的前 N 页；另列 `no_source`、`source_unreadable`、`scan_incomplete` 与未闭合引号的计数，**区分「没查」和「查了没找到」**。

### 5.3 strict 范围（待度量）

- **\[决策P3.14-4] 默认退出码 0。** `--strict` 下哪些 kind 计入，由 §7 的度量决定。证据不足的类别先只作建议报告（`strict: false`，`strict_reason: '未达度量门槛'`）。
- 预期 `misattributed`、`no_source`、`source_unreadable`、`scan_incomplete` 都不计入：措辞没错，或者根本没查成。`altered` 与 `unsupported` 是否计入、在什么阈值下计入，看非 OCR 层的人工确认率。

### 5.4 OCR

- **\[决策P3.14-5] OCR 只作提示，不作裁决依据。**
  - raw frontmatter 的 `parsed_by` 照原样展示在 `ocr_hint` 中。也展示库内已有的格式声明，比如含 `ocr` 字样的字段。
  - **不把后端名直接等同于「用了 OCR」**：同一后端可能走文本层，也可能走 OCR，没有可靠记录时，`ocr_hint` 留空，就是未知。
  - 本阶段**不新增**完整的解析方式记录机制。
  - 不靠后端名单永久决定 strict 豁免，也不靠它禁止自动修复。`ocr_hint` 是否影响 `strict`，同样由 §7 的分层度量决定。
- 原型实测：OCR 原文自带错字，还有混入句中的页眉和版面信息。按它逐字改正，会把错字带进 wiki；原型试跑中就有一页因此被改错，事后还原。这正是 §8 要把 OCR 校对作为单独能力来设计的原因。

## 6. 写入纪律（已落地）

`references/conventions.md` 新增〈直接引语〉一节，`SKILL.md` 的 ingest 写页要求引用它：
- 逐字引用与转述明确区分：直接引语只放逐字照抄的原文；
- 不相连的原文分别引用，或用「……」标出省略；
- 不带入脚注编号、页眉页脚、页码与版面信息。与核对的关系：脚注编号在 `norm()` 中两侧对等去除，删掉即可，不必标省略；页眉、页脚等插在句中的版面噪声无法可靠识别，跳过时用「……」标出（§3.2）；
- 疑似 OCR 错字不凭上下文猜改后当作逐字原文写入：能对照扫描件核实的按核实结果写，核实不了的照原文写并记 `待核`；
- 规则只约束直接引语：术语、提法、专名与书名篇名的引号不受约束，但整句加了引号就按直接引语对待。

## 7. 误报度量（实现 `--strict` 之前必做）

1. 按 §3～§5 的最终规则重写原型，全库重跑。
2. **分层抽样**：
   - **层**：`altered` 与 `unsupported` 两类，各自再分 OCR 提示层与非 OCR 层（共四层），另加 `misattributed` 一层作对照。
   - **样本量**：每层抽样，非 OCR 的两层各不少于 50 条。
3. **人工逐条裁决**，对照 raw（OCR 层另对照扫描件），记三种结论：
   - **确认问题**：引语确实不是原文；
   - **误报**：原文确实如此，是规则误判，记下误报成因；
   - **无法裁决**。
4. 按层给出确认率、误报率、无法裁决率，以及误报成因分布。
5. 据此决定：
   - 哪些 kind 在哪一层计入 `--strict`；
   - 覆盖率阈值；
   - §3.5 的过滤规则要不要调整。

度量报告附在本文之后。

## 8. 自动修复（另立 P3.14.1，不在本阶段）

原型已跑通，以下是后续设计必须保留或补上的要求：

- **保留**：
  - wrapper 保存写前副本，失败则回滚；写门禁没有按页回滚的能力，`page_guard` 只取元数据指纹，这一层要 wrapper 自己做；
  - 写后确定性复核：只许改清单所列的行；链接只许新增 source 页，不许删除；`:行` 引用不许增删；不许带入脚注编号；
  - 带失败原因重做，有轮数上限。
- **补上**：「修复后的引语在某份 raw 中逐字存在」**还不够**，还要核对修复后的**出处关系**。改成逐字的引语，必须在该行（修复后）出处所指的 raw 中命中（§3.3）；命中在别的 raw，就要同时补上正确出处，否则仍判不合格。原型只查了前一半。
- **OCR 校对作为可演进的能力**：后续模型校对可以同时读扫描件、OCR 文本和 wiki 引语，三方对照判断。先在真实库上评估准确率，再逐步放开自动处理；无法确认的交人工。
- **复核不能省**：原型中模型在重写时会重新写出同一个系统性笔误，靠写后复核才拦下。

## 9. 测试要点

- **应报出**：
  - 改一个字；
  - 缩写原句；
  - 两句拼成一句；
  - 转述加引号；
  - 引语中含 `[[链接|显示文本]]`；
  - 直引号与弯引号混用时的配对。
- **命中规则**：
  - 用「……」连接的两个片段**倒序**出现在原文中：不算命中；
  - 两个片段分别在两份 raw 中：不算命中，覆盖率也不合并；
  - 原文句子跨行：算命中。
- **不应报**：
  - 标点差异（含全角半角）；
  - 链接语法与粗体，**两侧对称**：引语带 `[[目标|显示文本]]`、raw 是纯文本，以及 raw 带 `[[目标|显示文本]]`、引语是纯文本，两种都通过；
  - 原文句中有脚注编号 `[4]`、引语按写入纪律删掉了它：通过；
  - 原文句中插有页眉、引语在该处用「……」标出省略：通过；
  - 「……」省略且片段顺序正确；
  - mermaid 节点；
  - 8 字以下的术语；
  - config 页。
- **防漏报**（「过滤规则要配漏报用例」，两面都要配）：
  - raw 的 frontmatter 里含有与引语相同的字段值时，**必须**报出（证明剥了 frontmatter）；
  - 序列标签规则的反例：含 `—`、`→` 但其中有完整句子的正常引语，必须收进来核对；
  - 未闭合引号：`“未闭合文字；“这里是一条完整的正常引语……”` 必须收下后一条引语；一行里有落单的 `”` 时，同行后面的正常引语照收；
  - 原文句中插有页眉、引语**没有**用省略号标出：报 `altered`（已知限制，用例写明预期，防止将来被误当作缺陷「修掉」）。
- **出处范围**（映射原语的三种情形分别测试）：
  - source 页只有 `> 原始资料：` 声明、没有 `raw_digest`，声明指向的 raw 可读：照常核对；
  - 只有 `raw_digest`：照常核对；
  - 两者都没有：判 `source_unreadable`，且不回退到页级 sources；
  - 行内引了 source 页时，只在它的 raw 里核；逐字见于别的 raw 时，判 `misattributed`；
  - raw 遍历不完整时，判 `scan_incomplete`，不出现 `unsupported`。
- **报告**：
  - `--strict` 与 `ok` 的关系；
  - 每条 finding 带 `strict` 与 `strict_reason`。
- **测试文件名**：一律用短 ASCII（长中文文件名在 Linux 上按字节计长，CI 会失败）。

## 10. 边界与失效条件

- **只证「引语出自原文」，不证「引语用得对」。** 断章取义、张冠李戴到错误的场合，都不在范围内。
- **依赖行内出处习惯。** 页面大量用不带来源名的裸 `:行` 时，会回退到页级出处，误报增多。补齐来源名是内容维护工作，不归本命令。
- **规则变化须同步。** 若 conventions 改变出处写法（如允许一个条目跨行引用），或者 raw 映射原语变化，本命令的范围规则须同步修改。
- **原型数据会过期。** §1 的数字只用来论证动机。规则一改，就以 §7 的度量为准。

## 11. 待决

1. `--strict` 计入哪些 kind、覆盖率阈值取多少：由 §7 决定。
2. 未闭合引号：只计数，还是报为一个独立的低优先级 kind？倾向只计数。
3. 结构标签过滤：本阶段只启用序列标签一条（§3.5）。其余按字符判断的规则是否换成按形态的规则，看 §7 的误报成因。
4. 直引号嵌在弯引号里（`“甲"乙"丙”`）会被截断（§3.1）。是否值得支持，看 §7 中这类误报的占比。
