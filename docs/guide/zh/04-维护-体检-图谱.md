# 维护:体检与图谱

知识库长期保鲜靠一组**零 LLM 的确定性维护工具**。`health` / `lint` 是 **advisory(建议性,默认不阻断)**;`graph` / `reindex` / `remove` 是确定性写派生物/修索引/撤源;`heal` / `audit` 是需 LLM 的写操作(走门禁)。

---

## `guanlan health`

文件级结构体检:**桩页(stub)+ index↔磁盘同步**,以及页型↔目录一致性、source 页无原文、overview 体积、**同名页**等提示。

```bash
guanlan -C my-wiki health
guanlan -C my-wiki health --json
guanlan -C my-wiki health --strict     # 有建议则以退出码 6 失败(供 CI/nightly)
```

| 参数 | 说明 |
|---|---|
| `--json` | 输出 JSON 契约 |
| `--strict` | 有建议时退出码 `6`(`EXIT_LINT_FINDINGS`),用于 CI/nightly 把建议升级为失败 |

默认 advisory:即使有建议也退出 `0`。`index_missing_page`(磁盘有页未收录)由 [`reindex`](#guanlan-reindex) 修。

`duplicate_stem`(同名页):两张页文件名相同(不分大小写、不看目录)时,`[[名字]]` 只能解析到路径排序在前的那张,其余按名不可达、在图谱里也共用一个节点。该提示报在不可达的那张页上;修法是合并两页,或给其中一张改名并改正指向它的链接(改名后旧名不能再作它的别名,否则撞另一张页)。见 [`P3.13`](../../P3.13-同名页检测.md)。

---

## `guanlan lint`

图感知结构 lint:**孤儿页 / 断链 / 缺失实体**,外加图谱拓扑的 advisory 发现(hub 节点 / 跨社区细链 / 孤立社区 / 割边 / 割点)。

```bash
guanlan -C my-wiki lint
guanlan -C my-wiki lint --json
guanlan -C my-wiki lint --strict
```

| 参数 | 说明 |
|---|---|
| `--json` | 输出 JSON 契约 |
| `--strict` | 有发现则退出码 `6` |

默认 advisory。`missing_entity`(高频断链)由 [`heal`](#guanlan-heal) 物化成页。

## `guanlan quotes`

引语核对：页面里加了引号的文字，是否逐字出自它所引来源的 raw 原文。**零 LLM、只读**，不改任何文件。

```bash
guanlan -C my-wiki quotes                    # 全库汇总:各类计数 + 不符最多的页
guanlan -C my-wiki quotes --page 某页          # 只查一页,逐条列出
guanlan -C my-wiki quotes --json             # 机器可读(含 summary)
guanlan -C my-wiki quotes --strict           # 有计入 strict 的不符则退出码 6
```

| 参数 | 说明 |
|---|---|
| `--page <名>` | 只核对一页,并逐条列出 |
| `--min-len N` | 引语归一后最少字数(默认 15;更短的多是术语,不查) |
| `--include-corner` | 另收「」内文字(默认只查双引号) |
| `--show-misattributed` | 逐条列出「措辞属实、出处未能核实」的引语(默认只计数) |
| `--json` / `--strict` | 同 health |

怎么读结果:

- `altered`:大部分文字出自原文,但改了字、缩写没标「……」或拼接了不相连的句子。**只有这一类、且原文没有 OCR 提示、引语不像标签时,才计入 `--strict`**(真实库两轮抽样精确率约 85%)。
- `unsupported`:原文里找不到。多是转述加了引号、标签或本库自己的措辞,只作建议。
- 措辞属实、出处未能核实:引语逐字存在,但不在本行所引的来源里。出处写法千差万别,本命令不断言出处错配,只计数。
- 未能核对:无出处、出处不可读(比如引用的是没有 raw 的实体页)、raw 遍历不完整。这是「没查成」,不是「查了没找到」。加 `--strict` 时,raw 遍历不完整本身即判失败:核对不完整,不能让 CI 通过。

原文是扫描件识别稿时,差异可能来自识别错字,`ocr_hint` 会列出 raw 里的解析信息;这类条目不计入 strict,改之前请对照扫描件。写法约定见技能 conventions〈直接引语〉,设计与度量见 [`P3.14`](../../P3.14-引语核对.md)。

## `guanlan graph`

确定性建图:`[[wikilink]]` → `graph/graph.json` + 自包含零-JS `graph/graph.html`(含社区、拓扑提示、割边/割点)。

```bash
guanlan -C my-wiki graph
guanlan -C my-wiki graph --json-only     # 只写 graph.json,跳过 graph.html
```

| 参数 | 说明 |
|---|---|
| `--json-only` | 只写 `graph.json`,跳过 `graph.html` |

图谱是**可幂等重建的派生物**,从不成为事实来源。LLM 推断边被刻意排除(保持可重建性)。

## `guanlan reindex`

索引回填:把磁盘已存在但未收录的内容页**登记进 `index.md`**。**零 LLM**,修 `health.index_missing_page`。

```bash
guanlan -C my-wiki reindex
guanlan -C my-wiki reindex --dry-run     # 只打印 worklist,不写盘
guanlan -C my-wiki reindex --prune       # 额外删除指向不存在文件的悬空行
```

| 参数 | 说明 |
|---|---|
| `--dry-run` | 只打印 worklist,纯读不写盘 |
| `--prune` | 额外删除 index 里指向不存在文件的悬空行(`index_dangling`),默认关 |
| `--json` | 输出 JSON 契约 |

默认应用(写 `wiki/index.md`)。一行摘要留空给后续 `ingest`/人填(决策 P3.4-1)。只写 `index.md`,不碰 `raw/`、不过门禁、不写 `log.md`。

## `guanlan heal`

缺失实体物化:把高频断链(被多页 `[[...]]` 引用却无页)**按需 LLM 建成 entity 页**。**走 P2 写门禁。需配置模型。**

```bash
guanlan -C my-wiki heal --dry-run                 # 仅打印 worklist(纯读、零 LLM)
guanlan -C my-wiki heal                            # 物化(默认上限/阈值)
guanlan -C my-wiki heal --limit 3 --min-refs 2
```

| 参数 | 说明 |
|---|---|
| `--limit` | 本批最多物化几个(按引用频次降序;须 ≥ 1) |
| `--min-refs` | 入选阈值:被 ≥ 此数页引用才物化(对齐 lint;须 ≥ 1) |
| `--dry-run` | 仅打印 worklist,纯读、零 LLM、不触 Agentao |
| `--model` | 覆盖 Agentao 模型 |
| `--json` | 输出 worklist/receipt 的结构化 JSON |

`--dry-run` 先看清要建哪些再决定。物化是受治理写入(子进程 + `raw/` 快照,同 ingest)。

## `guanlan audit`

语义审计:确定性粗筛**漂移源**(`raw/` 被替换/重转,但引用它的 wiki 页还没重新综合)→ LLM 复核这些页的论断是否过期。复核后由宿主把该源的新指纹刷回 source 页的 `raw_digest`(托管字段、勿手改)。**走 P2 写门禁。需配置模型。**

```bash
guanlan -C my-wiki audit --dry-run           # 仅打印漂移源组(纯读、零 LLM、不触 Agentao)
guanlan -C my-wiki audit                      # 复核(默认上限)
guanlan -C my-wiki audit --limit 3
```

| 参数 | 说明 |
|---|---|
| `--limit` | 本批最多复核几个**漂移源组**(按 slug 升序,整组原子复核+刷新;须 ≥ 1) |
| `--dry-run` | 仅打印漂移源组,纯读、零 LLM、不触 Agentao |
| `--model` | 覆盖 Agentao 模型 |
| `--json` | 输出漂移源组 / 回执的结构化 JSON |

典型场景:拿更新版 PDF `convert --overwrite` 盖掉旧 `raw/`,再跑 `audit` 找出哪些 wiki 页该重摄。若库里的 `raw/` 从不被覆盖,`audit` 永远空跑——这是**正确**的(无漂移即无候选)。

## `guanlan remove`

源撤回:把**误摄 / 已撤稿**的源整体移入回收区 `<库>/.trash/<slug>@时间戳/`(软删、非 `rm`,留 `manifest.json` 存档),多源衍生页里对该源的 `[[引用]]` 确定性摘除(只改 provenance、正文一字不动),撤回后留下的孤儿页/悬链只报 advisory。**人发起、零 LLM、不起 Agentao、不过门禁。**

```bash
guanlan -C my-wiki remove 旧报告               # 默认仅预览 worklist(零写盘)
guanlan -C my-wiki remove raw/旧报告.md --yes  # 确认执行(移入 .trash/)
```

| 参数 | 说明 |
|---|---|
| `src` | 源标识:`<slug>` / `raw/<slug>.md` / `wiki/sources/<slug>.md` |
| `--yes` | 确认执行(不带则只打印 worklist、零写盘——比 `reindex`/`convert` 更保守) |
| `--json` | 输出 JSON 契约(含 `backlinks`:指向该摘要页的页面清单) |

**预览会先说清撤完谁会悬链**:多一段 `⚠ 入链页`,列出正文里 `[[链接]]` 指向这张摘要页的页——撤走之后它们就悬空了。别名与大小写变体一样算数,代码块里的 `[[…]]` 不算(与 `check`/`graph` 同一道扫描归口)。仍是 advisory:入链页一字不动,撤回后跑一次 `guanlan lint` 复核全库断链。**同 stem 的两张页共用一个图节点**,故目标侧遇到歧义(`sources/foo` 与 `entities/foo` 同时存在)会退回空清单——那种情形下撤走摘要页后链接仍被同名页兜住、本就不会悬链;而来源侧反过来宁可多列,漏列会瞒掉本功能唯一要说的事。

**人发起的纠正路径**,与投喂(人加源)对称——只是方向相反。失源页的正文重综合是 LLM 的活,`remove` 不做,留给后续 `ingest`/人工(产一条 advisory 提示)。回收区即审计轨迹,反悔时可人工从 `.trash/` 取回。

## 退出码

| 码 | 名 | 含义 |
|---|---|---|
| `0` | `EXIT_OK` | 成功(advisory 命令即使有建议也是 0,除非 `--strict`) |
| `1` | `EXIT_USAGE` | 用法/环境错误(如缺可选依赖、参数非法、IO 失败) |
| `3` | `EXIT_CHECK_FAILED` | `check` 校验失败(写门禁把关项) |
| `4` | `EXIT_RAW_MUTATED` | 写操作期间 `raw/` 被改动(快照不一致) |
| `5` | `EXIT_AGENT_ERROR` | Agentao 运行时/Agent 出错 |
| `6` | `EXIT_LINT_FINDINGS` | `health`/`lint` 在 `--strict` 下有建议/发现 |

**advisory-not-gate**:`health`/`lint` 默认退 `0`,只在 `--strict` 才用 `6` 失败——日常用看报告、CI/nightly 用 `--strict` 当门禁。
