# 安装

## 环境要求

- **Python 3.10+**。
- 核心命令（`init` / `check` / `health` / `lint` / `graph` / `reindex` / `search`）**零 LLM、可离线运行**，不需要任何模型或网络。
- `ingest` / `query` 以及 Web 端问答需要**配置一个模型**（经 Agentao 运行时）。
- `convert` 从观澜这一侧看也是零 LLM，但它会**外调** `pdf-to-markdown` 技能的转换后端（MinerU / marker / pypdf），真正跑一次转换需至少装好其中一个后端。

## 安装核心包

```bash
pip install guanlan-wiki
```

> PyPI 发布名是 `guanlan-wiki`（裸名 `guanlan` 已被一个无关项目占用）；安装后**命令行与导入名仍是 `guanlan`**。

验证：

```bash
guanlan --version     # 应打印当前版本（如 0.1.9）
guanlan --help
```

## 可选宿主（叠加层，按需安装）

观澜的核心是 CLI；Web / MCP / IM 三个宿主都是**可选叠加层**，不装也能用全部 CLI 命令。

### Web 宿主

```bash
pip install 'guanlan-wiki[web]'
```

带入可选依赖：`fastapi` / `uvicorn` / `markdown` / `python-multipart` / `anyio`。装完才有 `guanlan web`，详见 [Web 宿主](05-web-宿主.md)。

### MCP 宿主

```bash
pip install 'guanlan-wiki[mcp]'
```

带入官方 `mcp` SDK（`mcp>=2,<3`）与 `anyio`。装完才有 `guanlan mcp`，详见 [MCP 宿主](06-mcp-宿主.md)。

> SDK **1.x 已不支持**（P4.18 硬切到 v2 / 协议 `2026-07-28`）。环境里若还钉着 1.x，`guanlan mcp` 会明确提示升级；照旧钉在旧修订的 MCP 客户端不受影响——v2 服务端仍同时服务握手时代的协议修订。

### IM 宿主

```bash
pip install 'guanlan-wiki[im-weixin]'   # 个人微信
pip install 'guanlan-wiki[im-feishu]'   # 飞书 / Lark
pip install 'guanlan-wiki[im]'          # 两个都要
```

**按平台分成两个 extra 是有意的**：只用微信的人不该被拖来一份 `lark-oapi`。微信侧带入 `httpx` 与 `qrcode`（终端里画登录二维码），飞书侧带入 `lark-oapi>=1.6.8`。装完才有 `guanlan im` / `im-login` / `im-identify`，详见 [IM 宿主](08-im-宿主.md)。

> 飞书的下限 `1.6.8` 钉得很死：那是长连客户端接受 `extra_ua_tags` 的第一个版本，**不传这个 tag 服务端就不推群 @ 事件**。版本过旧时适配器会拒绝启动并让你升级——这比连上了却静默收不到群消息好。

> 每个 extra 都是「**没装就优雅降级**」：未安装对应依赖时,运行 `guanlan web` / `guanlan mcp` / `guanlan im` 会给出明确的「请 `pip install 'guanlan-wiki[...]'`」提示,而非崩溃。IM 的探针**只探你指定的那个平台**——装了 `[im-weixin]` 的人不会因为没装 `lark-oapi` 就跑不了微信。

## 从源码开发安装

仓库用 [`uv`](https://github.com/astral-sh/uv) 管理依赖:

```bash
git clone <repo-url>
cd guanlan
uv run guanlan --help     # 直接在项目环境里跑 CLI
uv run pytest             # 跑测试
```

开发模式下,仓库根**自身就是一个样例 wiki**,维护引擎 `skills/guanlan-wiki/` 会命中 Agentao 的 repo-root 技能发现路径(`<工作目录>/skills/`),**免安装**。详见仓库根 [`CLAUDE.md`](../../../CLAUDE.md) 的「Two run modes」。
