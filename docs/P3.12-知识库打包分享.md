# P3.12 知识库打包分享（`guanlan zip`，零 LLM）

> **半阶段增强（不是新里程碑），已实现。** 新增 `guanlan zip`：把一个知识库打成可以直接交给别人的 zip，
> **默认排除私有配置、日志、会话、工作数据与操作系统隐藏文件**。零 LLM、只读知识库，唯一的写入是输出的 zip。
>
> 关联：[`P3.9-源撤回.md`](P3.9-源撤回.md)（`.trash/` 的来历）、[`P4-Web宿主.md`](P4-Web宿主.md)
> 与 [`P4.6-Web上传与晋级.md`](P4.6-Web上传与晋级.md)（`workspace/` 的来历）、[`P3.7-语义审计.md`](P3.7-语义审计.md)（`raw/` 可为指向库外存储的符号链接）。

## 1. 动机与对既有判断的修订

[`backlog/notes/llm_wiki-反向评审-v0.6.4.md`](backlog/notes/llm_wiki-反向评审-v0.6.4.md) §46 曾判「库归档 = 目录
tar/git，观澜无需内建」。那次考虑的是**归档**：库作者自己保存历史，git 足够。

本次需求是**分享**：把库交给不用 git 的人（如在 Windows 上解压后直接 `guanlan web`）。这时难点不在「打成一个文件」，
而在**别把私有数据一起送出去**。一个用过的知识库根目录里，除了 `raw/`、`wiki/` 和两份配置，还有：

| 路径 | 内容 | 为什么不能外传 |
|---|---|---|
| `.env` | 模型、搜索服务的 API Key | 凭据 |
| `agentao.log*` | Agent 运行日志 | 含完整提示词与工具输出 |
| `.agentao/` | 会话（`sessions/`）、记忆库 `memory.db`、权限设置、工具输出落盘、目标 | 使用记录与本机配置 |
| `workspace/` | Web 上传件、解析中间稿、作者的草稿与脚本 | 未审的工作数据 |
| `.trash/` | `remove` 撤回的页面 | 作者有意撤下的内容 |

手工 `zip`/`tar` 整个目录会把这些全带上。故**修订原判断**：归档仍交给 git，**分享**由观澜内建，价值在排除规则。

## 2. 决策

- **决策P3.12-1 白名单，不用黑名单。** 库根下只收 `AGENTAO.md`、`SCHEMA.md`、`wiki/`、`raw/`，可选 `graph/`；
  其余一律不收，并在报告里逐项列出「排除（不在分享白名单内）」。黑名单只能挡已知的私有文件；用户日后在库根放的
  新文件（脚本、笔记、导出物）白名单默认不收，不会因规则没跟上而外泄。
- **决策P3.12-2 `raw/` 默认收、`graph/` 默认不收、`.trash/` 永不收。**
  - `raw/` 是事实来源，接收方要核对引用行号、继续 `ingest`/`audit` 都需要它；有版权顾虑时 `--no-raw` 只分享 wiki。
  - `graph/` 是派生物（Markdown 唯一真相），接收方 `guanlan graph` 几秒即可重建，且可能已过时；`--with-graph` 才收。
  - `.trash/` 是作者撤回的内容，没有开关。
- **决策P3.12-3 白名单目录内再按路径过滤。**
  - 路径任一段以 `.` 开头：`.DS_Store`、`._*`（AppleDouble）、`.git/`、`.obsidian/`、`raw/.gitkeep` 等。
  - 操作系统 / 编辑器杂项：`Thumbs.db`、`ehthumbs.db`、`desktop.ini`、`__MACOSX/`、`Icon\r`、Office 锁文件 `~$*`、
    `*.swp` / `*.swo` / `*~`。
  - 符号链接不跟随，跳过并报告——防把库外文件（如私钥）经链接打进去。**例外**：白名单目录**本身**是符号链接
    （如 `raw/` 指向库外存储，P3.7 已承认此形态）时照常进入其内容。白名单根文件（`AGENTAO.md` 等）是符号链接时同样跳过。
  - 非普通文件（管道、套接字、设备）跳过。
- **决策P3.12-4 只按路径过滤，不检查内容。** 正文是用户的内容，扫描密钥既会误报也给人虚假的安全感。报告末尾固定
  提示「分享前请自行确认 AGENTAO.md、SCHEMA.md 与 wiki 正文不含不宜外传的信息」。
- **决策P3.12-5 zip 形态。**
  - 顶层是一个以库名命名的目录：接收方解压到父目录即得完整知识库（对应用户指南里「ZIP 包内包含顶层目录」的情形）。
  - 非 ASCII 文件名由 `zipfile` 自动置 UTF-8 标记（通用位 11），Windows 自带的 `Expand-Archive` 解压中文名不乱码。
  - 收入的目录都写目录条目，空的 `raw/` 也保留，解压后库骨架完整（`require_kb_root` 的写入口要求 `raw/` 存在）。
  - 条目按路径排序；保留文件修改时间（1980 年以前的时间钳到 1980，`strict_timestamps=False`）；DEFLATE 压缩。
- **决策P3.12-6 输出准入。**
  - 默认 `<库名>-YYYYMMDD.zip`，放当前目录；**当前目录在库内时改放库的上一级目录**（先 `cd` 进库再跑是常见用法）。
  - 输出落在库内即拒绝，`raw/`、`wiki/`、`graph/` 经符号链接指向的库外存储也算库内——否则会把 zip 自己或半成品打进库里、或写进只读的 `raw/`。
  - 父目录须存在；目标已存在须 `--force`（`--dry-run` 不查）；先写同目录临时文件 `.<名>.tmp-<pid>` 再原子改名，中断不留半个 zip。
- **决策P3.12-7 报告。** 收入文件数与大小、各白名单项的文件数、排除项、跳过的隐藏文件 / 杂项 / 符号链接 / 非普通
  文件（前 5 项 + 总数），以及无权限读取、未能收入的目录（`⚠`，否则会沉默漏收）。zip 内最长路径超过 200 字符时提醒：Windows 解压到较深目录可能超过 260 字符上限。
  `--dry-run` 只预览、不写；`--json` 给出结构化结果与完整文件清单（`entries`）。

## 3. 命令

```bash
guanlan -C <库> zip                     # 打包到 ./<库名>-YYYYMMDD.zip（在库内运行则放库的上一级目录）
guanlan -C <库> zip -o share/alpha.zip   # 指定输出路径
guanlan -C <库> zip --dry-run           # 只看会收入与排除什么
guanlan -C <库> zip --no-raw            # 只分享 wiki
guanlan -C <库> zip --with-graph        # 连同 graph/
guanlan -C <库> zip --json              # 结构化结果（含完整文件清单）
```

退出码：成功 0；非知识库、输出在库内、输出目录不存在、目标已存在未加 `--force`、写入时读文件失败 → 1（`EXIT_USAGE`）。

`--json` 契约：

```json
{
  "output": "/abs/alpha-20261106.zip",
  "dry_run": false,
  "files": 5,
  "bytes": 1234,
  "compressed_bytes": 987,
  "included": {"AGENTAO.md": 1, "SCHEMA.md": 1, "wiki/": 2, "raw/": 1},
  "excluded_top": [".agentao/", ".env", "agentao.log", "workspace/"],
  "hidden": ["wiki/.DS_Store"],
  "junk": [],
  "symlinks": [],
  "special": [],
  "unreadable": [],
  "longest_path": {"chars": 24, "path": "alpha/wiki/concepts/Foo.md"},
  "entries": ["alpha/AGENTAO.md", "..."]
}
```

`--dry-run` 时 `output` 与 `compressed_bytes` 为 `null`。

## 4. 不做

- **不扫描内容**（决策P3.12-4）。
- **不做解压 / 导入命令**：接收方用系统自带工具解压即可。
- **打包前不跑 `check`**：打包是复制，不评判内容质量；需要时自行先跑。
- **不加锁**：打包时若有写作业（`ingest` 等）在跑，可能收进不一致的中间状态。打包前应确认没有写作业在运行。
- **不在 Web / MCP / IM 暴露**：分享是库作者在本机的一次性操作，CLI 足够。

## 5. 实现与测试

- `guanlan/zipkb.py`（不叫 `zip.py`，免与内建 `zip` / 标准库 `zipfile` 混淆）：`build_plan`（纯计算）→
  `_check_output`（准入）→ `write_zip`（临时文件 + 原子改名）→ `format_report` / `format_json`；
  `zip_entrypoint` 是 CLI 与 `python -m guanlan.zipkb` 的共同落点。
- `tests/test_zipkb.py`：白名单与私有数据排除（逐一列出 `.env`、`.env.local`、日志、`.agentao/`、`workspace/`、
  `.trash/`、库根杂文件、`graph/`）；白名单目录内的隐藏文件与杂项（逐一列出，防规则吞掉后沉默漏报）；库内符号链接
  跳过、`raw/` 本身是符号链接时照常收入；输出在库内（含 `raw/` 的库外存储）拒绝；已存在需 `--force`；输出目录不存在；
  默认输出在库内运行时落到上一级目录；顶层目录、UTF-8 标记、空目录条目、条目有序、无临时文件残留；`--dry-run` /
  `--no-raw` / `--with-graph`；`--json` 契约；非知识库；打包前后库内文件逐字节不变。
