## 0. 动机

1. **网上的资料要先手动下载再上传**：政策文件、报告 PDF、网页文章，现在都要先存到本地、再从「导入」上传。
   多一次落地，出处也断了——入库后 `origin` 记的是 `workspace/uploads/x.pdf`，看不出原文来自哪个网址。
2. **HTML 转出来噪声大**：`.html` 现在走 MinerU（固定 `flash` 档）或 marker，导航、侧栏、页脚、版权声明、
   相关推荐整段进 `raw/`，ingest 时被当正文。一键入库的页眉页脚清理靠分页锚点，网页没有分页，这一步不起作用。
3. **HTML 没有不需模型的后端**：pandoc 只给 `.docx` 用；没装 MinerU / marker 时 HTML 直接转换失败。
   pandoc 按 `<h1>`–`<h6>` 出标题层级，一键入库的拆分正好按标题切。

## 1. 用户流程与界面

「导入 → 上传文件」区，现有「上传文件…」按钮旁加「从网址下载…」，弹出：

```
┌ 从网址下载 ───────────────────────────────────────┐
│ 网址                                              │
│ [ https://example.org/report-2026.pdf          ]  │
│ □ 下载完成后直接一键入库                            │
│   □ 网页保留整页（不提取正文）                       │
│                               [取消]  [下载]      │
└──────────────────────────────────────────────────┘
```

点「下载」后弹窗显示进度，可「停止」：

```
  ⟳ report-2026.pdf        12.4 / 38.0 MiB
```

- 下载完成后刷新「上传文件」列表，下载来的文件与上传的文件同列，文件名旁标「🔗」，悬停显示原网址。
- 勾选「直接一键入库」时，下载成功后宿主自动发起一键入库的准备阶段，弹窗切到解析进度浮层（同点「一键入库」）；
  准备完成停在「等待确认」，用户在任务卡上点「开始入库」。「保留整页」只在下载结果是网页时起作用。
- 同一时刻只有一个下载：已有下载在进行时，按钮置灰并显示正在下载的网址。
- 可写会话进行中：按钮置灰（同上传，层③）。reader 宿主不显示。

**HTML 文件行多一个「整页一键入库」**（图标按钮，悬停说明「不提取正文，整页转换」）。无论文件是上传的还是下载的，
只要是 `.html` / `.htm`，都有这个入口。用途是**重试**：用户在等待确认时从「已解析」预览发现正文提取丢了段落，
放弃任务后，对同一文件点「整页一键入库」再来一次。不新增预览或比对功能。

## 2. 下载

### 2.1 端点

下载与上传同走 #172 的「快车道」：**不进写作业队列、不取库级锁**——它只写 `workspace/uploads/`，
CLI 与 wiki 写作业都不写这里。下载可能要几分钟（大 PDF），不能占着一个 HTTP 请求，故在后台线程执行、前端轮询：

| 端点 | 说明 |
|---|---|
| `POST /api/upload/url {url, oneclick?: bool, html_extract?: "auto"\|"off", backend?: str}` | 校验网址格式，后台开始下载，返回 `{download_id}`。层③ 423；已有下载在进行 → 409（带正在下载的网址） |
| `GET /api/upload/url` | 当前或最近一次下载：`{download_id, url, state, received, total, saved, kind, error, oneclick_job}`；没有 → `null` |
| `POST /api/upload/url/{download_id}/cancel` | 停止：中断下载、删除临时文件 |

- `state` ∈ `downloading` / `committing` / `done` / `failed` / `cancelled`。
- 下载状态只在内存里（§9 Q4），服务重启即丢；中途被杀留下的隐藏临时文件由现有的启动清理（`sweep_stale_upload_tmps`）收掉。
- 页面刷新后用 `GET /api/upload/url` 找回进行中的下载，所以不需要前端记住 `download_id`。
- 全部 `_writer_only`；reader 下不注册（决策P4.9-2）。

### 2.2 下载过程

**分两段**：后台线程只负责把字节下到临时文件；选名、检查、换名统一回到事件循环线程做（决策P4.31-4）。

后台线程（`fetch.py`）：

1. **网址校验**：只收 `http` / `https`；拒绝带用户名密码（`https://user:pw@host/…`）；长度 ≤ 2048。
2. **安全检查**（§3）：解析域名，目标地址在禁止网段 → 拒绝。
3. **请求**：`GET`，不带 Cookie、不带认证头；User-Agent 用通用的 `guanlan/<版本>`，不带用户、库名等任何本地信息。
   跳转由下载器自己跟（最多 5 次），**每一跳都重做 §3 检查**。
4. **流式写盘**：边收边写 `workspace/uploads/.upload-*.tmp`，内存里同时只有一块；超过上限立即断开。
   停止标志置位即中断、删临时文件。
5. **判定类型**（§2.3），算出建议文件名（§2.4）与出处记录内容（§2.5），交回事件循环。

事件循环线程（与 `POST /api/upload` 的提交在同一线程、中间不 `await`，见 §2.4）：

6. 层③ 再查一次（下载可能要几分钟，期间可能开始了可写会话）→ 423 则删临时文件、记失败；
7. 定最终文件名（同名加序号）→ 写出处记录 → 换名；
8. `oneclick=true` 时调 `start_prepare`（§6）。

限额：

| 项 | 值 | 说明 |
|---|---|---|
| 单个文件 | 256 MiB | 同上传 `MAX_UPLOAD_BYTES` |
| 连接超时 | 10 秒 | |
| 读空闲超时 | 60 秒 | 连续这么久收不到数据即失败 |
| 总时长 | 15 分钟 | |
| 跳转 | 5 次 | |

### 2.3 类型判定

本期只支持下表这些格式；**内容嗅探说了算**，扩展名与 `Content-Type` 只用来判断「期望」与给文件命名。

| 格式 | 判定依据 | 扩展名 |
|---|---|---|
| PDF | 文件头 `%PDF-` | `.pdf` |
| Word / PowerPoint / Excel | 文件头 `PK\x03\x04`，且 zip 里的 `[Content_Types].xml` 声明了对应的主文档类型 | `.docx` / `.pptx` / `.xlsx` |
| HTML | 去掉 BOM 与空白后以 `<!doctype html` 或 `<html` 开头（不分大小写） | `.html`（`.htm` 统一改 `.html`） |
| 图片 | PNG / JPEG / GIF / WebP / TIFF / BMP 魔数 | 对应扩展名 |
| Markdown | `Content-Disposition` 文件名或网址路径以 `.md` / `.markdown` 结尾，或 `Content-Type: text/markdown`；且内容是合法 UTF-8、不含 NUL | `.md` |

- 都不符合 → `failed`「暂不支持从网址下载这种格式（…）；请先下载到本地，再用「上传文件…」上传」。
  这包括 EPUB、CSV / TSV、RTF、ODT、MHTML、`.doc` / `.xls` / `.ppt` 老格式等——它们上传后照样能一键入库，
  只是不在下载这一侧做识别（决策P4.31-3）。
- **期望与实际不符时拒绝**：`Content-Disposition` 文件名、网址路径或 `Content-Type` 表明是 PDF / Office，
  嗅探却是 HTML → `failed`「返回的是网页而不是 PDF，可能需要登录或链接已失效」。这是最常见的坑：登录页、
  验证码页、软 404。
- 期望是 HTML（`text/html`）、嗅探也是 HTML → 正常按网页处理。

### 2.4 文件名与提交

建议文件名：

1. `Content-Disposition` 文件名（含 RFC 5987 的 `filename*`）→ 2. 网址路径末段（百分号解码）→
   3. `<主机名>-<路径 slug>`；
2. 扩展名以 §2.3 的判定为准（补上或改正）；
3. 过上传同一套规范化（`_safe_workspace_target(root, "uploads", …)`：Unicode 规范化、去非法字符、UTF-8 字节限长）。

**同名不覆盖，加序号**（`report-2026-2.pdf`）。与上传不同：上传的文件名是用户自己选的、覆盖是本意；
下载的文件名来自对方服务器，不能让它悄悄替掉用户已有的文件。

**提交的并发边界**：「选名 → 检查不存在 → 换名」如果放在后台线程里做，两个并发提交会选中同一个
`report-2026-2.pdf` 而互相覆盖。所以这一段**回到事件循环线程**、中间没有 `await`，与 `POST /api/upload` 的
提交（`commit_upload`）在同一线程上串行——上传与下载的提交不会穿插，不需要库级锁。
换名用「不覆盖」的方式（`os.link` 后删临时文件；目标已存在则换下一个序号），兜住事件循环之外的写入者
（如用户在 Finder 里往 `uploads/` 拷文件）。

「不覆盖」只约束**下载**的提交；**上传的覆盖规则不变**：

| 先后 | 结果 |
|---|---|
| 上传先提交、下载后提交同名 | 下载加序号（`report-2026-2.pdf`），两份都在 |
| 下载先提交、上传后提交同名 | 上传按既有规则覆盖（用户自己选的名字）；下载留下的出处记录因哈希不符而失效（§2.5），该文件此后按普通上传处理 |

### 2.5 出处记录

每个下载成功的文件旁写一份隐藏的出处记录 `workspace/uploads/.<文件名>.source.json`（点文件，暂存区列表不显示）：

```json
{
  "url": "https://example.org/r?id=42",
  "final_url": "https://cdn.example.org/files/report-2026.pdf",
  "fetched_at": "2026-11-11T10:23:45+08:00",
  "sha256": "…",
  "content_type": "application/pdf",
  "charset": null,
  "bytes": 4404019
}
```

- `charset`：`Content-Type` 头里声明的字符集（HTML 才有意义，§4.1）。
- 提交顺序：先写出处记录的临时文件，换名文件，再换名出处记录。中途失败留下「有文件、没记录」，
  等同于一个普通上传，不会出错。
- 只认 `sha256` 与文件当前内容一致的记录：同名文件后来被手工上传覆盖，记录即失效，读到时删掉。
- 删除暂存文件（现有的 `DELETE /api/workspace/file`）时一并删掉它的出处记录。

## 3. 网络安全

Web 宿主只监听 127.0.0.1、单用户，发起请求的就是用户本人；但「本机替用户去取网址」仍是一个新的出网能力，
要防的是：粘贴来的网址（或网址跳转）把请求引到本机或内网服务（SSRF）。

**默认直连**，不读 `HTTP_PROXY` / `HTTPS_PROXY` 等环境变量（httpx `trust_env=False`）：

- **禁止网段**（解析后的每个地址都查，任一命中即拒绝）：回环 `127.0.0.0/8`、`::1`；私网 `10/8`、`172.16/12`、
  `192.168/16`、`fc00::/7`；链路本地 `169.254/16`（含云元数据 `169.254.169.254`）、`fe80::/10`；
  CGNAT `100.64/10`；`0.0.0.0/8`、组播、保留段；IPv4 映射的 IPv6 按其 IPv4 判。
- **固定解析结果**：解析一次、用解析出的地址建连接（`Host` / SNI 仍用原主机名），不让连接时再解析出另一个地址
  （防 DNS 重绑定）。每一跳跳转都重做解析与检查。
- **放行内网**：环境变量 `GUANLAN_FETCH_ALLOW_CIDRS`（逗号分隔 CIDR），形式参照 agentao 的
  `AGENTAO_WEB_FETCH_ALLOW_CIDRS`，用于取公司内网文档。默认空。

**代理是显式配置**：设了 `GUANLAN_FETCH_PROXY` 才走代理，此时**目标地址由代理解析，信任交给代理**——
本机不再做网段检查（本机查到的地址与代理实际连接的地址可能不同，查了也没有保证），只拒绝网址里直接写的
禁止网段 IP 与 `localhost`。用户指南写明这一点：配置代理即表示信任该代理对目标地址的处理。

其它：

- **证书**：校验 TLS 证书，不提供关闭开关。
- **不做**：不读 `robots.txt`（这是用户逐个粘贴的单次下载，不是爬取）；不带浏览器 Cookie，需要登录的页面取不到，
  按 §2.3 的「期望与实际不符」报给用户。

## 4. HTML 转换：正文提取 + pandoc 优先

改在 `pdf-to-markdown` skill 的 `convert.py` 里做（格式处理归口在 skill，决策P5.2-2/5），
因此 `guanlan convert x.html` 与一键入库同时受益；本地另存的网页同样适用。

```
原始 HTML 字节
  → ① 解码成 UTF-8
  → ② 正文提取（trafilatura）—— --html-extract off、不可用或结果过短时用整页
  → ③ 图片与链接改写：相对地址补全，远程图片改成普通链接（§4.4）
  → ④ 写临时 UTF-8 HTML
  → ⑤ 后端链：pandoc → mineru → marker（对 ④ 的产物）
```

①–④ 是**公共 HTML 预处理**，在进入后端链之前做完，不论最终由哪个后端转换，输入都已是 UTF-8、
已提取正文、不含远程 `<img>`。

### 4.1 解码

pandoc 只认 UTF-8 输入，中文网站仍有不少 GBK / GB18030 页面，必须先转码。字符集按序取：

1. 宿主传入的 `--html-charset`（出处记录里的 HTTP 头字符集；HTML 规范里它优先于文档内声明）；
2. BOM；
3. 文档前 4 KiB 内的 `<meta charset>` / `<meta http-equiv="Content-Type">`；
4. `charset_normalizer` 探测（trafilatura 的依赖；没装时跳过这一步）；
5. 以上都没有 → UTF-8，`errors="replace"`，日志记一行。

`gb2312` / `gbk` 一律按 `gb18030` 解（超集，避免生僻字解坏）。

### 4.2 正文提取

用 **trafilatura**（Apache-2.0，与观澜同许可；零模型、确定性）。实测 2.3.1：
`extract(html, output_format="html", include_tables=True, include_images=True, include_links=True,
include_formatting=True, url=<base>)` 去掉 `<nav>` / `<footer>`，保留 `<h1>`–`<h6>`、表格、图片。

- **输出 HTML 而不是它自带的 Markdown**：交给 pandoc 统一转，标题层级、表格（含合并单元格）与 `.docx` 同一口径。
- **结果过短时退回整页**：提取出的可见文字 < 200 字，或不到整页可见文字的 10% → 判为提取失败、用整页，
  日志记一行。这只挡得住「几乎全丢」；**长度检查保证不了正文完整**，提取结果够长却丢了重要段落时，
  靠「保留整页」重试（§1，决策P4.31-13）。
- **标题**：提取结果里没有 `<h1>` 时，用页面 `<title>`（trafilatura `with_metadata` 的 `title`）补一个，
  一键入库的 frontmatter `title` 与拆分都靠它。
- **不可用时降级**：环境里没有 trafilatura → 跳过提取、用整页，日志 `[html] extract=none（未安装 trafilatura）`。
- **开关**：skill 参数 `--html-extract {auto,off}`，默认 `auto`。Web 经 §1 的「保留整页」/「整页一键入库」
  传 `off`；`guanlan convert` 本期不加对应参数（直接调 skill 的用户可自行传）。

### 4.3 pandoc 处理 HTML

`PANDOC_EXTENSIONS` 加入 `.html` / `.htm`；`auto` 顺序变为 HTML：pandoc → mineru → marker。
`.mhtml` / `.mht` 不变（只有 MinerU 4 能转）。

参数（本地 pandoc 3.13 实测）：

```
pandoc in.html -f html-native_divs-native_spans -t gfm --wrap=none --lua-filter <过滤器>
```

| 写法 | 实测结果 |
|---|---|
| `-f html -t gfm` | `<div class=…>`、`<span style=…>` 原样漏进 Markdown |
| `-f html -t gfm-raw_html` | 包装标签没了，但合并单元格的表格被拍平成错位的管道表 |
| **`-f html-native_divs-native_spans -t gfm`** | 包装标签去掉、合并单元格表格保留为 HTML 表格，与 `.docx` 口径一致 ✓ |

### 4.4 图片

在公共预处理第 ③ 步做（决策P4.31-9），**不放在 pandoc 的 Lua 过滤器里**：回退到 MinerU / marker 时
不会执行 pandoc 过滤器，而现有的图片收集（`collect_and_rewrite`）对外链原样保留，远程 `<img>` 就会漏进 `raw/`。
在送进任一后端之前改好，一次处理覆盖整条后端链。

- **远程图片不下载，改成普通链接**：`<img src="https://…/a.png" alt="说明">` → `<a href="https://…/a.png">图：说明</a>`
  （没有 `alt` 时为「图」）；已在 `<a>` 里面的图片只换成文字「图：说明」，外层链接保留，不造嵌套链接。
  理由：`raw/` 里留 `<img>` 远程地址，Web 预览会让浏览器去第三方站点取图（泄露访问、可被追踪），图也可能随时失效；
  改成链接后出处还在、不会自动发请求。各后端都把 `<a>` 转成 Markdown 链接。
- **相对地址先补全**：下载来的网页里 `src="/img/a.png"` 按 `--html-base-url`（出处记录的 `final_url`）
  补成绝对地址再转链接；`<a href>` 同样补全。本地另存的网页没有基址 → 相对图片保持 `<img>` 原样，由一键入库报
  「图片找不到，原样保留」（与现状一致）。
- `srcset` 属性与 `<picture>` 里的 `<source>` 一并去掉（它们同样会触发远程请求，且后端各自处理不一）。
- `data:` 内嵌图片不动：pandoc 由现有的 `--extract-media` 落成本地图片，与 `.docx` 同。
- **实现方式**：用标准库 `html.parser` 逐标签改写，其余内容按原文字节输出（`get_starttag_text`），
  不依赖 lxml——没装 trafilatura（也就没有 lxml）时这一步照样执行。
- pandoc 现有的 `PANDOC_IMAGE_FILTER`（非网页格式图片换说明文字、拆 `<figure>`）保留不变。
- 下载网页里的图片到 `raw/images/` 不在本期（§11）。

### 4.5 留痕

skill 在 stderr 多打一行 `[html] extract=trafilatura|off|none|fallback`，观澜按 #171 读 MinerU 档位的同一方式读回，
`parsed_by` 记 `pandoc+trafilatura`、`pandoc`（关闭 / 未安装 / 退回整页）、或原有的 `mineru/flash`、`marker`。
可以直接查出哪些源是整页转换的。

## 5. 出处进入 `raw/`

一键入库准备阶段（`oneclick.prepare` ①）发现原件旁有有效的出处记录（§2.5）时：

- frontmatter `origin` 记**最终网址** `final_url`（原网址不同时另记 `origin_url`），不再记 `workspace/uploads/…`；
- 加 `fetched: 2026-11-11`（网页内容会变，抓取日期是出处的一部分）；
- 把 `--html-charset`、`--html-base-url` 传给转换（经 `convert_to_markdown` 新增的可选参数透传）。

拆分出的每一份都带同样的 `origin` / `fetched`（沿用 P4.30 分卷继承整本元数据的口径）。
任务清单的 `upload` 字段不变（仍是暂存区里的路径），另加 `source_url` 与 `html_extract`，任务卡显示网址。

## 6. 下载后直接一键入库

- 后端串联，不靠前端：`oneclick=true` 时，提交（§2.2 第 8 步）后由宿主调用与 `POST /api/oneclick`
  **同一个函数**（把 `oneclick_start` 的检查与入队抽成 `start_prepare(upload_path, backend, html_extract)`）
  发起准备作业，作业号记进下载状态。用户关掉页面也照样发起。
- 发起失败（已有未完成的入库任务、库正被 CLI 写等）→ 文件保留在暂存区，下载状态里记原因，弹窗显示
  「已下载，但没能开始一键入库：…；稍后在列表里点一键入库」。
- 准备阶段照常可「停止」（#173）；准备完成停在「等待确认」（决策P4.30-8，§9 Q2）。

## 8. 决策（草案）

- **决策P4.31-1（下载走上传快车道）**：只写 `workspace/uploads/`，不进写作业队列、不取库级锁，与 #172 同理；
  一键入库运行期间也能下载。
- **决策P4.31-2（只下载、不渲染）**：取的是网址返回的那个文件本身，不执行 JavaScript、不带 Cookie。
  需要脚本渲染或登录的页面取不到完整内容，按「期望与实际不符」或提取过短报给用户，不尝试绕过。
- **决策P4.31-3（下载只认一小组格式，类型以内容嗅探为准，期望不符即拒绝）**：PDF、HTML、DOCX / PPTX / XLSX、
  图片、Markdown，每种都有明确的嗅探规则；其余格式提示先下载再上传，不为识别更多格式扩展一套框架。
  期望不符即拒，防止登录页 / 软 404 以 `.pdf` 之名进入管线。
- **决策P4.31-4（下载在后台线程，提交在事件循环）**：后台线程只下字节；选名、检查、换名回到事件循环线程、
  中间不 `await`，与上传的提交串行。同名加序号、不覆盖：文件名来自对方服务器，不能替掉用户已有的文件。
- **决策P4.31-5（默认直连、禁止内网与本机地址、逐跳检查、固定解析结果；代理须显式配置并被信任）**：
  Web 宿主第一次替用户出网取内容。内网放行须显式配置 `GUANLAN_FETCH_ALLOW_CIDRS`；配置了
  `GUANLAN_FETCH_PROXY` 即把目标解析交给代理，不再叠加本机网段规则（那解决不了代理重新解析的问题）。
- **决策P4.31-6（出处记录是派生的隐藏文件，以哈希绑定）**：不进 `raw/`、不是真相来源；哈希不符即作废。
  入库后出处落在 `raw/` 的 frontmatter（`origin` / `fetched`），那里才是长期记录。
- **决策P4.31-7（正文提取与 HTML 转换在 skill 里做）**：格式处理归口 skill（决策P5.2-2/5），
  `guanlan convert` 与一键入库同口径；宿主只透传字符集、基址与提取开关。
- **决策P4.31-8（正文提取是零模型的确定性规则，结果过短即退回整页）**：宿主不持 LLM 的不变式不变；
  宁可多留噪声，不可丢正文。
- **决策P4.31-9（远程图片转链接，不下载、不留 `<img>`，在公共预处理里做）**：`raw/` 不触发第三方请求；
  改写放在进入后端链之前，pandoc、MinerU、marker 都覆盖到。图片下载另议（§11）。
- **决策P4.31-10（「直接一键入库」后端串联，确认关口保留）**：复用 `start_prepare`，不另开一条入口；
  写 `raw/` 前的确认（决策P4.30-8）不因勾选而跳过。
- **决策P4.31-11（下载器与传输无关）**：`fetch.py` 不依赖 Web，CLI `import <url>` 以后直接复用。
- **决策P4.31-12（本期一个网址、一个活动下载）**：保留后台下载、进度轮询和停止；多网址队列与并发下载以后补。
- **决策P4.31-13（HTML 提供「保留整页」重试）**：长度检查保证不了正文完整；HTML 文件行的「整页一键入库」与
  下载弹窗的「保留整页」透传 `html_extract=off`，不新增预览或比对系统。

## 10. 测试要点

- **下载器（`tests/test_fetch.py`，`httpx.MockTransport` + 假解析器，零网络）**：
  - 网段：回环、私网、链路本地、云元数据、IPv4 映射 IPv6、`0.0.0.0` 各拒；`GUANLAN_FETCH_ALLOW_CIDRS` 放行；
  - **跳转到内网被拒**（第一跳公网、第二跳 `127.0.0.1`）——漏报类用例，只测正例测不出；
  - 固定解析：两次解析结果不同时只用第一次的地址；
  - 默认不读代理环境变量（设了 `HTTPS_PROXY` 仍直连）；设 `GUANLAN_FETCH_PROXY` 时走代理、只拒字面量禁止 IP 与 `localhost`；
  - 带用户名密码的网址、非 http(s) 协议、超长网址拒；
  - 超过 256 MiB 立即断开且不留临时文件；读空闲超时；跳转超过 5 次；停止后临时文件删除；
  - 类型判定：PDF / docx / pptx / xlsx / HTML / 各图片魔数 / Markdown；**`.pdf` 网址返回登录页 → 拒**；
    zip 但不是 Office（含 EPUB）→ 提示先下载再上传；CSV、RTF、OLE 老格式 → 同上；
  - 建议文件名：`filename*` UTF-8、百分号解码、无路径时用主机名、`.htm` 改 `.html`、UTF-8 字节限长
    （长中文名用例在 Linux CI 上跑）。
- **提交与端点（`tests/test_web_fetch.py`）**：
  - **两次下载同名并发提交不互相覆盖**：各得各的文件（第二个加序号），内容不串；
  - **上传先、下载后**：下载加序号，上传的文件不变；
  - **下载先、上传后**：上传按既有规则覆盖，旧出处记录失效（一键入库时 `origin` 回到 `workspace/uploads/…`）——
    上传语义不变，不为下载改它；
  - 事件循环外已存在的同名文件（直接写盘模拟）不被下载覆盖；
  - 下载期间开始可写会话 → 提交时 423、临时文件删除；
  - 已有下载在进行 → 409；页面刷新后 `GET /api/upload/url` 找回进行中的下载；reader 不注册；
  - 出处记录：哈希不符时作废并删除；删暂存文件连带删记录；
  - `oneclick=true` 成功后发起准备作业；已有任务时记原因、文件保留、不报错。
- **skill（`tests/test_skill_convert_html.py`，CI 装 pandoc 真跑；trafilatura 有 / 无两种）**：
  - GBK 页面（`<meta charset=gbk>`、仅 `--html-charset`、无声明三种）转出正确中文；
  - 导航 / 页脚被去掉、正文与标题层级保留；**正文很短的页面不被提取掉**（退回整页）——漏报类用例；
  - `--html-extract off` 时导航、页脚都在（整页）；
  - 无 `<h1>` 时用 `<title>` 补标题；
  - 合并单元格表格保留为 HTML 表格；`<div>` / `<span>` 不漏进 Markdown；
  - 远程图片转成 `[图：…](…)`，相对地址按基址补全；没有基址时相对图片原样保留；
  - **回退后端同样不留远程 `<img>`**：强制 `--backend mineru` / `marker`（假后端回显输入即可）时，送进后端的 HTML
    已不含远程 `<img>` 与 `srcset`——漏报类用例，只测 pandoc 测不出；
  - 链接里的图片只换成文字、不产生嵌套链接；没装 trafilatura 时图片改写照样执行；
  - 未装 trafilatura 时降级、日志有 `extract=none`；`parsed_by` 各取值读回正确。
- **一键入库（`tests/test_oneclick.py`、`tests/test_web_oneclick.py` 增补）**：有出处记录时 `origin` / `origin_url` /
  `fetched` 进每一份分卷；无记录或哈希不符时与现状一致；`html_extract=off` 透传到转换并记进任务清单。
- **前端**：真浏览器冒烟（Playwright，同 P4.20 的 `scripts/smoke_p420.py` 做法）：弹窗、进度、停止、
  「直接一键入库」切到解析进度浮层、HTML 行的「整页一键入库」。
