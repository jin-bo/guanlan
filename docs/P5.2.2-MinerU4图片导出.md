# P5.2.2 — MinerU 4 产物的图片导出（草案）

> **状态**：已实现（2026-11-21）。导图在 `skills/pdf-to-markdown/scripts/convert.py`（`export_doc_images`，
> 由 `_run_backends` 在错乱文字层检测通过后调用）；残留引用的计数与提示在 `guanlan/imageio.py`、`guanlan/convert.py`。
> §5 四项决策均按倾向裁定（附补充要求）。`--remote` 仍待实测。
>
> **定位**：P5.2.1「图片落盘」的补丁。P5.2.1 按 MinerU 3.x 的产物布局实测、设计了引擎无关的图片收集；
> MinerU 4.x 改了图片引用的写法，这套收集对它**全部落空**，而且是静默的。本提案只补 MinerU 4 这一种写法，
> 不改 P5.2.1 的收集、安全闸、容量上限与落盘顺序。
>
> **不推翻既有决策**。零 LLM。导图修在 `skills/pdf-to-markdown/scripts/convert.py`，guanlan 的收集逻辑不写
> MinerU 分支（沿决策P5.2.1-3「引擎无关收集」）；guanlan 侧只改统计与提示：导图失败残留的 `doc:` 引用
> 单独计数、单独提示（§5-4），涉及 `imageio.ConvertResult` 与 `convert` 的打印处。

---

## 0. 动机与实测

### 0.1 现象

MinerU 4.x（`mineru parse` 经本地文档库服务）产出的 markdown 里，插图、图表不再是相对路径，而是文档库定位符：

```markdown
![Image block](doc:060dfdd/tier:standard/page:8/block:3)
![Chart block](doc:bd759c4/tier:standard/page:14/block:5)
```

图片本身**不写到产物目录**，只存在 MinerU 的文档库里。P5.2.1 的安全闸（`imageio._admit_image_ref`）把 `doc:`
当作带 scheme 的外链：原样保留、计入 `skipped`、不报错（决策P5.2.1-5(a)）。结果：

- `raw/<slug>.md` 里的这些引用全部悬空，渲染时是坏图；
- 流程图、色谱图、表单等**图中文字**不进 markdown，也就进不了检索和 ingest；
- 命令只提示「另有 N 处图片引用未准入、原样保留」，读起来像正常的远程图，用户察觉不到。

`guanlan convert` 与 `guanlan import`（CLI 和 Web）都经 `convert.convert_to_markdown` 调 skill `convert.py`，
三个入口同样受影响。

### 0.2 实测

一个本地资料库（403 份文档：PDF 333、doc/docx 67、xls/xlsx 3），全部经 MinerU 4.2.3 本地 `standard` 档
（doc/xls 由 MinerU 自动用 `flash`）转换：

| 项目 | 结果 |
|---|---|
| 含 `doc:` 引用的产物 | 117 份（PDF 110、doc 6、docx 1），共 659 处 |
| 块类型 | `Image block` 504、`Chart block` 155 |
| 产物目录里的本地图片 | 0 张（MinerU 4 不落图） |
| 用 `mineru read <定位符> -f image -o <路径>` 导出 | 659/659 成功，PNG；单张约 0.36 s |
| 导出图片体积 | 合计 93 MB；单份最多 85 张、12 MB；单张最大 1.2 MB |

P5.2.1 的容量上限（单次 500 张、单图 20 MiB、累计 200 MiB）对这批数据全部够用。

### 0.3 导出的前提

`mineru read` 要求**文档库里登记的源文件还在原路径**，否则报 `no_accessible_file`。实测：批量转换时用的临时副本
删掉后，导出全部失败；把原文件重新 `mineru scan` 登记（文档按内容哈希识别，定位符不变）后才能导出。

`guanlan` 的转换内核把源文件复制进临时目录再调 skill（决策P5.2-10），临时目录在读完产物后才销毁。
所以**在 skill `convert.py` 运行期间导出**，源文件一定还在；等回到 `guanlan` 再导出就晚了。

## 1. 方案

### 1.0 时机：先过错乱文字层检测，再在 skill 内导图

P4.30.1 §3 在 `_run_backends` 里检测错乱文字层：判为错乱就删产物、换下一个后端。导图放在这项检测**通过之后**、
`_run_backends` 交出产物路径之前：

- 被拒的产物一张图都不导，不存在「回退时删除整个 `images/` 目录」的问题；
- 此时仍在 skill 进程内，guanlan 的临时源文件还在（§0.3），`mineru read` 能取到图。

`run_mineru_v4` 解析成功后，把本次解析的文档身份（`parse.sha256`、`parse.tier`）按产物路径记下，供导图时核对。

### 1.1 导图步骤（`export_doc_images`）

1. 扫描产物里的 `![…](doc:<id>/tier:<tier>/page:<n>/block:<m>)`；没有就跳过，行为与以前完全相同。
2. **按完整定位符去重**：同一定位符多次引用只导一次；按 markdown 中**首次出现的顺序**处理。
3. **核对归属**：定位符的 `<id>` 必须是本次解析 `sha256` 的前缀，`<tier>` 必须与本次解析档位一致；
   没有本次解析的身份记录时一张都不导。MinerU 文档库里还登记着别的文件，不核对就可能把它们的图带进来。
4. 每个定位符调一次 `mineru read <定位符> -f image -o <产物目录>/images/<文件名> --json`，**单次超时 60 秒**。
   导出前先删掉目标路径上的旧文件，导出后确认**本次写出了有效 PNG**（文件存在且以 PNG 文件头开头），
   才算成功；非零退出、没写出文件或不是 PNG，算这一张失败、删掉半成品，**继续下一张**。
   **第一次超时就停止本次导图**：MinerU 服务多半卡住了，再逐张等 60 秒只会把转换拖成几十分钟；
   已导出的照常改写，超时的这张和其余引用保留 `doc:`，汇总里说明停止原因。
5. **限量**（沿用 P5.2.1 的三道上限：500 张、单图 20 MiB、累计 200 MiB）：产物里已有、可被收集的本地图
   （相对引用、按 guanlan 同样的口径先解 %-转义、文件存在，按真实路径去重）先占用预算；导出后按顺序计入。
   - 张数到顶或累计超限：这一张删掉，它和其余引用都保留 `doc:`，不再导出；
   - 单图超限：只删掉这一张、保留它的 `doc:`，继续下一张。

   skill 不能引用 guanlan，三道上限各写一份，测试校验两边一致。guanlan `imageio` 的硬上限照旧：
   skill 限量后，正常情况下不会再触发它整份拒收。
6. 文件名 `p<页>-b<块>.png`；不同定位符映射到同一页码、块号时（例如短 id 长度不同），第二个起加
   `-2`、`-3` 后缀，避免串图。
7. 成功的引用改写为相对路径 `images/<文件名>`，alt 文本不动；没导出的**原样保留**。改写只动图片 URL：
   读写都用 `newline=""` 与 `errors="surrogateescape"`，CRLF 换行和非法 UTF-8 字节原样保留。
   先写同目录临时文件、沿用原文件权限，再 `os.replace` 换上；写盘失败时原产物不变、临时文件删除。
8. 进度与汇总写 stderr（开头一行 `[mineru] exporting N image block(s)`，失败的逐条说明原因，末尾
   `[mineru] exported k of N image block(s); M kept as doc: links (…)`，括号里按原因分项：不属于本文档、
   导出失败、超限、超时后未导；提前停止时再加 `stopped early (…)`）。CLI 和 Web 一键入库已有的进度日志通道
   会流式显示这些行。
9. 导图出任何异常都只记日志，**转换仍算成功**，正文照常交出；一张都没导出时不留空的 `images/` 目录。

之后的路径不变：`guanlan` 的 `collect_and_rewrite` 按「相对产物 md 父目录」收集这些 PNG，
编号重命名为 `images/<slug>/<slug>-<n>.png`，按 P5.2.1 的落盘顺序写入 `raw/images/<slug>/`。
单独使用 skill（不经 guanlan）时，图片留在产物旁的 `images/` 目录，md 直接可看。

### 1.2 为什么修在 skill 而不是 `guanlan/imageio.py`

- **只有 skill 运行时源文件还在**（§0.3）。在 `imageio` 里认 `doc:` 再回调 MinerU，就得让 guanlan 延迟销毁
  临时目录、又多一处 MinerU 专属逻辑，违背决策P5.2.1-3。
- 定位符是 MinerU 的内部格式，把它翻译成普通相对路径，正是 skill「把各后端产物统一成 markdown」的本职。
- skill 单独使用（Agent 调它解析到 `workspace/parsed/`）也一并修好。

## 2. 边界

- **只认 MinerU 4 的 `doc:` 定位符**。其它带 scheme 的引用（`http(s):`、`data:`…）仍按 P5.2.1 原样保留。
- **`--remote`（mineru.net 托管解析）**：定位符是否同样可 `read`、能否离线导出，**未实测**。按同一流程尝试，
  失败的保留原引用并汇总告警；实测后再补本节。
- **Office 文档**：实测 6 份 `.doc` 也产出了定位符（`flash` 档），流程相同。`.docx` 默认走 pandoc，
  只有 pandoc 不可用、回退到 MinerU 时才会遇到。
- **耗时**：每块一次子进程调用，约 0.36 s；本批最大的一份（85 块）约 30 s。串行执行，不做并发
  （文档库服务本身是单实例，并发收益未知）。单次 60 秒超时，**首次超时即停止本次导图**（§1.1 第 4 步），
  所以服务挂死时最多多等 60 秒；正常情况下不限总时长。
- **图中文字**：只导出图片，不做 OCR 把图中文字写进 markdown。图片落盘后，人和多模态模型都能看到；
  要不要把图中文字也抽出来，另议（§4）。

---

## 3. 已入库的断链

已经落进 `raw/` 的 `doc:` 引用不自动修复：临时源文件早已删除，必须重新转换。受影响的源可以这样找：

```bash
grep -rl '](doc:' raw/
```

对每份用 `guanlan convert <原文件> --overwrite`（或重新一键入库）覆盖重转即可。本期不在 `check` / `health`
里加检查项（决策 §5-3）。

---

## 4. 不做

- **不改 `imageio` 的安全闸与上限**（skill 侧另按同样的数值限量，§1.1 第 5 步）。`doc:` 在 guanlan 侧仍不准入、原样保留；只是不再混进「未准入」计数，
  而是单独计数、单独提示（§5-4）。修好后它只会在导出失败时出现。
- **不把 alt 文本换成图题**。MinerU 写的是 `Image block` / `Chart block`，图题通常在下一段（「图 2 …」）；
  调整 alt 属于整理规则，不在本提案。
- **不 OCR 图中文字**。流程图、表单里的字对检索有价值，但需要额外的识别步骤和误识风险评估，单独提案。
- **不清理 MinerU 文档库里的登记记录**。转换时临时副本的登记本来就会留下，与本提案无关。

---

## 5. 决策（2026-11-21 裁定，均按倾向）

1. **导出失败**：保留失败的 `doc:` 引用，stderr 汇总告警，转换仍算成功；不为几张图换到 marker
   （它会落图，但慢一个数量级：实测一份 19 页扫描件约 8.5 分钟）。补充：单次 `mineru read` 设超时，
   确认本次生成了有效 PNG 后才改写引用；进度沿用 CLI 与 Web 一键入库已有的日志通道（§1.1）。
   审查后再补（2026-11-21）：
   - **skill 侧限量**：导出的图会计入 P5.2.1 的上限，图多的文档原本会被 guanlan 整份拒收（以前 `doc:` 被跳过、
     不计数，反而能转）。现在 skill 按同样的三道上限限量，超限的保留 `doc:`，正文照常转换（§1.1 第 5 步）。
   - **首次超时即停**，普通单图失败仍继续（§1.1 第 4 步）。
   - **改写只动图片 URL**，保留 CRLF 与非法 UTF-8（§1.1 第 7 步）。
   - `mineru parse` 返回的 `error` 不是对象（如字符串）时，在 `attempt()` 里统一转成诊断消息，后端回退照常生效。

2. **文件名**：`p<页>-b<块>.png`，便于对回原 PDF 的页面（经 guanlan 时仍会重命名为 `<slug>-<n>.png`）。
   补充：按完整定位符去重；不同定位符映射到同一页码、块号时加后缀，避免串图（§1.1 第 5 步）。

3. **存量检查**：本期 `check` / `health` 不新增检查项，存量按 §3 查找并覆盖重转。理由：成功导出后会消除
   `doc:` 引用，导出失败时仍可能残留，但转换当时已单独提示（§5-4）；新增检查项有长期维护成本。

4. **提示文案**：`guanlan convert` 正常执行和 `--dry-run`，以及一键入库（解析完成后的任务日志）都单独报告
   「有 N 处 MinerU 图片引用未能导出（doc:），可用原文件重新转换。」N 按 markdown 中残留的**引用次数**计
   （`ConvertResult.doc_refs`）；通用的「另有 N 处图片引用未准入、原样保留」扣除这部分，避免重复报数。
   直接导入 `.md` 时没有「原文件」可重转，一键入库（CLI 与 Web 共用的任务日志）改用
   「有 N 处 MinerU 图片引用（doc:）无法显示。如有生成此 Markdown 的源文档，请重新转换源文档后再导入。」

## 6. 测试要点

skill 侧（`tests/test_skill_convert_doc_images.py`，假 `mineru read`，不依赖真实 MinerU）：

- 2 个不同定位符、其中一个引用两次 → `mineru read` 只调 2 次；引用改写为 `images/p<n>-b<m>.png`，alt 不变，图片存在。
- 一个导出失败 → 该引用原样保留、其余照常改写；stderr 有 `kept as doc: links` 汇总。
- 超时、写出的不是 PNG → 算失败，不留半成品、不留空目录；目标路径上的旧图不能当成本次成功。
- **首次超时后没有任何后续 `mineru read` 调用**，已导出的照常改写；普通单图失败不停。
- 限量：张数到顶后不再调用；产物已有的本地图占预算；单图超限只跳过它自己；累计超限后停止；
  三道上限与 `guanlan/imageio.py` 一致；**超限后正文仍照常交出**。
- 含 CRLF 与非法 UTF-8 的产物改写后，与原字节相比只有图片 URL 不同；文件权限不变；
  写盘失败时原产物逐字节不变、不留临时文件。
- 已有本地图的 %-转义引用（`images/a%20b.png`）按解码后的文件计入预算。
- 提前停止后，不属于本文档的块仍按「不属于本文档」汇总。
- `mineru parse` 返回字符串 `error` → mineru 档失败、诊断消息进日志、回退到下一个后端。
- 定位符属于别的文档、别的档位，或没有本次解析的身份记录 → 不调 `mineru read`，引用原样保留。
- 不同定位符同页同块 → 第二张加 `-2` 后缀。
- 产物不含定位符 → 不调 `mineru read`，产物字节不变；`https:`、`data:`、本地相对引用不被触碰。
- 接入 `_run_backends`：错乱产物不导图、换下一个后端；通过检测的 MinerU 产物先导图再交出路径；
  导图抛错不影响转换成功。
- `run_mineru_v4` 记下本次解析的 `sha256` / `tier`。

guanlan 侧（`tests/test_convert.py`）：

- 残留 `doc:` 引用按次数计入 `doc_refs`，不计入 `skipped`，引用原样保留。
- `convert` 正常执行与 `--dry-run` 都打印 §5-4 的提示，通用提示只报扣除后的数；没有残留时不打印。
- 一键入库（`tests/test_oneclick.py`）：任务日志（CLI 与 Web 共用）在有残留时写出同一提示，没有时不写；
  直接导入 `.md` 时写「请重新转换源文档后再导入」那一句。

真机验收（2026-11-21，本地 MinerU 4.2.3 `standard` 档）：一份 30 页、含 10 张流程图的公开文件，
`guanlan convert` 后 `raw/images/<slug>/` 下 10 张 PNG，md 中无 `doc:`；`--dry-run` 报「含 10 张图片」。
`--remote` 未验收。
