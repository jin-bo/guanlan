# P5.5 — CLI 问答画像（`guanlan query --profile`）

> **状态**：已实现（2026-11-23），经两轮评审（见 §6）。
> **来源**：[USER.md 试验设计草案](backlog/notes/USER.md试验-设计草案.md) §4.6（首轮结果）与 §5（第二期范围）；[用户画像 · 同类项目调研](backlog/notes/用户画像-同类项目调研.md)。
> **目标**：用户在只读 `guanlan query` 里显式附上一份自己写的短画像，回答按提问者的角色调整切入角度、详略和术语。证据仍只来自知识库。
> **不做**：默认画像路径、环境变量；`--backfill`、MCP `query`、Web、IM 的画像；自动提取或更新画像；改动 Agentao 用户级记忆通道。

## 1. 依据与边界

**试验结果**（第一期首轮，详见试验草案 §4.6）：

- 同一批题分无画像、角色甲画像、角色乙画像三组。两位评分人盲猜答卷属于哪一组，分别猜对 26/30 和 30/30。
- 三组的引用可定位率都在 99% 以上。

**没有验证的**：引用是否支持结论、反证条件是否处理、补问是否减少。用户 2026-11-23 决定不再重复试验，直接进入设计。所以本阶段能说的只是「画像能稳定改变回答的取向」，不能说「回答更好」。下面的设计因此保守：只开 CLI 只读一个入口，不给参数时行为逐字不变。

**设计时补做的零 LLM 复核**：试验把画像直接拼在问题后面，宿主召回（`build_query_prompt` 里的 `search_pages`）用的也是「问题 + 画像」。对同一批 10 题重算召回，与只用题干相比：

| | 前 8 个候选与只用题干时的重合 |
|---|---|
| 角色甲画像 | 每题 0–2 个 |
| 角色乙画像 | 每题 2–7 个 |

只用角色甲画像本身检索，得到的候选与「题干 + 画像」几乎相同：候选整体漂移到了画像的主题上。画像约 340 字，题干约 130 字，画像在 BM25 查询里占了大头；上限 1,500 字时会更明显。

所以试验观察到的角色差异，**有一部分来自读了不同的页，不只是写法不同**。这一点决定了 D2。

## 2. 决策

### D1 入口：只有 `guanlan query` 只读分支

- 参数：`--profile <路径>`，指向一个普通 markdown 文件。
- 不给参数：提示词与现状逐字相同（有测试锁定）。
- 不提供默认路径或环境变量：画像会改变回答，每次显式给出，用户才知道这一次带了什么。以后需要默认路径再议，候选是 `~/.guanlan/USER.md`。

### D2 宿主召回只用问题，与试验不同

宿主召回只拿原问题检索，画像不参与。**承诺**：同一个问题带不带画像，宿主 BM25 给出的候选页和顺序完全一致。

- **理由**：
  - 画像不是证据，不应决定宿主推荐读哪些页。
  - 画像比问题长时，它会主导 BM25，把候选拉离问题（§1 复核）。
  - 宿主这一侧的证据入口与不带画像时一致，出了问题容易归因。
- **不承诺的**：模型看到画像后仍可用 `search_file_content` 补查，最终读了哪些页、引用了哪些页可能变化。D3 的用途说明用来约束这一点。
- **代价**：上线行为与试验不同。试验混入了画像召回，保留试验措辞也复现不了原条件；试验里由召回漂移带来的那部分角色差异会消失，角色区分度可能比试验低。
- **核对办法**（不是新试验）：fake runner 测试锁定候选一致；实问两三题冒烟，确认回答仍带引用、能看出角色取向。

### D3 注入位置：系统提示，与参考项目一致

画像进**系统提示**，不放在本次问题后面。参考项目都是这样做的：

| 项目 | 注入位置 |
|---|---|
| Hermes | 会话开始时读取 `USER.md`，生成系统提示里的 `USER PROFILE` 小节，作为会话快照 |
| OpenClaw | 放在系统提示的 `Project Context` 段 |
| gbrain | 工作区 `CLAUDE.md` 用 `@USER.md` 导入，会话启动时载入 |
| AnythingLLM | 开启个性化后，把记忆追加到工作区系统提示末尾 |

首轮试验把画像拼在问题后面，是零代码对照的权宜做法，参考项目里没有同样的放法。

**通道**：`agentao run` 的 run spec 有 `instructions` 字段（0.5.22 已有，不需要改 Agentao）。非空时作为 `project_instructions` 传给 Agentao，渲染在系统提示最前面的 `=== Project Instructions ===` 段。但它会**顶替** `AGENTAO.md` 的磁盘读取，所以宿主要自己拼完整内容：

```
<库根 AGENTAO.md 的内容（用 Agentao 自己的 load_project_instructions 读，去 frontmatter；
  没有 AGENTAO.md 时按它的规则读 AGENTS.md；都没有则为空）>

## 提问者画像

画像仅用于调整切入角度、详略和术语；事实判断和引用以库内资料为准；如与项目规约或引用要求冲突，以项目规约和引用要求为准。

<画像全文>
```

- **标题挂到画像段之下**：画像段自己的标题是第 2 级。注入前把画像里最浅的 ATX 标题调到第 3 级，其余标题保持相对层次，最深到第 6 级为止。例如 `# 姓名：示例用户` → `### 姓名：示例用户`，同时 `## 回答方式` → `#### 回答方式`。最浅标题比第 3 级还深时上提到第 3 级。围栏代码块里的 `#` 不动；没有标题时原样注入；下划线式（Setext）标题不处理。1,500 字上限按用户文件原文计，不含调整时加的 `#`。
- **用户消息不变**：带不带画像，发给模型的用户消息（问题 + 宿主候选）逐字相同。D2 的候选一致因此自然成立，测试也好写。
- **项目指令原样保留**：用 Agentao 导出的 `agentao.prompts.load_project_instructions` 读取，与它自己读盘的结果逐字一致，避免宿主另写一套读法后出现偏差。测试锁定：不带画像时不传 `instructions`；带画像时 `instructions` 的前缀等于它的返回值。
- **权威度**：画像落在「Project Instructions」段，Agentao 的不可信输入规则会把这一段当指令遵守。画像是用户本人写的、经用户显式指定，可以接受；用途句把它限定在写法上，并写明与项目规约或引用要求冲突时以后者为准，不另做画像解析或过滤。画像不是资料，不应按不可信输入处理。
- **与以后的 Web 一致**：嵌入式会话在构造时传 `project_instructions`，走的是同一个通道（试验草案 §6.3 的倾向）。CLI 先用 run spec，Web 接入时不必另起机制。
- **实现**：`run_agent_task` 与 `AgentRunner` 加可选参数 `instructions`；`run_spec_text` 把它和 `prompt` 一起编进 spec，转义规则相同。spec 不声明 `parameters`，Agentao 不对 `instructions` 做模板渲染，`{{ }}` 原样保留。

### D4 校验：全部在调用模型之前

| 情况 | 处理 |
|---|---|
| 与 `--backfill` 同时给 | **`argparse` 互斥组**在参数解析时拒绝（退出码 2，与其它用法错误相同）。`--backfill` 会先取写锁再调 `run_query`，只在 `run_query` 里查的话，锁被占用时用户先看到的是锁冲突。回填进 `syntheses/`，画像不应影响共享内容。`run_query` 对直接调用者再兜一次底 |
| 文件不存在、不是普通文件、不可读、不是 UTF-8 | `EXIT_USAGE` 退出 |
| 解析符号链接后落在知识库目录内 | `EXIT_USAGE` 退出：只读 query 的 Agent 能读库内文件，画像会被当成资料读到，库内文件也可能被 `zip` 打包 |
| 去掉首尾空白后为空 | `EXIT_USAGE` 退出：给了参数却什么都没附，多半是路径写错 |
| 超过 1,500 字（去掉首尾空白后按字符计） | `EXIT_USAGE` 退出，不截断：截断会悄悄丢掉用户写的后半段 |

上限 1,500 字参照 Hermes `USER.md` 的 1,375 字符，按中文略放宽，与试验草案 §3 相同。

### D5 输出

- 不打加载成功提示；stdout 只有答案，与现在一样。
- 不写 `log.md`：只读 query 本来就不写库。

### D6 隐私与留痕

- 画像随请求发给配置的模型提供方，与问题本身一样。
- **本地明文留痕**：Agentao 的请求日志是正常的功能日志。首次模型请求记录完整系统提示，后续只记变化。日志写在库根 `agentao.log`；库根写不进去时，Agentao 改写 `~/.agentao/agentao.log`。所以画像文件本身在库外，内容会以明文出现在这份日志里；问题文本也一样。
  - `zip` 按白名单打包，不含日志；但直接复制整个库目录时，库根日志会一起带走。
  - 首稿说「试验后在 `agentao.log` 里未发现画像文字」，那是日志已经轮转，结论不成立，已更正。
  - 不改 Agentao，也不提上游需求。`--profile` 的帮助和文档写明：画像会发给模型提供方，并以明文记入库根 `agentao.log`（写不进时记入 `~/.agentao/agentao.log`）。
- 画像文件由用户维护，观澜不复制、不缓存、不改写。

## 4. 测试

用现有 fake runner，不打真实模型：

- **不给参数**：提示词与现状逐字相同。
- **给参数**：
  - 用户消息与不给参数时逐字相同，宿主候选及顺序因此一致；画像里放一个只命中某页的词，断言该页不出现。
  - 画像标题调级：最浅标题落到第 3 级、相对层次不变、封顶第 6 级、代码块内不动、无标题原样。
  - `instructions` = 项目指令（等于 `load_project_instructions` 的返回值）+ 画像段，分三种情况各一条：
    - 有 `AGENTAO.md`：前缀是它的内容（去 frontmatter）。
    - 没有 `AGENTAO.md`、有 `AGENTS.md`：前缀是 `AGENTS.md` 的内容，不能因为带了画像就丢掉库级规约。
    - 两者都没有：只有画像段。
  - 不给参数时不传 `instructions`。
  - `run_spec_text` 带 `instructions` 时可被 `yaml.safe_load` 原样读回（含 emoji、`{{ }}`、控制符）。
  - stdout 只有答案。
- **报错**：
  - `--profile` 与 `--backfill` 同用：参数解析即失败，不取锁、不调 runner。
  - D4 其余每种情况一条，断言 `EXIT_USAGE` 且没有调用 runner。符号链接用例不许 skip（CI 见 skip 即红）。
- **用例数据**：画像与页面一律用中性占位内容。
- **冒烟**：实问两三题。

## 5. 已定事项

1. D2：宿主召回只用问题，候选与顺序完全一致。
2. D3：画像进系统提示（run spec `instructions` → Project Instructions 段），附一句用途，并写明与项目规约冲突时以项目规约为准。
3. D1：不给默认路径，每次显式给出。
4. D5：不打成功提示。
