## 0. 动机

真实库（如 `kbs/xuexi`）入一本书的实际做法是：外部转换 → 手工去页眉页脚 → 手工按章拆成
数十个 ≤ 约 5 万字的分卷 → 写批处理脚本串行 `guanlan ingest`。现有暂存区只做到第一步，
后面全靠人和脚本。问题有三：

1. **拆分口径不统一**：xuexi 的 531 个分卷，中位数约 4.9 万字符、最大的 102 万字符没拆，
   拆分规则没有落在任何代码或文档里。
2. **跨页断句、页眉页码污染原文**：mineru 按页输出，一句话被页码和页眉切成两段；这些噪声
   进了 `raw/`，ingest 时被当成正文引用，`guanlan quotes` 也会因此报引语不一致。
3. **批量入库没有宿主支持**：几十篇串行、每篇约 10 分钟，中途断了只能靠人看日志判断从哪篇续。

## 2. 一键入库流程

输入：`workspace/uploads/<file>`（pdf / docx / 图片等 `convert` 支持的格式，或已是 `.md`）。
下文 `<sample>` = `raw_slug(<file> 的 stem)`。

```
uploads/<file>
  │ ① 解析（convert_to_markdown，确定性宿主，shell out 转换器）
  ▼
parsed/<sample>.origin.md  + parsed/images/<sample>/…        ← 解析原样，留档不改
  │ ② 规范化整理（零 LLM，§3）
  ▼
parsed/<sample>.md                                            ← frontmatter + 去噪 + 跨页接句
  │ ③ 拆分（零 LLM，§4）            ④ 目录索引（拆分时生成，不拆不生成，§4.4）
  ▼
parsed/<sample>/<sample>-01-<章名>.md …   parsed/<sample>/<sample>-目录.md（只留 parsed/）
  │
  ├─ ✋ 确认开始：展示份数与预计耗时，用户确认后自动继续（§2.1）
  │
  │ ⑤ 落 raw/（连图，复用晋级原语，§5）
  ▼
raw/<sample>.md                       （未拆分）
raw/<sample>/<sample>-01-<章名>.md …  （已拆分；不再落 <sample>.md 整本，免重复内容）
  │ ⑥ 依次入库（run_ingest 串行，§6）
  ▼
wiki/
```

①–⑤ 是确定性、零 LLM 的宿主步骤，秒到分钟级；⑥ 每篇走 Agentao + P2 写门禁，
单篇约数分钟到十余分钟。**确认之前、以及 ⑤ 之前任何一步失败，`raw/` 都不被触碰**。

### 2.1 确认（决策P4.30-8）

①–④ 跑完后任务停在 `awaiting_confirm`，展示：

- 默认只展示文件名、分份数与预计耗时，提供「开始入库」「放弃」；用户无需理解处理过程。
- 整理摘要、拆分方式、逐份文件名/标题路径/页码区间/字数与落点放在可展开详情里，只供查看。
- 冲突预检（§5）在 ①–④ 阶段完成，结果直接进确认页。可覆盖的冲突单独提示风险，需勾选「覆盖」才能继续；
  不允许覆盖的冲突（§5 首版限制）只给「放弃」；正常无冲突流程没有额外选项。
- 预计耗时：份数 × 单篇平均入库时长（取本库最近若干次入库的实测均值，没有记录时按 10 分钟估）。

用户可以：**确认**（执行 ⑤⑥）、**放弃**（任务记为 `cancelled`，`parsed/` 产物保留，可删可看），
或先在「已解析」里用只读预览查看整理/拆分后的文本再决定。确认不算对原文逐字人审（决策P4.30-1 不变），
它只确认开始执行与时间成本；拆分方案和写入位置由系统决定，详情可查。水印候选不提供勾选、
逐项确认、阈值设置或人工复核入口，Web 与 CLI 使用同一套自动规则。

确认前的产物只在 `parsed/`，放置不管不占用任何写锁；任务清单里保存 ①–④ 产物的哈希，
确认时复检，**产物被改过就拒绝确认**，要求重新跑 ①–④（防止确认的和实际写入的不是同一份）。

## 3. 规范化整理（`<sample>.origin.md` → `<sample>.md`）

**全部确定性、零 LLM**（决策P4.30-3）。整理器对每处改动记一条操作日志，进入作业输出，
供事后核对「删了什么、挪了什么」。`origin.md` 永远保留原样。

**顺序固定**：分页（§3.2）→ 识别并删除噪声（§3.3）→ 跨页接句（§3.4）→ 统计正文、写入元数据（§3.1）
→ 拆分（§4）。接句必须在去噪之后，否则页码、页眉会挡在被切开的两半句子之间。

### 3.1 frontmatter

```yaml
---
title: 企业食品安全管理人员基础读本·食品生产篇
origin: uploads/企业食品安全管理人员基础读本.pdf   # 沿 P5.2 provenance
parsed_by: mineru                                   # 沿决策P5.2-13
source_sha256: 3f2a…                                # 原件内容哈希
pages: 539                                          # 有分页锚点时
chars: 412876                                       # 正文字数，口径见 §4.1
normalized:                                         # 整理摘要
  headers_removed: 512
  page_numbers_removed: 531
  watermarks_removed: 0
  sentences_joined: 87
---
```

`title` 取文档首个一级标题；没有则取文件名。拆分信息另见 §4.3。

### 3.2 页面切分依据

以转换器的分页锚点 `<!-- page N of M -->` / `<!-- page N -->` 把正文切成页。
**没有分页锚点**（docx、已是 md 的输入）→ 跳过 §3.3–3.4，只写 frontmatter。

### 3.3 自动删除页眉、页脚、页码、水印

- **页码**：页面首尾数个非空行内，整行只有页码形态（`15`、`- 15 -`、`第 15 页`、`15/539`、
  罗马数字）的行。**还须有跨页证据**：印刷页码与锚点页号的差（偏移）至少在 3 页上一致；前置页、跳页
  让偏移分段变化时按段各自计。凑不出同一偏移的孤立数字（页尾一行 `42`、列表项 `- 12`）保留。
  （实现说明：首版只看形态与「≤ 最大页号 + 20」，评审指出页尾孤立数字会被静默删除，补了这道证据。
  这只用于判断整行页码，不改变「同行页码只剥与锚点直接相等者、不做偏移推断」的规则。）
- **页眉/页脚**：页面首尾数个非空行内，在至少 3 页且 **≥ 30% 的页面**重复出现、长度 ≤ 60 字，
  并稳定处于页首或页尾的独立文本行。比对只去首尾空白、合并连续空白，保留数字与标点，
  避免把不同条款合并成同一模式。奇偶页分别统计；列表、表格、代码和引用块不参与删除。
  另有三条补充，都只作用于页首尾窗口里的命中行：
  - **标题形式的页眉**：转换器常把页眉输出成标题行（如每页顶部的 `## 书名`）。标题行**可以**按页眉删除，
    但须同时满足：页边位置稳定、文本重复、页数达到上面的门槛。只删这些位置上的命中，正文中的同名真实
    标题保留。**不笼统排除所有重复标题**（「练习」「小结」可以是合法章节标题）。
  - **页码与页眉同行**（如 `15　企业食品安全管理人员基础读本`）：比对前只尝试剥离**行首或行尾、带分隔的**
    页码字段，且该数字须与本页分页锚点的页号**直接相等**；不删除行内其它位置的相同数字。
    分页锚点是 PDF 物理页序，可能与印刷页码有偏移：首版只处理能直接匹配的情况，**不做页码偏移推断**。
  - **章节页眉**（奇数页印当前章名，全书占比达不到 30%）：增加局部连续规则——同一行在**同一奇偶序列**、
    页首窗口内**连续至少 3 次**出现，即视为页眉。满足后只删除命中的边缘行。
    实现收窄（真实样本校准）：只认**页首**的**普通文本行**。标题形式的页眉须达到上面的全书/奇偶页门槛，
    否则连续几页各自小节开头的同名小标题（如「（一）适用范围」）会被误删；页尾的表单行（如「年 月 日」）
    同理不走这条规则。
  - **首个同名标题保留**：标题形式的页眉命中时，文档中**第一次**出现的同文标题保留——它通常就是真实的
    书名/章名标题；只删后面重复印在页边的那些。
- **水印**：按下述规则自动判断，重复率只用于发现候选，不单独作为删除依据。
- 阈值与窗口都是内置常量，集中定义、带测试，不暴露给用户。**证据不足就自动保留**，
  仅在详细日志记为「疑似」，不暂停、不要求用户判断。

#### 3.3.1 水印判断（自动执行）

1. **找候选**：按页统计长度 ≤ 60 个非空白字符的独立短行，同一文本在至少 3 页且 ≥ 30% 页面出现。
   比对只去首尾空白、合并连续空白，不去数字、标点，不做模糊匹配。正文中的相同短语不算整行命中。
2. **排除正文结构**：标题、列表、表格、围栏代码、引用块及其内容不参与删除；只处理独立普通文本块。
   页首尾已判为页眉页脚的行不重复计数。
3. **自动删除**：候选还必须整行匹配内置的明确水印模式，例如「由扫描全能王扫描创建」一类
   扫描工具生成标记。模式采用少量明确的全行匹配，随实际样本和误删测试维护；不把「仅供学习」、
   「内部资料」、网址、版权声明等泛化词单独列为删除规则。只删除通过判断的具体块，绝不对全文替换短语。
4. **其余保留**：仅重复但不符合明确模式的行、嵌在段落内的水印、OCR 变体，以及无分页依据的输入，
   均原样保留。流程照常自动继续，日志记录候选文本、出现页码、处理结果和命中的规则。

首版只处理转换后文本中的水印，不新增 OCR、版面坐标分析、图片去水印或 LLM 分类。
这是一套保守的自动清洗规则，不承诺识别所有水印；`origin.md` 保持原样，便于事后追溯。

### 3.4 跨页接句

分页锚点保留（是定位原件页码的唯一线索），只把被切开的句子接回一侧。

**判定被切开**：锚点前最后一段的末字**不是**句末标点（`。！？；…」』”）】`、`:` 结尾的
列表引导除外），且锚点后第一段**不是**标题、列表、表格、图片、引用块。

**挪动规则（往长处汇集）**：设锚点后第一段为 `head + 断点标点 + rest`，其中断点标点是该段
**第一个**`，。；：！？`。比较锚点前那句的残句长度 `L_prev`（上一个句读标点之后到页末）与
`head` 的长度：

- `L_prev ≥ len(head)` → 把 `head + 断点标点` 挪到锚点**前**，接在上一段末尾。
- 否则 → 把上一段的残句挪到锚点**后**，接在 `head` 之前。
- 锚点后第一段找不到断点标点 → 整段视作 `head`，同样比较。

题目给的例子：残句「食品生产者应按照法律」10 字 > `head`「规定」2 字 → 「规定，」挪到上一页：

```markdown
食品安全监管部门依法履行法定职责，食品生产者应按照法律规定，

<!-- page 24 of 539 -->

遵照相关制度要求，积极配合监管部门工作。重要的食品安全监管制度如下:
```

**中英文接合**：两侧都是 CJK 时直接拼接；拉丁字母间补一个空格；行尾连字符 `-` 断词时去掉连字符拼接。

## 4. 拆分（`<sample>.md` → `<sample>/…`）

### 4.1 字数口径

**字数 = 正文（去掉 frontmatter）中非空白字符数**，不计分页锚点与 markdown 图片/链接的 URL 部分。
CJK 一字记一，英文一个字母记一（与 `wc -m` 去空白同量级，便于和既有库对照）。

阈值常量：`SPLIT_MIN = 40_000`（不拆的上限），`CHAPTER_FLOOR = 10_000`，`PART_MAX = 40_000`。

### 4.2 算法

```
split(doc, level):
    if chars(doc) <= SPLIT_MIN:            → 不拆
    chapters = 按「本文档出现 ≥ 2 次的最高一级标题」切
    if 找不到这样的标题  或  所有章都 < CHAPTER_FLOOR:
        → 按大小拆（§4.2.1）
    for 每一章:
        if chars(章) > PART_MAX: split(章, level+1)  # 对这一章递归，换下一级标题
        else: 落为一个文件
```

- 选拆分层级和切章时，只看 §3.3 去噪后的正文：已被识别为页眉而删除的标题行不再存在，自然不参与。
  拆分器**不另设重复标题过滤**（决策P4.30-13）。
- 第一个标题之前的前言/版权页等，若 < `CHAPTER_FLOOR` 并入第一章；否则单独成一份 `-00-前言`。
- 递归下降到没有更低一级标题时，对该章改用按大小拆。
- **相邻小章合并**（实现补充，真实样本校准）：同一层里 < `CHAPTER_FLOOR` 的相邻小章在不超过 `PART_MAX`
  的前提下合成一份（名为「首章～末章」，文件名取首章）；合并后仍 < `CHAPTER_FLOOR` 的组并进后一章作引子
  （名随后一章），放不下再并进前一章。否则附录里几十个小节会各成一份几十字的文件——一本 539 页的样本书
  按字面规则拆出 50 份、其中 30 余份不足千字，合并后为 13 份。

#### 4.2.1 按大小拆

每份 ≤ `PART_MAX`。切点优先级：**标题前 > 分页锚点前 > 空行（段落边界）**；**绝不切在段落内部**。
单个段落超过 `PART_MAX`（极少见）时退到句末标点切。贪心装箱：在不超限的前提下取最靠后的高优先级切点，
因此相邻的小章节会被自然地装进同一份。为免切出碎片，先在「已装满一半以上」的范围里找切点，找不到才放宽。

### 4.3 文件命名与拆分元数据

```
parsed/<sample>/<sample>-<NN>-<章名>.md
parsed/<sample>/<sample>-<NN>-<章名>-<MM>-<子章名>.md      ← 递归拆出的
parsed/<sample>/<sample>-<NN>.md                           ← 按大小拆的
```

- `NN`/`MM` 两位序号（超过 99 份时自动三位），**保证文件名排序 = 原文顺序**。
- 章名取标题文本，经 `raw_slug` 净化，**截断到 24 个字符**，整个 basename 再按**字节**限到 200 以内
  （Linux 按字节计 255 上限；CJK 一字 3 字节，只在 macOS 上测会漏掉）。
- 每份的 frontmatter 继承 §3.1 的字段，另加：

```yaml
split:
  parent: 企业食品安全管理人员基础读本          # <sample>
  index: 3
  total: 17
  path: [第二章 食品生产许可, 第一节 许可条件]   # 标题路径
  method: chapter        # chapter | size
  pages: [88, 131]       # 本份覆盖的原件页码（有锚点时）
  prev: 企业食品安全管理人员基础读本-02-…
  next: 企业食品安全管理人员基础读本-04-…
```

### 4.4 目录索引 `<sample>-目录.md`（拆分时生成，只留 `parsed/`）

列出每份的序号、标题路径、页码区间、字数，带到每份的相对链接。**只落 `parsed/<sample>/`，不进 `raw/`、
不入库**（决策P4.30-9）：它只有标题和页码，入库价值低；拆分关系已写进每份的 `split:` frontmatter，
ingest 时 Agent 能看到前后篇。它的用途是 §2.1 确认时和事后在「已解析」里查看全貌。

## 5. 落 `raw/`

- 未拆分：`raw/<sample>.md`。已拆分：`raw/<sample>/<sample>-NN-….md`，**不落整本 `<sample>.md`**。
- 写入复用 P4.6.1 晋级的落盘原语：`imageio.collect_for_promotion`（按引用收集图片、归一到**原语决定的落点**）
  → `imageio.commit_md_with_images`（图 staging-swap → md 末步 `rawio.atomic_write_raw` → 失败回滚）。
  实现说明：直接调 `imageio` 里的两个原语，不经 `web/promote.py`——后者依赖 FastAPI，CLI `import` 不能要求装 web extra。
  `collect_for_promotion` 加了 `strict=False`：相对引用找不到时原样保留并记账，不再抛错（见下条「图片断链」）。
- **图片断链检查**（决策P4.30-16）：③ 拆分后、确认前，对每份做一次零 LLM 检查。拆分改写引用造成的断链
  （`.origin.md` 里找得到、分卷里找不到）是一键入库的缺陷，任务直接失败；解析时就断的链（转换器漏掉的图）
  在确认页作警告，原样保留，不阻止入库。不做自动修复——唯一的确定性修复手段「重整」已下线（决策P4.30-2）。
- **图片落点沿用现有原语，不另建布局**：`imageio._images_dir` 锚在 md 的父目录（`<md 父目录>/images/<stem>/`）。
  因此未拆分时落 `raw/images/<sample>/`，嵌套分卷落 `raw/<sample>/images/<分卷 stem>/`，每份只带自己引用到的图片。
- **拆分时重写图片引用**（§4）：分卷从 `parsed/<sample>.md` 移到 `parsed/<sample>/` 下，原有的相对引用
  `images/<sample>/…` 随之失效。拆分器按新文件位置重写为 `../images/<sample>/…`，保证 `parsed/` 里的分卷可以
  预览、⑤ 能按引用收集到图片；落 `raw/` 时再由原语归一到上面的落点。
- **整批预检后再写**：预检在 ①–④ 阶段完成，结果进确认页（§2.1）。**`raw/<sample>.md` 与 `raw/<sample>/`
  作为一个整体检查**：两者任一存在即视为与本次导入相关，再按下表处理（决策P4.30-12）：

  | 盘上现状 | 处理 |
  |---|---|
  | 两者都不存在 | 无冲突，正常写入 |
  | 存在，且由某个旧任务清单记录为同一 `<sample>` 的产物，**目标文件集合与本次完全相同** | 可覆盖：确认页提示风险，勾选「覆盖」后逐个覆盖（人背书，沿决策P5.2-8） |
  | 集合不同（分卷数变化、整本 ↔ 分卷形态变化），或有文件不属于任何旧任务清单 | **冲突，不允许覆盖**：列出差异，只能放弃；需要用户先自行清理 `raw/` 后再导入 |

  归属**只认旧任务清单**，不凭路径推断：同名目录里可能有用户手工放入、并非一键入库产生的文件，
  不能整目录清理。
- **首版不做整书替换**：集合变化时自动撤回旧分卷，需要逐份撤回 source 页、独源衍生页和引用。现有
  `guanlan remove` 只定位顶层 `raw/<slug>.md`（`remove._locate`），不支持嵌套分卷，也会保留独源衍生页的正文，
  不能保证旧知识撤干净。把它扩成批量撤回与替换系统超出本阶段范围；这只限制异常路径，正常入库仍全自动。
- **写锁内复检**：⑤ 在写锁内重做预检。目标集合或已有文件的内容与确认时不同 → 旧确认失效，任务回到
  `awaiting_confirm` 并展示新的预检结果，**不能凭先前的「覆盖」勾选继续**。
- **写入的原子性只到单篇**（决策P4.30-14）：预检失败整批不写；预检通过后**逐篇原子写入**（每篇 md 与其图片
  走原语的 staging-swap + 回滚）。每篇的清单记录分两步：
  1. **写盘前**先持久化 `land: "writing"`、目标路径、最终 md 内容哈希，以及该篇图片的目标路径与哈希；
  2. 提交成功后改记 `land: "written"`。

  第 10 篇写盘失败时前 9 篇已经落盘，不做整批回滚；任务停下，修好后可续跑。
- **续跑时本任务已写的文件不算冲突**：清单记为 `written` 且盘上哈希与记录一致的文件，属于本任务自己，
  预检直接放行；哈希不一致才按冲突处理。
- **`writing` 的恢复**（提交成功、清单还没来得及更新就退出）：比对目标 md 与各图片的盘上哈希和记录——
  全部一致 → 补记 `written` 继续；目标都不存在 → 视为未写，重新写；**其余情况（部分存在或内容不符）→ 停下并
  列出差异**，不猜测。
- **slug 冲突**：沿 `ingest._reject_source_slug_collision`，在预检阶段就查，不留到 ⑥ 才炸。

## 6. 依次入库、进展日志、暂停与继续

### 6.1 任务清单（落盘，可续跑）

一键入库是一个**长任务**，状态落在 `workspace/tasks/<task_id>.json`（新目录，**不在**暂存区浏览/删除
白名单内）：

```json
{
  "task_id": "20261110-153012-企业食品安全管理人员基础读本",
  "upload": "uploads/企业食品安全管理人员基础读本.pdf",
  "upload_sha256": "3f2a…",
  "origin": "web | cli",
  "state": "preparing | awaiting_confirm | running | paused | done | failed | cancelled",
  "stages": {"parse": "done", "normalize": "done", "split": "done", "confirm": "done", "land": "done"},
  "prepared_sha256": {"parsed/企业…/企业…-01-总则.md": "…"},
  "items": [
    {"raw": "raw/企业…/企业…-01-总则.md", "sha256": "…", "land": "written",
     "state": "done", "exit_code": 0, "started": "…", "finished": "…"},
    {"raw": "raw/企业…/企业…-02-….md", "sha256": "…", "land": "written",
     "state": "running", "started": "…"},
    {"raw": "raw/企业…/企业…-03-….md", "sha256": "…", "land": "writing",
     "images": {"raw/企业…/images/企业…-03-…/企业…-03-…-1.png": "…"}, "state": "pending"},
    {"raw": "raw/企业…/企业…-04-….md", "sha256": "…", "land": "pending", "state": "pending"}
  ],
  "log": "workspace/tasks/<task_id>.log"
}
```

每完成一步、每写成一篇、每开始/结束一篇入库都**原子重写**这份清单（临时文件 + rename）。
`land` 记落盘进度（`pending | writing | written`，见 §5），`state` 记入库进度（`pending | running | done | failed`）。
开始入库前先把该项记为 `running` 再调 `run_ingest`，因此进程中途死掉时，清单能显示哪一篇没有完成。
续跑判定**同时**看清单记录和盘上指纹（§6.4），任何一方都不能单独决定跳过。

### 6.2 执行

整个任务作为 JobQueue 里的**一个作业种类 `oneclick`**，与 ingest/heal 同一单写者 FIFO。
⑥ 在作业内串行逐篇调 `run_ingest`；不并行（沿 xuexi 批量入库约定：各篇共享 entity 页与 `index.md`）。

**任意一篇非 0 退出码即停**（决策P4.30-7）：该项记为 `failed` 与退出码，任务进入 `paused`，后续篇目不再执行；
用户处理后点「继续」，从这一篇重试。理由：`run_ingest` 只返回退出码，没有可供区分「单篇内容问题」与
「门禁/环境问题」的结构化结果（`unexpected_writes` 是 `heal` 的字段）；为此新增一套失败结果协议不值得，
停下等人看一眼更简单，也不会在环境出问题时连续写坏多篇。

### 6.3 进展日志

- 经 `emit` 实时推送（决策P4.6.1-11 的通道），同时追加写 `workspace/tasks/<task_id>.log`，
  页面刷新或服务重启后仍能看到。
- 日志粒度：阶段开始/结束；整理摘要（删了多少页眉、接了多少句）；拆分结果表（份数、每份字数）；
  入库逐篇「`[3/17] 入库 raw/…-03-….md … 完成（4 分 12 秒，wiki 新建 5 页、更新 8 页）`」。
- 顶部常驻一行进度：`入库 3/17 · 已用 21 分钟 · 预计剩余约 1 小时`（按已完成篇的平均耗时估算）。

### 6.4 暂停与继续

- **暂停 = 本篇入完后停**（决策P4.30-5）。点击后状态显示「将在当前这篇入库完成后暂停」。
  不中途杀 Agentao：中断的入库会留下未经门禁收尾检查的 wiki 写入。
  解析阶段可以立即暂停（杀转换子进程，下次从头解析这一步，产物在 `parsed/` 覆盖）。
- **继续**：从清单读出断点，逐项判定：
  - **跳过**须同时满足：清单记录**本任务**已把该项入库成功（`state: done`），**且** `raw/` 文件哈希与清单一致、
    source 页的 `raw_digest` 与之匹配。只凭 `raw_digest` 不够：该篇可能以前入过库，这次重新入库时中断，
    旧 digest 仍然匹配，但 wiki 已被这次运行改了一部分；
  - 清单为 `running`（上次中断在这一篇）或 `failed` → **重新入库**；
  - `raw/` 文件哈希与清单不一致（被人改过）→ 停下，列出差异，请用户确认；
  - 其余 → 入库。
- **库级写锁**（决策P4.30-15）：互斥靠**操作系统文件锁**，不靠 pid。新增 `guanlan/kblock.py`，对 `<库根>/.guanlan.lock`
  加非阻塞排他锁（POSIX `fcntl.flock`，Windows `msvcrt.locking`，不新增依赖）；锁随进程退出由操作系统自动释放，
  不存在「残留锁」。锁文件里写入 pid、`origin` 与开始时间，**只用于显示是谁在写**，不参与正确性判断。
  - **覆盖所有写入口**：CLI 的 `ingest`、`query --backfill`、`heal`、`audit`、`remove`、`convert`、`reindex`、`graph`、`import`
    （普通 `query` 及真正只读的预览——`heal`/`audit`/`remove`/`convert`/`reindex` 的 `--dry-run`——不取锁；
    **`import --dry-run` 例外**：它会执行 ①–④、把中间产物写进共享的 `workspace/parsed/`，所以仍按准备阶段取锁
    并检查未完成任务，只是不执行 ⑤⑥），以及 Web 的 `WriteGate.write_lock` 持有期间（JobQueue 写作业、
    可写 chat turn）。拿不到锁 → 立即失败并说明谁在写，不排队等待。
  - 实现说明：`remove` 只在带 `--yes`（真正写入）时取锁，默认预览不取；任务号同一秒内重复时追加序号，
    不让第二个任务覆盖第一个的清单。
  - **嵌套写放行**：持锁的写运行里，Agent 按 `AGENTAO.md` / `SKILL.md` 在 shell 跑 `guanlan convert` / `ingest` /
    `reindex` 时，子进程拿不到锁，若直接拒绝会让这些原本可用的流程失效。**每次真取锁**新生成一个令牌
    `GUANLAN_KB_LOCK_TOKEN`，写进执行者信息，并在持锁期间放进 `os.environ` 由子进程继承、释放时还原；
    子孙进程发现持有者带着同一令牌、不是自己且仍存活，就当作嵌套调用、不再取锁。没有令牌的无关进程照常互斥；
    令牌只对这一次持锁有效，上一次持锁期间派生、活得更久的进程（后台 shell、长驻 MCP server）在下一次
    持锁时拿的是旧令牌，同样被拒。
  - **只由最外层入口取锁**：锁在 `cli.py` 子命令分发处和 `WriteGate` 里获取；`run_ingest`、`run_guarded_write` 等
    内核函数**一律不取锁**。因此 `import` 或 Web 作业内部调用 `run_ingest` 不会再去抢同一把锁（POSIX `flock`
    对同一进程里另开的文件描述符同样互斥，重复获取会让自己失败）。
  - 一键入库在**准备阶段 ①–④** 与 **执行阶段 ⑤⑥** 都持锁：准备阶段拿到锁后，先检查有没有未完成的任务，
    没有才创建新任务，这样 Web 与 CLI 不会同时建出两个任务、互相覆盖同一组 `parsed/` 产物。
    进入 `awaiting_confirm` 时释放；`awaiting_confirm` 与 `paused` 期间不持锁，不妨碍其它写操作。
  - Web 不在进程生命周期内长期持锁，只在每个写操作期间持有，否则开着 Web 时 CLI 什么都写不了。
- **恢复任务状态**：清单为 `preparing` 或 `running` 时，先尝试拿库级写锁。拿得到 → 原执行者已退出：
  `preparing` 的任务改记为 `failed`（准备阶段零 LLM、可直接重来，`parsed/` 产物会被新任务覆盖），
  `running` 的任务改记为 `paused`，
  在暂存区顶部提示「有 1 个未完成的入库任务」；拿不到 → 有进程仍在执行，**不改清单**，只显示锁文件里的执行者。
  Web 启动时和 CLI `--status` / `--resume` 都走这条规则。CLI 发起的任务可在 Web 里继续，反之亦然。
- **一个库同时只允许一个一键入库任务**处于 preparing/awaiting_confirm/running/paused；新任务需先完成或放弃旧任务。
  这条检查在持锁后进行（见上），不会出现两个进程同时通过检查的情况。

### 6.5 CLI：`guanlan import`（决策P4.30-10）

```bash
guanlan -C <kb> import <file>              # ①–④ → 打印确认摘要 → 交互确认 → ⑤⑥
guanlan -C <kb> import <file> --dry-run    # 只跑 ①–④ 并打印确认摘要，零 LLM，不写 raw/（仍取锁，见下）
guanlan -C <kb> import <file> --yes        # 跳过交互确认（非交互终端必须给，否则以用法错误退出）
guanlan -C <kb> import <file> --overwrite  # 允许覆盖 raw/ 已有目标（人背书，沿决策P5.2-8）
guanlan -C <kb> import --resume            # 继续本库唯一未完成的任务（Web 发起的也可以）
guanlan -C <kb> import --status            # 打印未完成任务的清单与进度，零 LLM
guanlan -C <kb> import --cancel            # 放弃等待确认或已暂停的任务（parsed/ 产物保留）
guanlan -C <kb> import <file> --json       # 结构化输出确认摘要/回执
```

- `--dry-run` 与准备阶段相同：持库级锁、有未完成任务时拒绝执行；产物留在 `workspace/parsed/`，**不创建任务记录**，
  不占用「唯一任务」名额。
- `<file>` 可以是任意路径（不限 `workspace/uploads/`）；`origin` 记用户给的原始路径（沿决策P5.2-11）。
  中间产物仍落 `workspace/parsed/`，与 Web 同形，Web 端可以看到、预览、删除。
- 进展日志写 stderr 与 `workspace/tasks/<task_id>.log`；stdout 只留最终回执（`--json` 时为 JSON）。
- **暂停**：第一次 Ctrl+C = 本篇入完后暂停（打印提示）；第二次 Ctrl+C = 立即中止，当前篇记为 `pending`，
  它的 wiki 写入可能未经门禁收尾——中止后提示先跑 `guanlan check`。
- `--model` / `--thinking` 透传给每篇 `run_ingest`。
- **断链统计**（决策P4.30-16）：⑥ 开始前和全部完成后各跑一次零 LLM 的 `run_check`，把 wiki 断链数的变化记进
  任务清单和完成提示，断链不为 0 时建议「可运行 `guanlan heal --dry-run` 查看可补的页面」。**不自动跑 heal**：
  断链在写门禁里本就只作警告（决策8），一本书的前几份留下的断链常被后几份补上；heal 要调 LLM、按频率挑目标，
  值不值得跑由用户决定，塞进一键入库会让耗时和费用无法预估，也让暂停/续跑多出「heal 算第几篇」的问题。
- 实现补充：CLI 没有确认页，可覆盖的冲突须事先给 `--overwrite`，否则打印差异、放弃任务并以 `EXIT_USAGE` 退出；
  交互确认答「否」同样放弃任务（`EXIT_OK`）。`--cancel` 是为「新任务需先完成或放弃旧任务」补的出口。
  第二次 Ctrl+C（立即中止）以 `EXIT_USAGE` 退出，任务记 `paused`、当前篇记 `pending`。
  为让第一次 Ctrl+C 不连带打断正在跑的 agentao，`import` 调 ingest 时让子进程进新会话（`start_new_session`），
  其余命令不变。
- 退出码沿用现有集合，不新增：全部成功 `EXIT_OK`；用法/冲突 `EXIT_USAGE`；某篇失败时任务暂停，以该篇的退出码退出；库被其它写者占用时同样以 `EXIT_USAGE` 退出；
  **用户主动暂停**（Ctrl+C）以 `EXIT_OK` 退出，回执里 `state: paused`；因失败而暂停时按上一条以失败篇的退出码退出。

## 7. 模块与归口

整理、拆分和任务执行都**与传输无关**，不放进 `web/`；Web 与 CLI 只是两层薄壳：

| 模块 | 职责 |
|---|---|
| `guanlan/normalize.py`（新） | §3：分页、页眉页脚页码水印识别、跨页接句、frontmatter；返回 `(text, ops)` |
| `guanlan/splitdoc.py`（新） | §4：字数口径、章节/大小拆分、命名、拆分元数据、目录索引；返回分份列表，不写盘 |

## 8. 决策（草案）

- **决策P4.30-1（一键入库的点击即人背书，取消解析后的人审关口）**：沿 P5.2「命令行用户即背书人」口径，
  点「一键入库」等于对整条管线的产物背书。原件和 `origin.md` 留在暂存区，可事后对照。
  代价：解析质量差的文档会直接进 `raw/` 并入库。补救：未拆分的源可用 `guanlan remove <slug>` 撤回（源移入 `.trash/`、
  剥引用、修索引）；**拆分出的嵌套分卷目前 `remove` 不支持**（只定位顶层 `raw/<slug>.md`，见 §5），首版只能手工处理。
- **决策P4.30-2（parsed/ 只保留删除与只读预览）**：晋级、断链检查、重整下线；Agent 在 `parsed/` 里手工拆合的
  工作方式随之退场，由确定性拆分取代。只读预览保留，供确认前后查看整理/拆分效果（§9 Q1）。
- **决策P4.30-3（整理与拆分零 LLM）**：页眉页脚识别、接句、拆分都是可测试、可复现的规则。
  理由：① 宿主不持 LLM 的不变式；② 这一步改的是**将成为原文的文本**，LLM 改写会悄悄改字，
  正好破坏 `quotes` 引语逐字核对的基础；③ 一本书几百页，LLM 逐页整理成本高且慢。
- **决策P4.30-4（拆后不落整本）**：`raw/` 中同一内容只出现一次，避免整本与分份重复入库。
- **决策P4.30-5（暂停只在篇与篇之间生效）**：保证每篇入库都走完门禁收尾。
- **决策P4.30-6（任务清单落盘，清单记录与盘上指纹同时成立才跳过）**：跳过一篇须本任务清单记 `done`，且
  `raw/` 哈希与 source 页 `raw_digest` 都匹配；`running`/`failed` 的篇重新入库。`preparing`/`running` 状态只在
  拿到库级锁、确认原执行者已退出后才恢复（§6.4）。
- **决策P4.30-7（任意一篇失败即暂停）**：见 §6.2。不区分失败类型，因为 `run_ingest` 只给退出码。
- **决策P4.30-8（写 `raw/` 前确认一次）**：见 §2.1。确认开始执行与时间成本，拆分和清洗由系统决定；
  确认时复检 ①–④ 产物哈希（§9 Q3）。
- **决策P4.30-9（目录索引只留 `parsed/`）**：见 §4.4（§9 Q2）。
- **决策P4.30-10（同步提供 CLI `guanlan import`，与 Web 共用内核和任务清单）**：见 §6.5（§9 Q4）。
  任务清单放在 `workspace/tasks/`，跨进程互斥用库根的 `.guanlan.lock`（决策P4.30-15）；两端可以互相续跑。
- **决策P4.30-11（清洗全自动，用户不参与过程）**：页眉页脚、水印识别与拆分使用内置规则，
  用户无需选候选、调参数或审文本。水印按「重复短行候选 + 正文结构排除 + 明确模式」自动删除，
  证据不足自动保留并继续；清洗详情只供事后查看。写 `raw/` 前仍保留一次开始确认，覆盖已有目标需明确背书。
- **决策P4.30-12（覆盖只限同集合，归属只认旧任务清单；首版不做整书替换）**：见 §5。`raw/<sample>.md` 与
  `raw/<sample>/` 一起预检；集合变化或归属不明一律报冲突。理由：现有 `remove` 不支持嵌套分卷、也撤不净
  独源衍生页，自动替换会把一键入库扩成批量撤回系统。
- **决策P4.30-13（页眉规则可删标题行，但不泛化过滤重复标题；不做页码偏移推断）**：见 §3.3、§4.2。
  标题形式页眉须满足页边位置稳定、文本重复、页数门槛；拆分器只是看不到已删的页眉，不另设过滤。
  同行页码只剥行首/行尾带分隔、且与锚点页号直接相等的字段；章节页眉用同奇偶连续 ≥ 3 次的局部规则。
- **决策P4.30-14（写入原子性只到单篇，失败可续跑）**：见 §5。不引入整批事务；清单逐篇记 `land`，写盘前先记
  `writing` 与预期哈希，续跑时本任务已写且哈希一致的文件不算冲突，`writing` 按盘上实况补记或报差异。
- **决策P4.30-16（图片断链只检查、wiki 断链只统计，都不自动修复）**：见 §5、§6.5。拆分造成的图片断链判失败，
  解析时就断的作警告；wiki 断链数在入库前后各统计一次并提示 `heal --dry-run`，不自动跑 heal。
- **决策P4.30-15（库级操作系统文件锁，覆盖所有写入口）**：见 §6.4。pid 只用于显示；任务状态只有在拿到锁、
  确认原执行者已退出后才恢复。只由最外层入口取锁，内核函数不取。一键入库的准备与执行两段都持锁。
  这是本阶段唯一一处触及其它命令的改动。

## 10. 测试要点

- `normalize`：题目中的跨页例子逐字复现；奇偶页交替页眉；页码各形态；正文里恰好是数字的行（表格、
  年份）不误删；无锚点输入只写 frontmatter；**漏报用例**（本该删的页眉因阈值被放过时测试能发现）。
- 页眉补充规则，正反例成对：
  - 标题形式页眉（每页顶部 `## 书名`）被删；正文中位置不在页边的同名标题保留；合法的重复章节标题
    （「练习」「小结」）保留，且仍参与拆分。
  - 页码与页眉同行：行首/行尾带分隔、与锚点页号相等的页码被剥离后整行按页眉删除；行内其它位置的相同数字
    不动；页码与锚点页号不等（有偏移）时整行保留。
  - 章节页眉：同奇偶连续 3 页页首出现即删；只连续 2 次、或分散出现未连续、或出现在正文中间的相同短句不删。
  - 顺序：页码、页眉位于被切开的句子之间时，去噪后接句仍得到正确结果。
- 水印：重复扫描工具标记自动删除；重复正文、不同数字条款、版权声明、仅供学习等泛化短句不误删；
  标题/列表/表格/代码/引用内不删；同文段内短语不被全局替换；少于 3 页、覆盖不足、OCR 变体或无分页时保留；
  删除与保留均可追溯，疑似项不产生人工待办，Web 与 CLI（含 `--yes`）使用相同规则。
- `splitdoc`：< 4 万不拆；按章、章全 < 1 万改按大小、单章 > 4 万递归；切点不落段落内；文件名字节上限
  （用超长中文章名，Linux CI 上跑）；`split:` 元数据前后链完整；拼回所有分份 == 拆前正文（无丢失、无重复）。
- 冲突预检：`raw/<sample>.md` 与 `raw/<sample>/` 任一存在都被发现；同集合且归属旧任务 → 可覆盖；
  分卷数变化、整本 ↔ 分卷形态变化、目录里有不属于任何旧任务的文件 → 冲突且不可覆盖；确认后 `raw/` 被改动
  → 写锁内复检使旧确认失效、回到 `awaiting_confirm`。
- 图片：拆分后 `parsed/<sample>/` 分卷的图片引用被重写且可预览；落 `raw/` 后图片在 `raw/<sample>/images/<分卷 stem>/`，
  每份只带自己引用的图。
- 写入与续跑：第 N 篇写盘失败时前 N−1 篇保留、清单记 `written`，续跑时它们不算冲突；清单为 `running` 的篇
  即使旧 `raw_digest` 匹配也重新入库；只有本任务记 `done` 且指纹匹配才跳过。
- `writing` 恢复：提交成功但清单未更新即退出 → 续跑时盘上哈希一致，补记 `written` 并继续；目标不存在 → 重写；
  部分存在或内容不符 → 停下并报差异。
- 库级锁：一键入库执行期间 CLI `ingest`/`query --backfill`/`heal` 立即失败并显示执行者，普通 `query` 与其它只读 `--dry-run`
  不受影响；`import --dry-run` 仍取锁——一键入库执行期间它立即失败，有未完成任务时拒绝执行，且不创建任务记录；
  `import` 内部调用 `run_ingest` 不因重复取锁失败；Web 与 CLI 同时发起准备阶段时只有一个任务被创建；
  准备进程被杀后遗留的 `preparing` 任务被改记为 `failed`；执行进程被杀后锁自动释放、任务被恢复为
  `paused`；锁被占用时 `--status` 不改清单；Web 只在写操作期间持锁。
- `oneclick`：预检冲突整批不写；任意一篇失败即暂停、继续时从该篇重试；暂停在篇间生效；
  重启后 running→paused；续跑跳过已入库项（`raw_digest` 匹配）；`raw/` 被人改过时停下。
- 确认：①–④ 后停在 `awaiting_confirm` 且 `raw/` 未被触碰；确认后才写；确认前改动 `parsed/` 产物 → 拒绝确认；
  放弃后 `raw/` 不变、`parsed/` 产物保留。
- 使用流程：默认确认页只展示必要摘要，不出现水印候选勾选、清洗参数或逐项复核；无冲突时确认开始后自动完成。
- CLI：`--dry-run` 零 LLM 且不写 `raw/`，但持锁、写 `parsed/`；非交互终端缺 `--yes` 以用法错误退出；第一次 Ctrl+C 篇间暂停；
  `--resume` 能接 Web 发起的任务；Web 与 CLI 同时执行写操作时后者被库级锁拒绝。
- 端点：下线端点 404；parsed 预览仍可用；reader 模式不注册；可写 turn 活跃时 423。
