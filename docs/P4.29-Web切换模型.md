# P4.29 Web 会话内切换模型（`/model`）· **已实现**

> P4 Web 宿主的会话能力增强：可写会话里用 `/model <provider>/<model-name>` 换到另一个 provider 的另一个模型
> （只写 `/model <provider>` 则用该 provider 的默认模型 `{PROVIDER}_MODEL`），
> 只影响当前会话。零新依赖；切换本身零 LLM。代码基线：`33e96db`。

## 1. 范围

**做**：
- 斜杠命令 `/model`：无参 → 显示当前 `provider/model`、环境中已配置的 provider 名、用法；带参 → 切换。
- 端点 `POST /api/chat/{id}/model`，请求体 `{"model": "<provider>/<model-name>"}` 或 `{"model": "<provider>"}`。
- `/status` 与会话 `info` 显示 `provider/model`；`info` 多出 `provider`、`providers`（仅名字）。

**不做**：
- 只读会话切换（409，提示先 `/mode workspace-write`）；只读部署（`--reader`）整条禁用（端点不注册 → 404，
  与 `/mode`、`undo` 同口径）。
- 跨会话 / 进程级默认模型的修改（新会话仍用 `--model` 或环境发现的默认）；冷会话恢复不回绑切换后的模型
  （沿用 `conversation_store` 既有口径：盘上只存模型名、不存 provider，回绑会得到不一致的组合）。
- 模型目录查询（不调 `/models` 端点，不校验模型名是否存在——写错名在下一轮调用时由 provider 报错）。
- `ingest` / `query` 等子进程命令的模型（它们走 `--model` / 环境，不在会话里）。

## 2. 决策

- **决策P4.29-1 线上只传名字，凭据服务端解析**：同 agentao ACP `session/set_config_option` 的安全性质——请求体
  `extra="forbid"`，夹带 `apiKey` 等字段直接 422。服务端用 agentao 公开的 `discover_llm_kwargs`（会话构造期
  `build_from_environment` 用的同一函数）把 `LLM_PROVIDER` 换成目标名取该 provider 块，原样交给
  `agent.set_provider`。guanlan 不自拼 key 变量名、不缓存、不记日志、不回传；错误消息只含 provider **名**，
  agentao 重配失败只报异常类型。这仍守「wrapper 不持 API key」：key 只在一次调用栈内从进程环境流到 agentao。
- **决策P4.29-2 格式**：按**第一个** `/` 切（model id 自身可含 `/`，如 `openrouter/org/model`）。provider 名只收
  环境变量前缀形状 `[A-Za-z][A-Za-z0-9_]*`，大小写不敏感（归一为大写前缀），杜绝拼出任意环境变量名去探测环境；
  model 名保留大小写。**仅写 provider**（无 `/`）→ 用该 provider 块的 `{P}_MODEL`（与会话构造期环境发现同一口径，
  经同一次 `discover_llm_kwargs` 取得）；该变量未设 → 422，提示写成 `<provider>/<model-name>`。写了 `/` 却缺任一侧
  （`alpha/`、`/m-1`）视为笔误 → 422，不当作「仅 provider」。
- **决策P4.29-3 仅 workspace-write**：换模型等于换计费方与数据去向，与写权限同级对待。只读会话 409；前端先挡一道
  给出本地化提示，服务端按会话真实姿态判。
- **决策P4.29-4 wire 协议随 provider 块走**：`{P}_API_FORMAT` 未设 = 默认 wire（`openai-completions`），**不是**
  「沿用当前」——否则从 anthropic-messages 的 provider 切回 OpenAI 兼容的 provider 时，key 和端点会被发给错的
  SDK（同 ACP 处理器的注释）。非法取值在动 agent **之前**拒（422），会话保持原 provider；`base_url` 未设（或空串）
  即 SDK 默认端点，不继承上一个 provider 的自定义端点。
- **决策P4.29-7 非默认 provider 须显式配端点**：环境里的 `*_API_KEY` 不全是 LLM key（搜索、地图等服务也用这个后缀）。
  只凭 key 放行，`/model sometool/x` 会把那个服务的 key 当 bearer 发往 SDK 默认端点。故除进程默认 provider（会话
  构造期已在用、确认可用，如未设端点的官方 OpenAI / Anthropic）外，缺 `{P}_BASE_URL` 一律 422。共享参数
  `LLM_TEMPERATURE` / `LLM_MAX_TOKENS` 非数字时同样 422（而非 500）。
- **决策P4.29-8 不改落盘 model、reader 不露 provider 名单**：切换只改活会话，不改落盘的 model 元数据——冷恢复回到
  进程默认模型，盘上若记成新模型，重启后冷会话 `/status` 会显示一个并不会用的模型。`--reader`（匿名多用户）下
  会话 `info` 不返回 `providers`：那是部署情报，且 reader 下 `/model` 本就不可用。前端取命令后的**全部**剩余文本
  作参数（`/model alpha / m-1` 不会静默变成「仅 provider」）。
- **决策P4.29-5 与在飞 turn 串行**：端点持 `conv.lock`（同 `/mode`），并先过层③自死锁检查；流式中 `/model <值>`
  在前端按「生命周期命令」拦下，提示先停止。随模型而变的状态（token 编码、观测上限、旧模型的推理产物）由
  agentao `set_provider` 清理，不在 guanlan 重复。
- **决策P4.29-6 provider 列表只看名字**：`/model` 无参列出环境里 `{P}_API_KEY`、`{P}_BASE_URL`、`{P}_MODEL` 三者
  都非空的 provider（与 agentao CLI `/provider` 同口径），只判断是否非空、不读出值。

- 全量 pytest 通过；契约测试在真 `Agentao` 上验证 `set_provider` 的重配语义（离线，死端点）。
- 真浏览器（Playwright + Chromium，真 agentao、死端点）：只读会话 `/model alpha/m-1` 被拦；`/mode workspace-write` 后
  `gpt`（缺 `/`）与未配置 provider 各给明确提示；`alpha/org/m-1` 切换成功；`/model`、`/status` 显示
  `alpha/org/m-1`；所有 `/api/` 回包里不含 key。
