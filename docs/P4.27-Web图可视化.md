# P4.27 Web 图可视化（只读表现层）· **已实现**（落点见 §8，实测见 §10）

> P4 Web 宿主的**表现层增强**：在 Web 内用交互式关系图浏览 wiki 的链接结构——社区总览、社区展开、单页一跳邻域三个视图，
> 按社区或页型着色，点节点打开页面。零 LLM、零写（不写 `graph/`）、不新增第三方依赖。
> 代码基线：`2019e41`。
>
> **首版范围一句话**：三个视图（总览、社区、一跳邻域）＋一个只读 API＋一个图谱面板。不做布局持久化、通用图框架或新的缓存基础设施。
>
> **背景**：决策P3-7 把力导向、缩放等图形化展示留给「P4 Web UI」，P4 落地时又没做——Web「图谱」按钮至今只是重建
> 并打开 P3 的零 JS 邻接列表 `graph.html`。这一项被推迟过两次（`docs/backlog/notes/next-milestone-and-graph-viz.md` §3），
> 推迟条件是「语料规模上来后」；现在本机已有三个 770–1,530 页的真实库，条件成立。

## 1. 范围

**做**：一个只读端点 `GET /api/graph`（服务端按视图裁剪、聚合）；Web 内一个图谱面板，三个视图；wiki 页查看器加「在图中查看」入口；
复用已随 P4.20 内置的 ECharts，并把它的懒加载抽成公共加载器。

**不做**：
- 全图视图（小库也走总览 → 社区，统一入口）；两跳邻域（§3.1）。
- 割点 / 割边高亮——真实库几乎没有命中（§2），却要增加字段、图例与测试；后置，见 §7。
- 记录同一对页面间的链接条数（需改 `build_graph`）；LLM 推断边（DESIGN §8 仍推后）。
- 布局持久化或可复现坐标；在图上编辑链接；IM / MCP 展示。
- 改动 `graph.json` 契约、`graph.html`、`guanlan graph`、`build_graph`（决策P3-5/P3-7 原样成立）。

**归 P4.27**：与 P4.13/P4.20 同位阶——前端内容渲染 + 一个只读端点，不引入数据模型。

## 2. 规模实测：为什么不画全图

本机四个真实库，内存建图（不写盘），库名按页数记为 A–D。`build_graph` 已按 (source, target) 去重，
「有向边」即不同的有向页对；「无向页对」再把双向链接合并；「最大邻居数」按无向邻接（`undirected_adjacency`）计。

| 库 | 节点 | 有向边 | 无向页对 | 社区 | ≥5 页社区 | 单页社区 | 最大邻居数 | 割边 / 割点 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| A | 1,531 | 1,723 | 1,670 | 1,449 | 4 | 1,443 | 29 | 0 / 0 |
| B | 770 | 17,908 | 12,276 | 5 | 5 | 0 | 745 | 0 / 0 |
| C | 845 | 7,704 | 5,035 | 16 | 16 | 0 | 167 | 0 / 1 |
| D | 116 | 1,002 | — | 6 | 6 | 0 | — | 0 / 0 |

社区内部规模（页数 / 社区内无向页对）：B 最大三个为 215/3,534、210/1,933、176/2,090；C 最大为 102/604；D 最大为 30/111。

三种形状，没有一种适合「全图力导向」：

- **A 是散点**：1,450 张孤儿页，其中 1,447 张是互不相链的 source 页。全图是一片散点，信息在「只有 4 个成形社区」这一事实上。
- **B 是毛球**：近 1.2 万对无向页对，最大枢纽页连着 745 页；从它出发 1 跳就有 745 页，2 跳是 767 页（几乎全库）。
- **C 适合社区总览**：16 个社区、每个 56–102 页，按社区先看全局、再进单个社区，正好。

**完整请求耗时**（建图 + 社区检测 + 视图聚合 + 序列化，3 次取最快）：

| 库 | 建图 | 社区检测 | 聚合 + 序列化 | 合计 | 最大社区视图 JSON |
|---|---:|---:|---:|---:|---:|
| A | 0.16 s | 0.01 s | <0.001 s | 0.17 s | 5 KB |
| B | 0.30 s | 0.02 s | 0.004 s | 0.33 s | 139 KB |
| C | 0.13 s | 0.01 s | 0.001 s | 0.14 s | 24 KB |
| D | 0.02 s | <0.01 s | <0.001 s | 0.02 s | 5 KB |

耗时几乎全在 `build_graph`（全库读页 + 解析链接）；社区检测与聚合可忽略。

结论：**入口是社区总览，页面级只在单个社区或单页一跳邻域内画，且有节点上限。**

## 3. 设计

### 3.1 端点：`GET /api/graph`

只读、内存建图、**不写 `graph/`**，因此 reader 模式（P4.9）也注册——与需要重建文件、只在写者下注册的 `GET /graph` 不同。
建图是同步 CPU 活，经 `anyio.to_thread.run_sync` 卸离事件循环（同 `/api/search`，`guanlan/web/app.py:635`）。

| 参数 | 视图 | 返回 |
|---|---|---|
| `view=overview` | 社区总览 | 节点 = 页数 ≥2 的社区；边 = 社区间相连的无向页对数；另报单页社区（孤立页）数量 |
| `view=community&anchor=<页名>` | 社区展开 | 节点 = 锚页所在社区的页；边 = 社区内无向页对；每页带「连到别社区的页数」 |
| `view=page&name=<页路径或页名>` | 单页邻域 | 以该页为中心的**一跳**邻居（跨社区）及它们之间的边 |

**只做一跳**：两跳在 B 的枢纽页上近乎全库（§2）；且按度截断可能删掉连接中心与二跳页的中间页，使二跳页成为散点、失去「邻域」的意义——
要避免就得引入保路径的截断算法。不值得，v1 不提供 `hops` 参数。

**社区按锚页寻址，不按社区号**：社区号是 Louvain 在全图上算完后的重编号，wiki 任一改动都可能让同一号指向另一社区
（入库后刷新、点面包屑就会进错）。总览每个社区节点带 `anchor`——**社区内邻居数最多的页，并列按 id 升序**；
`view=community` 只接锚页名，用 P3.8 `resolve_owner` 归口后取该页**当前**所在的社区。锚页已不存在 → 404，前端回总览。

**字段**：

- 页面视图（社区、邻域）节点：`id`（小写页名 stem，同 `graph.json` 的 `id`，是 wikilink 解析键）、`path`（相对库根，前端用它打开页面）、
  `title`、`type`、`degree`（全图无向邻居数）。边：`source`、`target`（均为页面 `id`）、`mutual`（双向互链为真）。
- 总览节点：`id` = 该社区的 `anchor`（小写页名 stem）、`anchor_title`、`size`（页数）。边：`source`、`target`（均为社区的 `anchor`）、
  `weight`（两社区间相连的无向页对数）。不暴露社区号。

**边的口径**：按无向合并；`build_graph` 不保留同一对页面链了几次，故页面级边只标 `mutual`、不带条数。
断链、指向 config 页的链接、自环不画，口径与 `build_graph` / `lint` 一致——断链是 `check` / `lint` 的事。

**上限与截断**：每个视图节点上限 `GRAPH_VIEW_MAX_NODES`（初值 300，见 U1）。超出时：

| 视图 | 保留规则 |
|---|---|
| 总览 | 按 `size` 降序、`anchor` 升序取前 N 个社区；只留两端都在保留集内的边 |
| 社区 | 按 `degree` 降序、`id` 升序取前 N 页；只留两端都在保留集内的边 |
| 单页邻域 | 中心页恒保留；其余邻居按 `degree` 降序、`id` 升序取前 N−1 页；只留两端都在保留集内的边（一跳邻居都与中心直连，截断不会产生散点） |

截断时响应带 `truncated: {total: 原节点数, shown: 实际数}`，前端显式告示（如「只显示连接最多的 300 页」），不静默截断。
社区视图不单设边上限——只有互链 / 单向之分时按边截取近乎任意丢边；边量由 U1 在 B 最大社区（215 页 / 3,534 对）上实测定。

**确定性**：同一份 `wiki/` 返回字节相同的 JSON（节点按 id、边按 (source, target) 排序）。布局坐标不在响应里。

**缓存**：`graphview` 模块内一个**单槽 memo**，键为 `wiki/` 页面的 (相对路径, mtime_ns, size) 签名，值为建好的图、无向邻接与社区划分；
签名不变直接复用，变了整体重建。写者、reader 两种模式一样。只借鉴 `CorpusCache` 的签名做法，**不扩展检索缓存体系**——
`CorpusCache` 缓存的是检索文档与反链数，没有整图接口。签名本身要 stat 全库页面，比建图便宜一个量级；按 §2 实测，缓存命中后请求只剩聚合与序列化。

**并发**：不取 `write_lock`，ingest 进行中可能读到写了一半的 `wiki/`，与 `/api/search` 同口径，接受（下次请求即自愈）。
memo 由一把锁护单槽替换，并发首请求可能各建一次，结果相同，不做 singleflight。

### 3.2 前端：图谱面板

- 「图谱」按钮改为打开 Web 内的图谱面板（总览视图）；面板角落保留「静态列表」链接，写者模式下照旧走 `GET /graph`
  打开 `graph.html`（reader 下不注册该路由，链接不显示）。
- **渲染**：ECharts `graph` 系列 + `layout: "force"`。**不新增第三方库**。
- **ECharts 公共加载器**：现在的懒加载 Promise `_echartsPromise` 是 `flint_enhance.js` 模块内变量
  （`guanlan/web/static/flint_enhance.js:194`），抽成 `static/echarts_loader.js` 暴露 `loadEcharts()`，flint 与图谱共用、
  只注入一次 `<script>`。这是对 P4.20 代码的小重构，行为不变，P4.20 的冒烟脚本须照过。
- **视觉编码**：总览按社区着色、节点大小 ∝ `size`、边粗 ∝ `weight`；社区视图与邻域视图按页型着色、大小 ∝ `degree`、互链边加粗。
- **交互**：缩放、拖动；点社区 → 以其 `anchor` 展开；点页节点 → 在 wiki 查看器按 `path` 打开该页；面包屑「总览 › 某社区 › 某页」返回上级；
  返回时重新请求，不复用旧数据（社区可能已变）。
- **入口**：wiki 页查看器加「在图中查看」，进入该页一跳邻域。
- **双语**：新文案走 P4.7 的 `i18n.js`。
- **颜色**：ECharts 画在 canvas 上、读不到 CSS 变量；标签与连线颜色在渲染时用 `getComputedStyle` 取 `app.css` 的变量。
  应用目前只有一套亮色主题，没有暗色主题，故不做主题切换重绘（评审稿曾列此项，实现时核实后删去）。
- **释放**：ECharts 实例在关浮层、打开别的浮层（`core.js` `showOverlay` 复位宽卡片并释放）、点页面跳走时 `dispose`。

### 3.3 信任边界：标题一律纯文本

节点标题来自 frontmatter——LLM 写的，内容可能抄自 `raw/` 里的第三方原文；ECharts 的提示框默认按 HTML 渲染，
`label` / `tooltip` 的函数 formatter 返回的也是 HTML 串。**沿用 P4.20 的姿态**（决策P4.20-4 / P4.20-25，`flint_enhance.js:139`）：

- 提示框用 `renderMode: "richText"`，不走 HTML 提示框；
- 所有 formatter 只返回纯文本，不拼 HTML 标签；
- 标题、页名、锚页名一律按字面显示，`[[…]]`、`<…>` 不解释。

这是 P4.13 / P4.14 / P4.20 之后「内容 → 客户端渲染」的又一处入口，按同一标准对待；测试面带注入用例（§5）。

### 3.4 不变量

- `graph.json` 契约、`graph.html`、`guanlan graph` CLI 一字不改。`build_graph` 的建图逻辑不改，只让返回的 `Graph` 多带一个
  `resolution` 字段（建图时已建好的 P3.8 解析表，带默认值），供本相位按名寻址复用、免整库 frontmatter 二次解析；
  `graph_to_dict` 逐字段序列化，`graph.json` 不受影响。
- 端点零写：不写 `graph/`、不写 `wiki/`，reader 模式下也成立（P4.9 KB 零写）。
- 布局是表现，不是数据：力导向每次可能不同，不承诺坐标稳定，也不落盘。

## 4. 已知局限（接受）

- **总览在部分库上信息量有限**：A 只有 6 个页数 ≥2 的社区（外加 1,443 张孤立页的计数），B 只有 5 个社区——总览只回答
  「有几个成形社区、彼此怎么连」。总览的主要价值在 C、D 这类社区数适中的库；A、B 更多靠社区视图与单页邻域。
- 小库也要先过总览再进社区，比直接看全图多一次点击；换来一个统一入口。
- 大量孤立页只显示计数，不显示这些页本身——它们在 `lint` 孤儿列表里。
- 截断按全图邻居数取舍，低连接页在超大社区或枢纽页邻域里可能看不到，需从它自己的单页邻域进入。
- 社区划分来自确定性 Louvain（P3.5），不保证与人的主题划分一致。
- 页面级边不区分链接条数，只区分单向 / 互链。
