# P4.26 Web 子 Agent 进展跟踪（只读表现层）· **已实现**（落点见 §9）

> P4 Web 宿主的**表现层增强**：子 Agent 运行时，在答案气泡前用一行文字显示它是谁、跑到第几轮、最近调了什么工具，
> 结束时显示结果、轮数、工具次数与耗时。零新增 LLM 调用、零写、不落盘；不生成进度百分比。
> 源码核对基线：Agentao 0.5.17（`main@2a023ae6`）。**本期把依赖下限从 `>=0.5.16` 抬到 `>=0.5.17`**——配对所需的
> `child_task_id` 自 0.5.17 起才有（上游 #578 / #579）。
>
> **背景**：知识库可经 `.agentao/settings.json` 的 `agents.enable_builtin=true` 开启内建子 Agent，也可在
> `.agentao/agents/*.md` 定义项目子 Agent。Web 能执行它们，但整个运行期间只显示通用「处理中 Ns」心跳，
> 用户分不清是主 Agent 在想、子 Agent 在跑，还是卡住了。上游早已把所需事件发到 Web 的 transport，
> 旁听口 `_on_agent_event`（`conversation.py`）目前只转压缩与推理，其余丢弃。

## 1. 范围

**做**：一种 SSE 帧 `subagent`、每次子 Agent 运行一行旁注；普通流与 `/goal` 续跑流共用一个处理函数；依赖下限抬到 0.5.17。

**不做**：后台执行开关、子任务单独停止/重试、子会话跳转、工具轨迹列表、用量归因、实时计时、子 Agent 推理与正文
（上游本就不转发，见 P4.25 §7）、持久化与回放、IM / MCP 展示、上游 0.5.17 新增的 HostEvent 转播通道（§6）。
`bg_store=None`、权限检查、写门禁原样不动。

**归 P4.26**：与 P4.25 同位阶——旁听口加分支 + 一种新帧 + 前端一个处理函数，不引入数据模型与新端点。

## 2. 上游事件（已读源码核对）

### 2.1 用到的三个 transport 事件

全部在既有 `transport.subscribe(self._on_agent_event)` 旁听口收到。三者在 0.5.17 都带同一个 `child_task_id`
（每次前台运行一个 UUID4，`_wrapper.py:317-318` 在发 `AGENT_START` 之前生成；无 host 事件流时也有）：

| 事件 | 上游载荷 | 本方案用法 |
|---|---|---|
| `AGENT_START` | `agent`、`max_turns`、`task`（任务原文前 80 字）、`child_task_id` | 转 `id`、`agent`、`max_turns`；**丢 `task`** |
| 子 Agent 转发的 `TOOL_START` | `tool="[name n/max] tool"`、`call_id`、`args`、`child_task_id` | 转 `id`，从标签解析 `n`、`max`、工具名；**丢 `args`** |
| `AGENT_END` | `agent`、`state`、可选 `turns` / `tool_calls` / `tokens` / `duration_ms`、`error`、`child_task_id` | 转 `id`、`state`、`turns`、`tool_calls`、`duration_ms`；**丢 `tokens` 与 `error`**——`error` 在抛异常时是异常类名（`_wrapper.py` 的 `except Exception` 分支），在未完成路径却是 `incomplete.detail` 说明原文，两种含义混在一个字段里 |

- **主 Agent 自己的事件从不带 `child_task_id`**（上游 CHANGELOG 0.5.17 明文），故「有没有 ID」就是「是不是子 Agent 的」，
  不再靠标签格式区分。
- `AGENT_END` 对每个发过 `AGENT_START` 的前台运行**恰好发一次**，正常返回与抛异常都发（`_send_agent_end` docstring）。
- `state` 取值：`completed` / `failed` / `cancelled`——正常返回路径经 `_terminal_state(incomplete)`（`agents/tools/_outcome.py`）
  映射，子 Agent 没答完（incomplete）记 `failed`、被取消记 `cancelled`，不会冒出第四种。
  前端仍对未知值显示原文（纯文本），不当成功——防上游扩词表。
- 标签 `[name n/max] tool` 由上游测试钉住（`subagent-event-bridge.md` §7 第 3 条），上游 CLI 也用同一正则
  `^(\[[^\[\]]+ \d+/\d+\]) (\S+)$` 拆它；它现在只用来取轮次与工具名。不匹配就不发这一帧，开始/结束照常。
- `TOOL_COMPLETE` / `TOOL_OUTPUT` / `TURN_START` / `TOOL_CONFIRMATION` 也带 ID，但不用：本方案只显示「最近调用的工具」，
  不配对工具起止，不逐轮计数；确认仍走 P4.15 原交互。

### 2.2 配对：按 `child_task_id`

前端以 `id` 为键配对一次运行的开始、工具、结束。ID 每次运行唯一，**同名子 Agent 并行与否都不影响正确性**——
上一版依赖的「同名串行」（`tool_executor.py` 按工具实例加锁，原为保护 `output_callback`，非上游承诺）不再是前提，
相应的屏障契约用例与「同名重启标状态未知」规则一并删除。

`agent` 只作显示用，不再是键，故可以截断。

### 2.3 轮次的准确语义

标签里的 `n` 只在**有工具调用**的那一轮出现；没调工具的模型轮不发 `TOOL_START`。故文案是「第 n/max 轮」表示**最近观测到的**轮次，
工具名表示**最近调用的**工具，不声称它仍在执行；`max` 是预算，不换算百分比。

## 3. 设计

### 3.1 服务端：旁听口加三个分支

`_on_agent_event` 里加三个分支，**无状态一对一投影**（与 `thinking` / `compaction` 同法），统一发 `subagent` 帧：

| 上游 | 帧载荷 |
|---|---|
| `AGENT_START` | `{"phase": "start", "id", "agent", "max_turns"}` |
| 带 ID 的 `TOOL_START`（标签匹配） | `{"phase": "tool", "id", "turn", "max_turns", "tool"}` |
| `AGENT_END` | `{"phase": "end", "id", "state", "turns"?, "tool_calls"?, "duration_ms"?}` |

- **缺 `child_task_id`（非字符串或为空）就不发帧**——下限 0.5.17 下不会发生；不为旧版保留按名称配对的退路。
  ID 只取前 64 字符（UUID4 为 36）。
- 只转白名单字段；缺的计数省略（上游未知即省略，不补 0）；数字非整数则省略。`agent` 与 `tool` 只用于显示，各截断到 120 字符。
- 服务端**不保存任何状态**：不建表、不加锁、不分配 ID。配对放前端（单线程，见 3.2）。
- 迟到帧无需专门处理：`turn()` 收尾把 `self._emit` 置 `None`（`conversation.py`），之后的事件自然丢弃；
  收尾前发出的帧经 `call_soon_threadsafe` 先于 `done` 入队，与 token 帧同理。
- **子 Agent 名称发给浏览器——这是对更早约束「名称仅用于服务端关联、不发到浏览器」的有意变更**（决策P4.26-3）。
  理由：名称是用户自己在 `.agentao/agents/*.md` 写的定义名或内建定义名，与工具名同性质，不含任务内容；不发则界面只能显示
  「子任务 1」，用户无从知道是哪个子 Agent。任务原文（`task`）、参数、输出、失败说明仍不上线，那才是可能含敏感内容的部分。
  `id` 是上游生成的随机 UUID，不含任何内容。

### 3.2 前端：每次运行一行

`handleSubagent(botEl, payload)` 一个函数，`handleSSE` 与 `handleGoalSSE` 两处调用；收到帧时与 `thinking` 一样先撤心跳。

```text
⚙ codebase-investigator · 运行中 · 第 2/15 轮 · read_file
⚙ codebase-investigator · 已完成 · 3 轮 · 5 次工具 · 12s
⚙ generalist · 失败 · 4s
```

- **位置**：插在当轮 bot 气泡**之前**（与 `chat-compact` 同一插法），同档次淡色小字；不做折叠区。
- **配对**：`botEl._subagents` 记「`id` → 运行中的那一行」。
  - `start`：新起一行并登记；该 `id` 已登记则忽略（不应发生）。
  - `tool`：更新该 `id` 那一行的「第 n/max 轮 · 工具」；未登记就忽略。
  - `end`：把该 `id` 那一行改成终态，并从映射里移除；未登记就忽略（不凭空建「已完成」）。
- **行数上限**：每个气泡最多 `SUBAGENT_MAX_ROWS = 20` 行（决策P4.26-7）。超限的 `start` 不建行、不登记，只把气泡前一行
  「另有 N 次子 Agent 调用未显示」的计数加一；该运行后续的 `tool` / `end` 因未登记而自然被忽略。已显示的行照常接收事件。
- **终态文案**：`completed` → 已完成，`failed` → 失败，`cancelled` → 已取消，其他 → 原值。不显示失败原因（`error` 不上线，见 §2.1）。
  「已完成」只表示子运行结束，不表示内容正确。
- **收尾**：`done` / `turn_done` / `stopped` / `error` 及断流（`finally`）时，把仍登记着的行标「未收到结束」，**随即清空映射**——
  一个循环。清空保证收尾幂等：正常 `done` 之后 `finally` 再跑一遍，映射已空，不会把已收终态或已标过的行再改一次。
  没有计时器，所以没有要清理的东西。
- **纯文本**：只用 `textContent`，不渲染 markdown、不识别 `[[链接]]`；名称过长由 CSS 省略（`text-overflow: ellipsis`）。
- **i18n**：`subagent.running` / `subagent.turn` / `subagent.turns` / `subagent.tools` / `subagent.done` / `subagent.failed` /
  `subagent.cancelled` / `subagent.noEnd` / `subagent.elided` 中英两套。

### 3.3 不落盘、不回放

帧只活在本次 SSE 流与当前 DOM，刷新即无；`/messages` 回放不含子 Agent 行。IM 只认 `token` 帧，新帧原样丢弃。

## 4. 已知局限（接受）

- 没调工具的子 Agent 轮次不可见，行会停在上一个观测（§2.3）。转发的 `TURN_START` 带 ID、可补这一缺口，有真实需求再加。
- 子 Agent 自己的确认与提问仍以 `[name]` 前缀走 P4.15 原交互，不与这一行关联。

## 5. 测试面

`tests/test_web.py`（fake factory，沿 P4.25 写法）：

1. 三类事件 → `subagent` 帧，载荷只有白名单键、带 `id`；`task` / `args` / `tokens` / `error`（含未完成路径的说明原文）不上线。
2. 不带 `child_task_id` 的 `TOOL_START`（主 Agent 自己的）不发帧；不带 ID 的 `AGENT_START` / `AGENT_END` 也不发；
   带 ID 但标签格式不匹配只丢 `tool` 帧，开始/结束照常。
3. **两次同名运行交错**发事件（不同 ID）：帧序与发射序一致、各带自己的 `id`——证明配对不再依赖同名串行。
4. `/goal` 续跑流里同样出现，且落在所属内层轮的 `turn_start` 与 `turn_done` 之间。

`tests/test_im.py`：`subagent` 帧不进群。

`tests/test_agentao_contract.py`（真 Agentao、经观澜自己的构造路径与旁听口，不手工发理想事件）：

1. 真 wrapper 驱动、只换子 Agent 的 `chat()`，成功、抛异常、未完成（预算耗尽）、取消各跑一次：`AGENT_START` / `AGENT_END` 恰好各一次、带同一个 `child_task_id`，
   `state` 分别为 `completed` / `failed` / `failed` / `cancelled`；载荷键与 §2.1 一致，且未完成路径的 `error` 确为说明原文
   （钉住「`error` 不可当类型用」这一事实）。
2. 连续两次运行 ID 不同。
3. 全链路（真父 `chat` → 真执行器 → 真 wrapper → 真子 Agent → 真转发器，只换最底层 `chat_stream`）：主 Agent 自己调
   `agent_<name>` 的 `TOOL_START` 不带 `child_task_id`、不出帧；子 Agent 的工具带、出帧且 ID 与开始/结束一致（§2.1 区分规则的前提）。
   子工具的 `TOOL_START` 标签匹配 §2.1 的正则，`n` / `max` 与 `max_turns` 一致（第 1 条一并断言）。

`scripts/smoke_p426.py` 真浏览器冒烟（注入帧、不打真 LLM）：一行的建立/更新/终态、两次同名运行交错各占一行且各收各的终态、
名称里的 `<b>` 字面显示、心跳被撤、超过 20 行出现省略计数且已显示行仍能收终态。收尾按**普通流与 `/goal` 流各一遍**，
覆盖正常结束（`done` / `turn_done`）、停止、`error`、断流四种出口：只有未收终态的行被标「未收到结束」，已完成的行保持原样，
且收尾后映射为空（随后的 `finally` 不再改任何行）。

## 6. 上游：已就绪，不再提需求

观澜提的 [jin-bo/agentao#578](https://github.com/jin-bo/agentao/issues/578)（2026-10-24）已由 #579 实现，随 **0.5.17**（2026-10-25）发布：
前台运行的 `AGENT_START` / `AGENT_END` 与全部转发的子事件带同一个 `child_task_id`，与公开 `SubagentLifecycleEvent` 同值，
无 host 事件流时也有。本期按它配对（§2.2），并抬依赖下限。

同版上游还发布了一条**HostEvent 子会话转播**（`docs/design/subagent-event-channels.md`，#583 / #584）：
`Agentao(..., relay_subagent_events=True)` 时，子 Agent 的 `ToolLifecycleEvent` / `PermissionDecisionEvent` 以子会话的
`session_id` 出现在父 `events()` 流上，`SubagentLifecycleEvent` 带 `child_session_id` 与 `parent_tool_call_id` 作指针。**本期不接**：

| 考量 | 说明 |
|---|---|
| 要多开一个事件源 | 观澜 Web 至今不订阅 `events()`；接它得在工厂里开构造开关、在每次运行**之前**建一个 `session_id=None` 订阅（上游 §5.8：晚订阅会漏事件），再与 transport 帧对齐——正是决策P4.26-1 要避免的两源问题 |
| 信息不多于 transport | 本方案要的名称、轮次、最近工具、终态与计数，transport 帧已全有；转播给的是逐工具起止行，本方案不展示 |
| 上游自己也说 transport 留着 | 设计 §5.6：transport 转发器不改、不弃用，是 transport 宿主的兼容路径 |

若将来要做「工具轨迹列表」或「子会话跳转」（§1 不做项），再评估转播通道。

## 7. 决策表

| 编号 | 决策 | 理由 |
|---|---|---|
| P4.26-1 | 只用 transport 旁听口，不接 HostEvent observer，也不接 0.5.17 的子会话转播 | 一个事件来源、无对齐问题；与 P4.25 同路；所需字段 transport 已全（§6） |
| P4.26-2 | 服务端无状态投影，配对在前端按 `child_task_id` 做 | ID 每次运行唯一，与同名是否并行无关；前端单线程无需加锁 |
| P4.26-3 | 子 Agent 名称发给浏览器（**变更**更早的「不发到浏览器」） | 名称是定义名、不含任务内容；不发则界面无信息量 |
| P4.26-4 | 丢 `task`、`args`、`tokens`、`error` | 任务原文、参数、失败说明可能含敏感内容；`error` 一字段两义（类名 / 说明原文）不可当类型；用量已计入父轮，单列易被误读为另计 |
| P4.26-5 | 不计时，终态用 `duration_ms` | 沿 P4.25-3：计时器收尾出口多，存活提示交给心跳 |
| P4.26-6 | 一行旁注，不做折叠区 | 一轮通常一两个子 Agent，一行够看 |
| P4.26-7 | 不节流；每气泡至多 20 行，超限只计数 | 工具开始以秒计，无需节流；但单批调用数不受迭代上限约束，故行数须封顶 |
| P4.26-8 | 依赖下限抬到 `agentao[cli]>=0.5.17,<0.6`，不保留按名称配对的退路 | 两条配对路径并存要多一套规则与测试；0.5.17 已发布，抬下限更简单 |

## 8. 修订记录

**v2（2026-10-24，第三方评审）**：① `error` 一字段两义（异常类名 / 未完成说明原文），改为整个丢弃，不再转 `error_type`；
② 配对键 `agent` 不截断，只在显示时省略，加长名称撞键用例；③ 名称出站明确记为对上一版约束的有意变更（决策P4.26-3）；
④ 每气泡行数封顶 20、超限计数，已显示行仍收终态（决策P4.26-7）。

**v3（2026-10-25，上游 0.5.17 发布）**：① 配对键由名称改为 `child_task_id`（帧字段 `id`），删去「同名串行」前提、屏障契约用例与
「同名重启标状态未知」规则（i18n 少 `subagent.unknown`）；② 是否子 Agent 事件改由「带不带 ID」判定，标签只用来取轮次与工具；
③ `agent` 不再是键，与 `tool` 一样截断到 120 字符，删长名称撞键用例；④ 依赖下限抬到 0.5.17（决策P4.26-8）；
⑤ §6 由「上游需求」改为「已就绪」，并记录不接子会话转播通道的理由（决策P4.26-1）。
评审补充（非阻塞）：契约用例加取消路径（`cancelled`、结束恰好一次、ID 一致）；收尾标记后清空映射以保证幂等，
冒烟按普通流 / `/goal` 流 × 四种出口覆盖。

## 9. 落点

- `guanlan/web/conversation.py`：模块级 `_subagent_frame`（白名单投影 + 标签正则）+ `_on_agent_event` 一个分支。
- `guanlan/web/static/chat.js`：`handleSubagent` / `finishSubagents`，两流接线（帧 + 四种收尾出口 + `finally`）。
- `guanlan/web/static/{i18n.js,app.css}`：文案与一行样式（窄时只省略名称，状态与工具不缩）。
- `pyproject.toml` / `uv.lock`：下限 `>=0.5.17`；`CLAUDE.md` 状态段的下限说明同步。
- 测试：`tests/test_web.py` 4 例、`tests/test_im.py` 1 例、`tests/test_agentao_contract.py` 6 例（参数化 4 + 2）；
  真浏览器冒烟 `scripts/smoke_p426.py` 8/8。不动 `app.py` 端点与 `render.py`。
