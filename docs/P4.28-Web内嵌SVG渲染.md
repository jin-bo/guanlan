# P4.28 Web 内嵌 SVG 渲染（只读表现层）· **已实现**

> P4 Web 宿主的**表现层增强**：页面里的 SVG 直接显示成图。与 P4.13（mermaid）、P4.20（flint）同位阶——前端内容渲染，
> 不引入数据模型、不新增第三方依赖、不改任何端点。代码基线：`06003c4`。

## 1. 范围

**做**：两种写法统一渲染——

1. ```` ```svg ```` 围栏块（`fenced_code` 本就产出 `pre > code.language-svg`）；
2. **块级**原始 `<svg>…</svg>`：行首（≤3 空格缩进）起 `<svg`、`</svg>` 后到行尾只剩空白。此前被 `_EscapeHtmlExtension`
   （决策P4-4）转义成一屏标签文本。

作用于 wiki 单页、对话答案、raw 预览、暂存区预览——即所有经 `render_markdown` + `enhanceContent` 的注入点。

**不做**：
- SVG 内的链接、动画交互、`<foreignObject>` 里的 HTML、引用外部图片/字体/样式表（图像上下文里一律不生效）。
- 行内（段落中间）的 `<svg>`、嵌套 `<svg>` 的完整跟踪（非贪婪匹配到第一个 `</svg>`，余下部分照旧转义）。
  匹配不跨过另一个行首 `<svg`：正文里一行未闭合的 `<svg …` 字样不会吞掉后文直到下一个真 SVG 块。
- 列表项内（缩进 ≤3 空格）的 `<svg>` 会被当成顶层块提出，把所在列表断成两段；要放进列表请用 ```` ```svg ```` 围栏。
- 带 `<?xml …?>` 声明或 DOCTYPE 开头的块（不以 `<svg` 起行，不识别；改写成 ```` ```svg ```` 围栏即可，前端解析允许声明）。
- 仓外 `.svg` 文件的渲染——那是 `/api/raw/image` 已有的事（`helpers._image_file_response`）。

## 2. 决策

- **决策P4.28-1 服务端只做形状归一，不放行标记**：块级 `<svg>` 由 `render._SvgBlockPreprocessor`（优先级 23，
  低于 `fenced_code` 的 25——围栏里的 `<svg>` 已先被 stash，保持字面代码示例）改写成
  `<pre><code class="language-svg">转义源</code></pre>` 存入 htmlStash。服务端放行的 HTML 只有 `pre`/`code`，
  原始 HTML 全转义的姿态不变。两种写法到前端时已是同一形状，只有一个拾取点。
- **决策P4.28-2 前端经 `<img>` 渲染，不注入 SVG 标记**：`svg_enhance.js` 读 `textContent`（已反转义的源码），
  用 `DOMParser(…, "image/svg+xml")` 严格解析做校验（解析出的文档不挂树、不执行），再设
  `img.src = "data:image/svg+xml;charset=utf-8," + encodeURIComponent(src)`。作为图像加载的 SVG 不执行脚本、
  不发外部请求、不响应事件——安全边界由浏览器给出，**不需要也不引入 SVG 消毒器**。对比 mermaid（决策P4.13-3）
  靠库内 DOMPurify 把产物 innerHTML 进页面；这里连这一处注入点都没有。代价是 SVG 内链接/交互失效，静态示意图足够。
- **决策P4.28-3 宽容常见手写缺省**：markdown 里手写的 SVG 常省略 `xmlns`（内联 HTML 中可省，但作为图像必须有），
  `xlink:` 前缀也常不声明。前端只在根开标签缺失时补上这两个声明，其余不改。
- **决策P4.28-4 失败封闭、永不空白**：XML 解析失败、根不是 SVG 命名空间的 `<svg>`、超过 `SVG_MAX_CHARS`（100 万字）、
  `img.decode()` 失败——一律保留 `<pre>` 源码并在其上方贴 `.svg-error` 徽标（文案 `svg.renderFail`，textContent 注入）。
- **决策P4.28-5 尺寸**：有绝对 `width` 的按固有尺寸、超栏宽等比缩（`max-width:100%`）；有 `viewBox` 而 `width` 缺省或为百分比的没有固有宽度，
  `<img>` 会退成 300×150，故设 `width:100%`。`alt` 取根下 `<title>`，无则 `svg.alt`。
- 多块并发解码（`Promise.all`），总耗时取最慢一块而非逐块累加。
- **决策P4.28-6 与代码高亮划界**：highlight.js 的 `xml` 语言别名含 `svg`，`code_enhance.js` 显式跳过
  `language-svg`（同 mermaid/flint），避免两个增强器抢同一块；失败块因此不着色，与 mermaid 一致。

## 4. 验证

- `tests/test_web_svg.py`：块级多行/单行/3 空格缩进/大写/行尾空白/紧贴前后文本均改写；无语言围栏、`xml` 围栏、
  4 空格缩进、行内 code、段落中提及、未闭合均不改写；块内载荷与页内其余原始 HTML 仍转义；`/api/page`、`/api/raw/file`
  两个入口都生效；`svg_enhance.js` 代码（去注释后）不含 `innerHTML`/`outerHTML`/`insertAdjacentHTML`/`document.write`。
- 真浏览器冒烟（Playwright + Chromium，未入 pytest）：一页含 6 块——带 xmlns 定宽、无 xmlns 仅 viewBox 且用 `xlink:`、
  夹带 `onload`/`<script>`/外链 `<image>`、`width="100%"` + viewBox、坏 XML、```` ```svg ```` 围栏。结果 5 块成图（naturalWidth 均 > 0，viewBox 图与百分比宽度图
  撑满栏宽，`<title>` 作 alt），坏 XML 保留源码 + 1 个徽标；无 alert 弹出、无页面错误、外链零请求、`#wiki-view` 内
  活的 `<svg>` 元素为 0。
