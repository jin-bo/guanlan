# P3.13 同名页检测（`health.duplicate_stem`，零 LLM）

> 半阶段增强，不是新里程碑。给 `health` **加一类确定性 advisory**：两张以上页面的 stem（文件名去扩展名，
> 不分大小写）相同。按名解析只能落到其中一张，其余按名不可达。源自一个真实库的协调性体检：
> 一张 source 页与一张同名实体页（另一组是同名概念页）并存多日，`[[…]]` 一律落到实体页／概念页，
> source 页按名链不到，而 `check`、`health`、`lint` 都没有报。

## 0. 问题

`[[wikilink]]` 按 stem 全库解析（`pages.page_stem_index`，大小写不敏感），stem 全库唯一是按名解析的固有前提。
万一重名，解析按路径排序取第一张（确定性），于是：

- 其余同名页**按名不可达**：所有 `[[名字]]` 都落到排序第一的那张；
- 图谱里两张页**共用一个节点**（用户指南第 4 章「源撤回」一节已记这一现象）；
- Web 与 MCP 的 `read_page(name=…)` 同样只能读到第一张。

已有检查覆盖不到：`check` 只报 `aliases.collides_stem`（别名撞页面 stem）与 `aliases.duplicate`（别名重复），
**两张页面本身同 stem 不报**；`lint` 的断链判定看的是「能否解析到某页」，同名页恰恰都能解析，自然不报。

典型成因：ingest 给一份文献建了 source 页（slug 取自 raw 文件名），之后另一次 ingest 或 heal 又为同名文献
建了实体页或概念页。建页前查重只看 index 与别名，跨目录的同名页可能漏看。

## 1. 决策

- **\[决策P3.13-1] 放在 `health`，advisory，不进 `check`、不接写门禁。** 默认退出码 0，`--strict` 下退出码 6，
  与其他 health 项一致。
  不进 `check` 的理由：
  - 写门禁只拦「新增阻断违规」，进 `check` 固然能在 ingest 新建同名页时当场拦下，但拦下后的自愈要合并两页，
    这是内容判断，不该由门禁驱动；
  - 已有同名页的库会让 `guanlan check` 长期失败。

  先以 advisory 观察；若真实库里出现过模型新建同名页的实例，再评估升级。
- **\[决策P3.13-2] 判定口径 = 解析口径，同出一处。** 新增 `pages.page_stem_groups(wiki)`：stem(小写) → 按路径排序的
  页面列表（含 config 页）。`page_stem_index` 改为取每组第一个，检查报每组其余的页。「解析到谁」与「报谁按名不可达」
  不会各算一套，测试另断言报出的解析目标等于 `resolve_owner` 的结果。
- **\[决策P3.13-3] 报在按名不可达的页上，每张一条。** 三张同名报两条。`detail` 写明 `[[stem]]` 实际落到哪张，并给出
  两种修法：合并两页，或给其中一张改名并改正指向它的链接。注意，改名后**旧名不能再作这张页的别名**，否则会撞
  另一张页的 stem，被 `check` 报 `aliases.collides_stem`。
- **\[决策P3.13-4] 含 config 页，提示语随之换。** `concepts/overview.md` 排在 `wiki/overview.md` 之前，会把顶层
  overview 挤出按名解析，同样要报，finding 记在 config 页上。config 页不能改名、也不建图谱节点，所以牵涉 config 页时
  不说「共用一个节点」、不建议合并，改名对象只能是另一张内容页：
  - config 页被遮蔽：提示给遮蔽它的内容页改名；
  - config 页在前（如 `wiki/log.md` 遮蔽 `sources/log.md`）：提示给本页改名。
- **\[决策P3.13-5] 只认 stem 完全相同（转小写后）。** `foo_bar` 与 `foo-bar`、全角与半角这类 fold 变体，各自有精确
  解析键、互不遮蔽（P3.8「撞则不折叠」），不报。
- **\[决策P3.13-6] 排序。** `health.duplicate_stem` 排在 `FINDING_CAUSAL_ORDER` 第一档，位于 `health.index_missing_page`
  之前：它让整张页按名失联，是结构根因，先于 index 同步与内容建议展示。

## 2. 边界与失效条件

- **不判语义重复**：标题不同但内容重复的两张页，不在本检查范围。
- **不自动修**：合并两页需要内容判断，只提示，不改写。
- **与解析规则绑定**：若将来按名解析改为可带目录（如 `[[entities/X]]`）或改变同名取舍规则，本检查须同步修改。
  共用 `page_stem_groups` 与锁口径的测试会让两边分歧时先在测试里暴露。
- **成本**：多一次 `wiki/**/*.md` 的文件名遍历，不读文件内容，不增加状态。

## 3. 测试（`tests/test_health.py`）

- **应报出**：
  - 两目录同名：只报解析目标之外的那张；
  - 只差大小写（`Qux.md` / `qux.md`）也报。这条防漏报：比较时若忘了转小写，正例测不出来；
  - content 页与 config 页同名，两个方向各一条（改名对象须是内容页，且不提「节点」）；
  - 三张同名报两条。
- **不应报**：fold 变体 `foo_bar` / `foo-bar`。
- **口径锁定**：报出的解析目标等于 `resolve_owner(link_resolution_index(...))` 的结果。
- **其他**：
  - `--strict` 退出码 6；
  - JSON 契约；
  - 因果排序先于 `health.stub_page`。
- **测试文件名**：一律用短 ASCII（长中文文件名在 Linux 上按字节计长，CI 会失败）。
