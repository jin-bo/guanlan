## 0. 上游前提：图里的数据从哪来　**\[非本相位职责，但决定本相位是否通电]**

本相位被排上来的触发条件是：**观澜将经 MCP 接入用户的结构化数据库**。据此，闭环是

```
外部结构化库（MCP server）── agentao 注入的工具 ──▶ Agent 取数
   如：模型评测结果表 / 推理调用日志 / token 用量与成本表
        ──▶ 把结果行写成 ```flint 块（数据内联）落进 wiki 页 / 对话答案
              ──▶ P4.20：浏览器把该块编译渲染成图
```

两条**不属于 P4.20、但必须成立**的前提，先钉死免得实现时误以为本相位没通：

1. **只读路径能不能用外部 DB 工具，取决于上游而非观澜。** agentao `mcp/tool.py` 的 `is_read_only` 要求
   用户在 `mcp.json` 标 `trust: true` **且** server 自报 `readOnlyHint: true`；缺任一 → `query` /
   `guanlan mcp` 的 `ask` / Web **只读**问答一律 DENY（`runtime/tool_planning.py` 只读闸）。
   ⇒ 若接入的 DB server 不报 `readOnlyHint`，图只会出现在**可写路径**（`ingest`/`heal`/`audit`/P4.5 可写会话）
   的产物里。机制事实见 [`backlog/notes/mcp客户端注入-未排期.md`](backlog/notes/mcp客户端注入-未排期.md) §2–§3。
2. **数据必须内联落盘，不做「渲染时查库」**（决策P4.20-12）。图 = 取数那一刻的**快照**，100% 可从块内 JSON
   重建；浏览器**永不**发起数据请求。这是「markdown 是唯一事实来源」在本相位的直接形态——否则一张图的可重现性
   就绑死在外部库的当下状态上，且给前端开了一条出网路径。刷新数据 = 重新问答/ingest 产出新块，不是让图去查库。

## 1. 目标与范围

**P4.20 = 让 Web 宿主把页面里的 flint 围栏块画成图表。** 现状：

````markdown
```flint
{"data":{"values":[{"模型":"model-a","评测得分":72.4},{"模型":"model-b","评测得分":81.9},
                   {"模型":"model-c","评测得分":88.3}]},
 "semantic_types":{"模型":"Category","评测得分":"Score"},
 "chart_spec":{"chartType":"Bar Chart","encodings":{"x":{"field":"模型"},"y":{"field":"评测得分"}},
               "baseSize":{"width":420,"height":260}}}
```
````

经 `render_markdown` 的 `fenced_code` 渲染成 `<pre><code class="language-flint">…转义 JSON…</code></pre>`
——浏览器里显示为**一坨 JSON**，不是图。P4.20 把最后一公里补上：**同一段 markdown 在浏览器里成图，在 CLI /
纯文本回退里仍是 honest 的规格源码**（零信息损失——规格 + 数据都在块里）。

选 flint 而非直接写后端原生 spec 的理由（[研判笔记](backlog/notes/flint-chart-集成研判.md) §1）：flint 的输入是
「数据 + 语义类型 + 紧凑图规格」，刻度/轴/标签/图例/布局由编译器据数据基数推导——**Agent 能可靠生成、人能直接编辑**，
且**输入是纯 JSON、没有函数**，这两点正是本相位安全闸能站住的前提（§4）。

### 纳入 P4.20

- **前端拾取 + 编译 + 渲染**（`static/flint_enhance.js`，约 313 行 vanilla）：`enhanceFlint(container)` 扫
  `container.querySelectorAll('pre > code.language-flint')` → `JSON.parse(code.textContent)` → **入口白名单裁剪**
  → flint 编译成 ECharts option → **出口断言** → `echarts.init(…, {renderer:'svg'})` + `setOption` → 用
  `<figure>` 就地替换那个 `<pre>`。
- **接线成本为零**：P4.14 已把 P4.13 的单钩子泛化成 `enhanceContent` 编排器（决策P4.14-9），且**七个注入点
  全部只调它**（`wiki.js:199` `paintPage` / `wiki.js:255` raw 正文 / `chat.js:177` 历史重渲 / `chat.js:764`
  流式收尾 / `chat.js:1568` 收尾兜底 / `jobs.js:115` raw 预览 / `staging.js:542` 暂存区 `paint()`）。
  P4.20 **只在 `content_enhance.js` 里加一行 `enhanceFlint(container)`**，七处注入点一个字不动。
- **两个 vendored 运行时**（`static/vendor/`，钉版、非 CDN、随 `web` extra 静态资产打包）：
  - `vendor/flint/echarts.js` = `flint-chart@0.4.1` 的 `dist/echarts/index.js`，**自包含单文件 ESM**，经动态
    `import()` 加载（**新姿态**，见决策P4.20-3）；
  - `vendor/echarts.min.js` = `echarts@6.1.0` UMD，经注入 `<script>` 加载读 `window.echarts`（同 mermaid 姿态）。
  两者**独立懒加载、并发 `Promise.all`**，无 flint 块的页/答案零加载。
- **安全闸硬编码**（决策P4.20-4/-5，§4 是本相位实质）：入口只收白名单顶层键 + **拒 `data.url`（只认内联
  `data.values`）** → flint 生成式编译 → 出口断言（无 `image://` / 无 `http(s):` / 无带尖括号 `formatter` /
  `graphic` 仅 `type:'text'`）→ `renderer:'svg'` + `tooltip.renderMode:'richText'`（tooltip 不走 HTML 通道）。
- **资源闸**（决策P4.20-6，**结构化库接入带来的新问题**）：块源 > 64 K **字符**、`data.values` > 1000 行、
  或编译出的画布尺寸不是有限数 / 越界（宽 160–1600、高 120–1200）→ **不渲染**，保留源码 +
  `⚠ 数据过大` 徽标。**不静默截断**（沿决策P4.14-7 的「非静默」精神）。
- **实例生命周期**（决策P4.20-7，**前端第一个有状态渲染器**）：每次 `enhanceFlint` 先清扫 DOM 已脱树的
  ECharts 实例并 `dispose()`，避免切语言 / 切预览模式反复重绘泄漏实例。
- **优雅降级 + 错误兜底**：JS 关 / 运行时加载失败 / JSON 语法错 / 白名单拒绝 / 出口断言不过 / flint 抛错 / 超限
  → **`<pre>` 源码原样留存** + 错误徽标（`textContent` 注入）。永不空白、零未消毒注入。
- **昼澜主题**（沿决策P4.13-5）：一个常量把 ECharts 的 `color` 序列色板 / 文字色 / 网格色映射到 `app.css` 既有
  昼澜调色，**不引 ECharts 主题文件**、不预留深色档。
- **i18n**：两个 key 进 `i18n.js` 的 `zh`/`en`——`flint.renderFail`、`flint.tooLarge`。
- **配套一个独立的作者 skill `flint-chart-author`**（决策P4.20-11，**否则本相位是「通了电没有灯」**）：
  mermaid/LaTeX 模型本就会写，**flint 不会**——这是 P4.13/P4.14 没有的一片。它**不进** `guanlan-wiki`：
  作图是「拿到结构化数据 → 出一张合法图规格」的通用能力，与 wiki 维护（页型/frontmatter/wikilink/索引）
  是两条正交的轴；且本仓已有 `pdf-to-markdown` 这个同形态的辅助 skill 与之对齐。边界钉死为——
  **管**：选图型与编码、必要时聚合、生成/修复/解释/校验 flint 规格；
  **不管**：数据库连接与取数权限、wiki 维护、markdown 落在哪一页、浏览器渲染。

  ```text
  skills/flint-chart-author/
  ├── SKILL.md                    # 职责 / 触发描述 / 工作流 / 约束 / 不负责
  └── references/
      └── flint-spec.md           # 图型×通道表 + 常用语义类型 + 完整示例 + 常见错误对照（按需载入）
  ```

  触发描述（进 `SKILL.md` frontmatter 的 `description`，决定可发现性）：

  > 从结构化、表格或查询结果生成数据图表；选择适合对比、趋势、分布、相关性或层级关系的图型；
  > 生成、修复、解释或校验 Flint 图表规格。用户明确要求画图、可视化数据或输出 flint 块时使用。

### 不纳入 P4.20（按既有收窄推后）

- **服务端预渲染 / 导出图片** → 否（沿决策P4.13-2）：要背 headless 浏览器或远程服务，撞「零新重依赖」与
  「仅 `127.0.0.1`、离线自洽」。`flint-py` 服务端编译路**另有触发条件**（未发 PyPI、仅 `assemble_vegalite`，见研判笔记 §4）。
- **第二个渲染后端**（Vega-Lite / Chart.js / Plotly）→ 否（决策P4.20-2）：一个后端就够，多一个 = 多一份
  vendored 体积 + 多一片安全面，无实证需求。
- **图表交互**（`dataZoom` / 点击下钻 / 导出 PNG / 图例联动之外的一切）→ 否：本相位是**只读呈现**，
  不是 BI 面板。交互面 = 攻击面 + 状态面。
- **渲染时查库 / 自动刷新 / 实时数据** → 否（决策P4.20-12，见 §0.2）。
- **图表编辑器 / 输入即预览** → 否（沿 P4.13：Web 不是 live editor）。
- **CLI / MCP 端渲染** → 否（沿决策P4.13-7）：那俩是文本通道，CLI `query` 回字面 JSON（honest），
  MCP 回 markdown 原文由客户端自渲。
- **自动给页面注入图** → 否：画不画图是 Agent 综合 / 用户手写的**内容**决策，宿主只渲染既有块。
- **`graph.json` 出图** → 否：node-link 图是另一件事（见本文抬头）。
- **改 `check.py` / `search.py`** → 否（见 §4.4）：与既有确定性检查的两处交互都以**约定**规避，不动零-LLM 门禁口径。

## 3. 拾取、编译与渲染（`flint_enhance.js`）

```js
// —— 常量（决策P4.20-4/-6）——
const FLINT_MAX_CHARS = 64 * 1024;   // 围栏块源上限，**字符数非字节**（src.length 是 UTF-16 码元；
                                     // CJK 一字符 3 字节，叫 BYTES 会让人以为闸在 64 KB、实则放行约 192 KB）
const FLINT_MAX_ROWS  = 1000;        // data.values 行上限（实测：1000 点散点 ≈ 1050 个 SVG 节点 / 400 KB）
const FLINT_SIZE = { minW: 160, maxW: 1600, minH: 120, maxH: 1200 };  // 画布尺寸闸（决策P4.20-6）
const FLINT_TOP_KEYS = ["data", "semantic_types", "chart_spec", "field_display_names", "options"];
// 危险**键**清单（决策P4.20-4）：值一律被 ECharts 当文本画进 <text>，是键才决定它是不是链接/图片/HTML。
// **不含 `target`/`renderItem`**（决策P4.20-16，实现期实测修正）：前者只在与 `link` 配对时有意义、
// 而 `link` 已被无条件拒，单独的 `target` 是惰性的（`Sankey`/`Network Graph` 的 `links[].target` 是节点名）；
// 后者另走「必须是函数」规则（`Waterfall Chart` 的 renderItem 是 flint **自己**造的函数）。
const FLINT_BAD_KEYS = new Set(["link", "toolbox", "dataView"]);

// —— 懒加载：两个运行时并发，各自单例、失败不缓存（沿 P4.13/P4.14 范式）——
let _flintP = null;
function loadFlint() {                                   // ESM 动态 import（决策P4.20-3）
  if (_flintP) return _flintP;
  _flintP = Promise.all([
    import("/static/vendor/flint/echarts.js"),            // 自包含单文件 ESM → 具名导出，不挂 window
    loadECharts(),                                        // 注入 <script> → window.echarts（同 mermaid 姿态）
  ]).then(([flint, echarts]) => ({ assemble: flint.assembleECharts, echarts }))
    .catch((e) => { _flintP = null; throw e; });          // 失败不缓存、下次可重试
  return _flintP;
}

// —— 入口白名单：只放行五个顶层键；拒 data.url（决策P4.20-4/-5）——
function sanitizeFlintInput(raw) {
  if (!raw || typeof raw !== "object" || Array.isArray(raw)) throw new Error("bad-input");
  const inp = {};
  for (const k of FLINT_TOP_KEYS) if (k in raw) inp[k] = raw[k];
  const values = inp.data && inp.data.values;
  if (!Array.isArray(values) || !values.length) throw new Error("no-inline-values"); // data.url / 远端引用一律拒
  if (values.length > FLINT_MAX_ROWS) throw new RangeError("too-many-rows");
  inp.data = { values };                                             // data 只留 values，其余键丢弃
  // 列名存在性（决策P4.20-14）：flint 对不存在的列**不抛错**，静默产出空 series → 画出一张空图。
  // 列集取**全表并集**而非 values[0]：结构化库出来的行常常列不齐（NULL 列被整行省略），
  // 只看首行会把合法图误判成 unknown-field。行数已 ≤ 1000，全表并集是廉价的。
  const cols = new Set();
  for (const row of values) if (row && typeof row === "object") for (const k of Object.keys(row)) cols.add(k);
  for (const enc of Object.values((inp.chart_spec || {}).encodings || {})) {
    const f = typeof enc === "string" ? enc : enc && enc.field;
    if (f && !cols.has(f)) throw new Error("unknown-field");
  }
  return inp;
}

// —— 画布尺寸闸（决策P4.20-6）：flint **不钳制** baseSize——实测 {width:1e8} 直通 _width=100000123，
// {width:-5,height:NaN} 直通 NaN。故须「有限数」+「范围」两条：NaN 会让 echarts.init 拿到脏尺寸。
function checkedSize(w, h) {
  if (!Number.isFinite(w) || !Number.isFinite(h)) throw new RangeError("bad-size");
  if (w < FLINT_SIZE.minW || w > FLINT_SIZE.maxW) throw new RangeError("size-out-of-range");
  if (h < FLINT_SIZE.minH || h > FLINT_SIZE.maxH) throw new RangeError("size-out-of-range");
  return [w, h];
}

// —— 出口断言：**按键域**查已知危险键，不扫值域（决策P4.20-4）——
// 为何不扫值域：合法数据里就可能有 URL 串（AI/LLM 语境把模型卡/论文链接当类别名很常见），实测这类串
// 会原样进入产物 → 一条 /https?:/ 会把一张完全正常的图整张否掉。危险的从来是键不是值。
function assertSafeOption(opt) {
  (function walk(node) {
    if (Array.isArray(node)) return node.forEach(walk);
    if (!node || typeof node !== "object") return;
    for (const [k, v] of Object.entries(node)) {
      if (FLINT_BAD_KEYS.has(k)) throw new Error("bad-key:" + k);          // link/toolbox/dataView
      if (k === "image") throw new Error("image-ref");                     // graphic/背景的图片引用
      // renderItem 必须是**函数**（决策P4.20-16）：flint 自造的函数来自已钉版的 vendored 代码、
      // 用户 JSON 造不出函数；一个**字符串** renderItem 只可能来自版本漂移或注入，一律拒。
      if (k === "renderItem" && typeof v !== "function") throw new Error("bad-renderItem");
      if (k === "symbol" && typeof v === "string" && v.startsWith("image://"))
        throw new Error("image-symbol");                                   // ECharts 'image://<url>' 符号
      if (k === "formatter" && typeof v === "string" && /[<>]/.test(v))
        throw new Error("html-formatter");
      walk(v);
    }
  })(opt);
  for (const g of opt.graphic || []) if (!g || g.type !== "text") throw new Error("non-text-graphic");
  // 空图守门（决策P4.20-14 第二半）：列名全对、也不抛错，某些图型仍产出空 series——实测
  // Treemap / Sunburst Chart / Tree 只给 detail+size 时 `series[0].data === undefined`。
  const series = [].concat(opt.series || []);
  if (!series.length || !series.some((s) => s && (Array.isArray(s.data) ? s.data.length : s.data != null)))
    throw new Error("empty-series");
}

// —— 主流程 ——
async function enhanceFlint(container) {
  if (!container) return;
  sweepFlintCharts();                                                // 决策P4.20-7：先清扫脱树实例
  const blocks = container.querySelectorAll("pre > code.language-flint");
  if (!blocks.length) return;                                        // 早退：无图块零加载（懒）
  let rt;
  try { rt = await loadFlint(); } catch { blocks.forEach((c) => markFlintFailed(c, "renderFail")); return; }
  for (const code of blocks) {
    if (!code.isConnected) continue;                                 // await 期间可能被重绘
    const src = code.textContent;                                    // JSON 文本（浏览器已反转义）
    try {
      if (src.length > FLINT_MAX_CHARS) throw new RangeError("too-big");
      const input = sanitizeFlintInput(JSON.parse(src));
      // 编译：尺寸这件事**交还给 flint**（决策P4.20-19）——按栏宽拿 canvasSize 重编译，
      // 而不是编译完再改画布（那会把 flint 烤成绝对像素的图例挤出视口）。
      const opt = assembleFitted(rt.assemble, input, columnWidth(code));
      // 产物形态守门（决策P4.20-16）：某些「图型 × 编码」组合下 flint **不装配成 ECharts option**，
      // 而是静默回吐它自己的 Vega-Lite 形中间态（{mark, encoding}）——实测 Sunburst Chart 缺 color 即如此。
      // 少了这条，尺寸闸会把它误报成「数据过大」，把作者引向「删数据」这条错路。
      if (!opt || typeof opt !== "object" || !("series" in opt)) throw new Error("not-echarts-option");
      const [w, h] = checkedSize(opt._width, opt._height);
      for (const k of Object.keys(opt)) if (k.startsWith("_")) delete opt[k];  // 剥私有键（实测存在）
      assertNoSilentTruncation(opt._warnings);   // 决策P4.20-18：flint 自己的截断也不许静默
      for (const k of Object.keys(opt)) if (k.startsWith("_")) delete opt[k];
      assertSafeOption(opt);
      applyGuanlanPalette(opt, input.chart_spec.chartType); // 逐槽换色，语义色图型跳过（-13/-22/-24）
      plainTextFormatters(opt);                             // flint 的 HTML tooltip 压成纯文本（-25）
      // 先在**离树**的临时 figure 上 init + setOption，成功了才替换 <pre>（决策P4.20-15）。
      // 反过来做会漏一条失败路径：setOption 抛错时 <pre> 已脱树，markFlintFailed 拿到的 code
      // 其 parentElement.parentNode 为 null → 既贴不上徽标也回不去源码，页面留一个空 figure。
      // init 允许离树元素的前提是显式给 width/height——这里正好给了。
      const fig = document.createElement("figure");
      fig.className = "flint-rendered";
      // 主题走 init 第二参（决策P4.20-13）：**不**用 {...opt, ...THEME} 顶层展开——那会把
      // 主题里的 xAxis/yAxis 整块盖掉 flint 算好的轴字段与刻度。
      const chart = rt.echarts.init(fig, GUANLAN_FLINT_THEME, { renderer: "svg", width: w, height: h });
      try {
        chart.setOption({ ...opt, tooltip: { ...(opt.tooltip || {}), renderMode: "richText" } });
      } catch (e) { chart.dispose(); throw e; }   // 临时实例不泄漏，源码仍原样挂在树上
      code.parentElement.replaceWith(fig);        // 只有全程成功才动 DOM
      _flintCharts.add(chart);
    } catch (e) {
      markFlintFailed(code, e instanceof RangeError ? "tooLarge" : "renderFail");  // 保留 <pre> 源 + 徽标
    }
  }
}
window.enhanceFlint = enhanceFlint;
```

- **懒加载**：先 `querySelectorAll` 早退，**不含图的页/答案零加载**这 1.65 MB（沿决策P4.13-1）。
- **幂等可重入**：替换后原 `code.language-flint` 已离树，对同一 DOM 重复调不二次渲染；重绘路径由
  `enhanceContent` 挂在 `paintPage`/`paint()` 内部保证重增强（沿决策P4.13-8/P4.14-9）。
- **DOM 只在成功后动一次**（决策P4.20-15）：整条链（解析 → 白名单 → 编译 → 尺寸闸 → 断言 → init →
  setOption）**全部在 `<pre>` 还挂在树上时完成**，`replaceWith` 是最后一步。于是「任何失败保留源码」
  对**所有**失败点成立，而不只是编译期那几个；渲染期抛错时临时实例当场 `dispose`，不进 `_flintCharts`、
  不泄漏。
- **实例清扫**（决策P4.20-7）：
  ```js
  const _flintCharts = new Set();
  function sweepFlintCharts() {
    for (const c of [..._flintCharts]) {
      const dom = c.getDom && c.getDom();
      if (!dom || !dom.isConnected) { c.dispose(); _flintCharts.delete(c); }   // 脱树 → 释放
    }
  }
  ```
  切语言（`paintPage` 重设整页 `innerHTML`）/ 切 md↔源码（staging `paint()`）会让旧 `<figure>` 脱树，但
  ECharts 把实例挂在自己的**全局注册表**上——不 `dispose` 就是每切一次泄漏一份。**mermaid/KaTeX/hljs 都是
  无状态一次性渲染，没有这个问题；flint+ECharts 是前端第一个有状态渲染器**，这条是它独有的义务。
- **尺寸与自适应**（决策P4.20-17，**实现期实测推翻了设计稿的做法**）：**在 `init` 之前就把尺寸收到栏宽**
  （`fitToColumn`），而不是渲染成固定尺寸再让 CSS 缩。设计稿原写「产物带 `viewBox` → `max-width:100%` 即可缩」，
  实测两条都不成立：①ECharts 的 **浏览器端** SVG 渲染器**不写 `viewBox`**（只有 SSR 的 `renderToSVGString` 写）；
  ②即便补上 `viewBox`，`max-width:100%` 也**咬不住**——ECharts 把 `<svg>` 以 `position:absolute` 放进一个固定
  尺寸的容器 `div`，绝对定位元素的百分比相对那个 `div` 算，恒等于自身宽度（实测 544px 在 377px 的栏里纹丝不动）。
  故：**渲染前按 `<pre>` 的边框盒宽定尺寸**（ECharts 内部尺寸 == 显示尺寸 ⇒ 命中测试天然正确，收窄后 ECharts
  还会重新排版、标签自动旋转，比缩放定尺图更好读），另**补一行 `viewBox`** 兜底。窗口 resize 后不重排
  （**仍不引 `ResizeObserver`**），由 `overflow-x:auto` 兜底（实测：含图页与无图页的页面横向溢出量**相同**），
  下一次重绘（切语言/切页）自然按新栏宽重算。

## 4. 安全与资源分析（**本相位的实质**）　**\[决策P4.20-4/-5/-6]**

### 4.1 威胁模型

被投喂的 `raw/`、**以及经 MCP 接入的外部结构化库**，都可能夹带恶意载荷（P4-4 既有假设的自然延伸——
DB 里的一个字段值就是攻击者可控串）。载荷经 Agent 写进 ` ```flint ` 块，企图在编译/渲染链上取得同源脚本执行，
或让浏览器发起外部请求（数据外发 / 追踪像素）。

### 4.2 为何挡得住，逐层

1. **块内容永远是文本、且只经 `JSON.parse`。** 前端读 `code.textContent` 拿到 JSON 文本，**从不把它当 HTML 解析**；
   **JSON 里没有函数**——ECharts 的 `formatter`/`renderItem` 之类回调面在这条链上**天然不存在**（这是选 flint
   而非「让 LLM 直接写 ECharts option」的关键安全理由）。
2. **入口白名单（不是黑名单）。** 只放行五个顶层键、`data` 只保留 `values`。这是与决策P4.14-2 同一哲学：
   **KaTeX `trust:false` 式的白名单铰链**，而不是 MathJax 那种「全量包做减法」的脆弱黑名单。
3. **flint 是「生成式白名单」——用户 JSON 不能把任意键塞进 ECharts option。** flint 按 chartType/encodings
   从模板生成 option，**不 merge 用户私货**。实测三条走私路径（`chart_spec.chartProperties` 里塞
   `backgroundColor.image` / `graphic[type=image]`、顶层 `options` 里塞带尖括号的 `tooltip.formatter`、
   `chartProperties.symbol='image://…'`）产出的 option **与干净输入逐键相同**：无 `image://`、无 `http(s):`、
   无 `formatter`、无 `graphic`。
4. **出口断言（钉版之外的运行时守门），按键域而非值域。** 即便将来某个版本的 flint 在某图型下开始生成新形状，
   `assertSafeOption` 仍会在 `setOption` **之前**拦下危险**键**（`link`/`target`/`toolbox`/`dataView`/
   `renderItem`/`image`、`image://` 开头的 `symbol`、带尖括号的 `formatter`、非文本 `graphic`），并退回保留源码。
   **两条边界条件，都被实测钉住**：
   - **不扫值域**——合法数据里就可能有 URL 串（AI/LLM 语境把模型卡/论文链接当类别名很常见），实测这类串
     **会原样进入产物**，故一条 `/https?:/` 会把完全正常的图整张否掉。**危险的从来是键不是值**：值一律被
     ECharts 当文本画进 `<text>`，是键才决定它是不是链接/图片/HTML。
   - **不扫 SVG 字符串**——SVG 里恒含 `xmlns="http://www.w3.org/2000/svg"`，拿 SVG 扫 `http` 会全量误伤。
   补一条**它挡不住、也不该由它挡**的：ECharts 官方安全指南列的 `title.link` / `data.link` /
   `toolbox.dataView` / `dataset.transform` 等入口，实测在 flint 这条生成式管线上**当前不可达**
   （`Treemap`/`Sunburst Chart`/`Tree` 喂一列名为 `link` 的 `javascript:` 载荷，产物既无 `"link"` 也无
   `javascript:`；正常产物无 `toolbox`/`title`/`dataset`）。键域断言是**为将来的版本漂移**留的守门，
   不是在补一个现存漏洞——**不要据此把它扩写成通用 ECharts option 消毒器**（那条路是 MathJax 式的脆弱黑名单，
   决策P4.14-2 已经否过一次）。
5. **渲染产物不含 HTML 通道。** `renderer:'svg'` → 产物是 SVG DOM；`tooltip.renderMode:'richText'` →
   tooltip 作为图元绘制、**不走 HTML 字符串拼接**（ECharts 历史 XSS 多发于 HTML tooltip + 自定义 formatter，
   本相位把这条路整条关掉）。实测：把 `<img src=x onerror=alert(1)>` 当作类别名喂进去，SVG 里落成
   **转义文本**（`&lt;img …`），无 `<img`、无 `<script`、无 `foreignObject`、无 `<image>` 元素。
6. **失败封闭，且对渲染期失败同样成立。** 解析错 / 白名单拒 / 尺寸闸 / 断言不过 / flint 抛错 / 超限 /
   运行时加载失败 / **`init`+`setOption` 抛错** → 一律保留 `<pre>` 源码 + 徽标（`textContent` 注入）。
   保证它成立的是**顺序**（决策P4.20-15）：`replaceWith` 放在整条链的最后一步，失败时 `<pre>` 从未离开过 DOM。
   **任何异常路径都不产生未消毒注入、页面永不空白。**

### 4.3 残余风险与处置（**保守表述，不承诺产物绝对可信**）

沿决策P4.13-3/P4.14-4 的口径：**本期边界 = 入口白名单 + 拒 `data.url` + 三条资源闸 + 键域出口断言 +
`svg`+`richText` + 事务式替换 + 钉版 + 失败保留源码**，不把信任「完全压在」flint/ECharts 上。
①**钉版**（两枚资产的版本 + 字节 + SHA256 记 `vendor/README.md`），升级走**显式 PR 复核**——复核项固定为
「三条走私路径仍无残留 + 注入 payload 仍落成转义文本 + 产物仍带 `viewBox` + `baseSize` 仍不被上游钳制
（若上游开始钳制，尺寸闸不必撤、但复核结论要更新）」；②配置**硬编码**，页面/用户无任何放宽旋钮；③**CSP 收紧是独立加固、不扩本期范围**
（现状主 app 无 CSP，单开议题）。

### 4.4 资源面与「与既有确定性检查的交互」（**结构化库接入带来的新问题**）

前三类内容渲染器（mermaid/KaTeX/hljs）的输入都是**人手写的短文本**；flint 块的输入是**从数据库里取出来的行**，
体量分布完全不同。三处后果与处置：

- **浏览器**：SVG 渲染器的代价按**图元数**走，不按行数——1000 行折线图是一条 `path`，1000 行散点是 1000 个
  节点。实测（ECharts 6.1.0 SSR，散点）：**500 行 → 202 KB / 550 元素 / 16 ms；2000 行 → 816 KB / 2050 元素 /
  36 ms**。渲染时长不是瓶颈，**DOM 体量**才是（一页可能有多张图）。⇒ 行上限取 **1000**（≈1050 元素 / 400 KB），
  另加**画布尺寸闸**——因为 flint 对 `baseSize` **不做任何钳制**（实测 `{width:1e8}` 直通 `_width=100000123`，
  `{width:-5,height:NaN}` 直通 `NaN`），只卡行数拦不住一个 `baseSize` 就把浏览器打死的块。
  超限一律**不渲染、保留源码 + `⚠ 数据过大` 徽标**，不静默截断（截断出的图会**说谎**——比裸 JSON 更坏）。
- **检索噪音**：P5.0 的 BM25 会把块内 JSON 当正文索引，`{"模型":"model-a","评测得分":72.4}` 这类串会稀释页面主题词。
  ⇒ 本相位**不改 `search.py`**（那会动检索单一归口），以资源闸兜住上界 + 约定「图只画结论性的聚合结果、
  不搬原始表」（决策P4.20-11：写进 `flint-chart-author` 的 SKILL.md，作为通用作图纪律而非 wiki 专属规则）。
  **已知副作用，明写在此，不假装没有。**
- **`check.py` 的 `[[` 边角**：`WIKILINK_RE = \[\[([^\[\]\r\n]+?)\]\]` 对**围栏块不豁免**（只抹 HTML 注释），
  故理论上一段以嵌套数组收尾的 JSON（形如 `[[1,2]]`）会被当成 wikilink 而报 `wikilink.broken`。
  flint 的 `data.values` 是**对象数组**（`Record[]`），天然不产生该形状；⇒ **不改 `check.py`**（改它等于动
  零-LLM 门禁口径，是独立议题），由 `flint-chart-author` 的约束「数据用对象数组、单元格只放标量」天然覆盖
  （对象数组产生不了裸 `[[`）。
  注：这是**既有行为**（mermaid 块同样不豁免），非本相位引入。

## 5. 前端呈现与主题（`app.css` / `i18n.js`）

- **自适应宽**：`.flint-rendered{margin:.55rem 0;overflow-x:auto;text-align:center}` +
  `.flint-rendered svg{max-width:100%;height:auto}`——与 `.mermaid-rendered` 对齐。但**真正让图落在栏里的
  不是这条 CSS，而是渲染前的 `fitToColumn`**（决策P4.20-17）：ECharts 的 `<svg>` 是绝对定位、`max-width`
  咬不住它，这条 CSS 只在「渲染后又缩了窗口」时配合 `overflow-x` 兜底。
- **昼澜主题**（沿决策P4.13-5，最小常量、不预留切换）：**两半，缺一不可**（决策P4.20-13，实现期实测修正）。
  - **文字与轴** → `GUANLAN_FLINT_THEME` 常量，**经 `echarts.init(dom, THEME, opts)` 第二参传入**：
    `textStyle`（`--lan-ink` + 与 body 同一套字体栈）、`title`/`legend` 文字色、`categoryAxis`/`valueAxis`
    的 `axisLine`/`axisTick`/`axisLabel`/`splitLine`——**五档轴必须齐**
    （`categoryAxis`/`valueAxis`/`timeAxis`/`logAxis`/`singleAxis`，决策P4.20-23：漏档的轴会退回原厂灰）。ECharts 主题 schema 用的是 `categoryAxis`/`valueAxis`，
    与 flint 产物的 `xAxis`/`yAxis` **天然不撞键**，故不必自己深合并、也不会盖掉 flint 算好的轴字段与刻度
    （实测：轴标签全在）。
  - **序列色板** → **主题管不着**：flint 把 ECharts 默认色板**硬编码进产物**（顶层 `color` 数组 **+ 每个
    `series[].itemStyle.color`**），产物永远盖过主题。故另加 `applyGuanlanPalette(opt)`：只在**颜色键**
    （`color`/`borderColor`/`shadowColor`/`backgroundColor`/`areaColor`）上，把那 10 个默认色**按位**换成昼澜色板。
    这样既保住 flint 算好的「谁配哪一档」的配色分派，又不可能碰到数据文本（类别名/标签走的是别的键）。
    两条边界（决策P4.20-22/-24）：映射表从**产物自身的 `opt.color`** 现造（cat10/cat20/变体全覆盖），
    且**语义色图型整张跳过**（waterfall 拿颜色表示涨跌，换色会把「跌」画成绿的）。
  **不引 ECharts 主题 JSON、不 `registerTheme` 注册全局主题**（避免污染 + 多一个资产）。深色「夜澜」真落地时另加。
- **错误徽标**：`.flint-error` 贴在保留的 `<pre>` 上方，文案 `textContent` 注入（绝不 `innerHTML`）；
  两种文案分开——渲染/解析/安全闸失败 → `flint.renderFail`；超限 → `flint.tooLarge`（**不静默**，用户要能
  分辨「图画不出来」和「数据太大所以没画」）。**不做加载占位**（懒加载本地同源，沿 P4.13）。
- **i18n**（沿决策P4.7）：`i18n.js` 的 `zh`/`en` 各加两条，`test_web_i18n.py` 平价校验自动覆盖。
  切语言时图经 `paintPage` 重绘 → `enhanceContent` → 重新渲染（且旧实例被 `sweepFlintCharts` 释放）。

## 6. 决策记录

- **\[决策P4.20-1] 两个运行时（flint 编译器 + ECharts）vendored（非 CDN）+ 懒加载，归类为「内容渲染器」——
  延续决策P4-3 的有界破例（决策P4.13-1 / P4.14-1 同款）。** 守三条实质底线：无 CDN（随 wheel、离线自洽）、
  无构建（见决策P4.20-3）、不含图的页零加载。代价 = `web` extra 静态资产增 **1,653,326 B**（flint 531,443 +
  ECharts 1,121,883），**不到既有 `mermaid.min.js`（3,312,967 B）的一半**，量级可接受。若不接受，退路是
  「不渲染、保持字面 JSON」（决策P4.20-10 的 honest 回退本就常驻）。
- **\[决策P4.20-2] 后端只取 ECharts；否 Vega-Lite、否 Chart.js、否多后端并存。** ECharts：**单文件自包含
  UMD**、SVG 渲染器产物**带 `viewBox`**（纯 CSS 缩放）、时间轴原生、`renderMode:'richText'` 提供一个「tooltip
  彻底不走 HTML」的单旗铰链。Vega-Lite 要四个文件（vega 515,242 + vega-lite 252,198 + vega-embed 60,630 +
  vega-interpreter 5,709）且需 `ast:true`+解释器才免 `new Function`；Chart.js 虽小（208,518）但时间轴要再配
  date adapter（多一个依赖）、且只有 canvas（无 SVG 产物）。**只 vendored 一个后端**——多一个 = 多一份体积 +
  多一片安全面，无实证需求。
- **\[决策P4.20-3] flint dist 以 ESM 动态 `import()` 加载——与既有三件 vendored 资产（UMD + 注入 `<script>`）
  姿态不同，是本相位唯一的新机制。** flint-js 用 tsup 出 ESM+CJS，**不出 UMD、不出 `.min`**；但实测
  `dist/echarts/index.js` **零 bare import、零动态 `import(`**，是自包含单文件 ESM，浏览器可直接
  `import()`——**故仍无 npm、无打包链，决策P4-3 的「无构建」底线不破**。连带后果：`vendor/README.md` 里
  flint 那节的**升级校验步骤与其余三件不同**——不是 `tail` 看 UMD 尾巴，而是
  `grep -oE '(from|require\()["'"'"'][a-zA-Z@]'` 应空 + `grep -c 'import('` 应为 0，且 `assembleECharts` 仍为具名导出。
- **\[决策P4.20-4] 「内容→客户端」第三次破例的本期安全边界 = 入口白名单 + flint 生成式白名单 + 出口断言 +
  `renderer:'svg'` + `tooltip.renderMode:'richText'` + 钉版 + 失败保留源码；不承诺产物绝对可信。** 见 §4。
  三点与前两次不同、值得单记：①**JSON 输入天然无函数**，回调注入面不存在（这是选 flint 而非让模型直接写
  ECharts option 的核心安全理由）；②**白名单在入口、断言在出口**，中间的 flint 是生成式的——三条走私路径实测
  零残留；③**出口断言按键域、且只扫编译产物**——不扫值域（合法数据里就有 URL 串，实测会进产物，扫值域会
  误否正常图）、不扫 SVG（恒含 `xmlns="http://…"`，必然全量误伤）。**明确不做的事**：不把它扩写成通用
  ECharts option 消毒器——官方安全指南列的 `title.link`/`data.link`/`toolbox.dataView`/`dataset.transform`
  实测在 flint 管线上当前不可达（§4.2-4），键域断言是为**版本漂移**留的守门，不是在补现存漏洞；
  往黑名单方向堆砌正是决策P4.14-2 否掉 MathJax 的那条老路。
- **\[决策P4.20-5] 拒 `data.url`、只收内联 `data.values`；渲染器永不发起网络请求。** 与 flint-mcp 的
  `--disable-file-reference` 同精神，也与观澜「离线自洽 / 本地全权 / 仅 `127.0.0.1`」姿态一致。副作用是图必须
  自带数据——这正是决策P4.20-12 想要的（图可从 markdown 100% 重建）。
- **\[决策P4.20-6] 资源闸三条：块源 64 K **字符**、`data.values` 1000 行、画布尺寸有限数且在
  宽 160–1600 / 高 120–1200 内；超限不渲染、保留源码 + `⚠ 数据过大` 徽标，不静默截断。**
  这是**结构化库接入独有**的问题：前三类渲染器的输入是人写的短文本，flint 块是查询结果。三条闸各有其因：
  ①**字符数不是字节数**——`src.length` 是 UTF-16 码元，CJK 一字符 3 字节，若把常量叫 `MAX_BYTES` 会让人
  以为闸在 64 KB、实则放行约 192 KB；②**行上限 1000 而非 2000**——代价按图元数走（实测散点 500 行 →
  550 元素 / 202 KB，2000 行 → 2050 元素 / 816 KB；折线图 1000 行只是一条 `path`），取 1000 是「最坏图型
  仍可接受」的档；③**尺寸闸不可省**——flint 对 `baseSize` **不做任何钳制**（实测 `{width:1e8}` 直通
  `_width=100000123`、`{width:-5,height:NaN}` 直通 `NaN`），只卡行数拦不住一个 `baseSize` 打死浏览器，
  且 `NaN` 会被直接喂进 `echarts.init`。截断后画出的图会**说谎**（读者看不出少了行），比裸 JSON 更坏——
  故沿决策P4.14-7 的「非静默」精神：宁可不画、也要让人看见「因为太大所以没画」。
  **三条闸值须与 `flint-chart-author` 的约束逐条对齐**（决策P4.20-11）——渲染器与作者对同一组数字有分歧，
  就等于让 skill 稳定产出会被拒渲的块。
- **\[决策P4.20-7] ECharts 实例须显式 `dispose`：每次 `enhanceFlint` 先清扫 DOM 已脱树的实例。**
  ECharts 把实例挂在自己的全局注册表上，而 `paintPage`（切语言）/ staging `paint()`（切 md↔源码）会重设整页
  `innerHTML` 使旧 `<figure>` 脱树——不清扫就是每切一次泄漏一份实例（含其事件与定时器）。
  **这是前端第一个有状态渲染器**：mermaid/KaTeX/hljs 都是一次性 DOM 变换、无此义务。清扫放在 `enhanceFlint`
  开头（而非某个卸载钩子），因为前端没有统一卸载点，而「每次增强前扫一遍」与既有「幂等可重入」范式同构。
- **\[决策P4.20-8] 服务端零改、转义姿态不破；载体 = `pre>code.language-flint`；`code_enhance.js` 与
  `language-mermaid` 并列跳过它。** 沿决策P4.13-4 / P4.14-5：不在服务端造 `<div class="flint">`（那要改转义
  姿态、走 stash、扩攻击面）。跳过高亮是显式化——`hljs` 本就没有 `flint` 语言、行为等价，但显式跳过让「谁负责
  这个块」在代码里一眼可见。
- **\[决策P4.20-9] 块内容只收 JSON（`JSON.parse`），不引 YAML 解析器。** flint 输入本就是 JSON；引 YAML =
  多一个第三方解析器 + 多一片解析歧义面（锚点/别名/隐式类型），收益仅是「少打几个引号」。解析失败 →
  保留源码 + 徽标，与其它失败同路。
- **\[决策P4.20-10] 优雅降级常驻 + CLI/MCP 不渲染。** 沿决策P4.13-6/-7：剥掉渲染层，页面退回 honest 的规格
  JSON，**零信息损失**（规格与数据都在块里）；CLI `query` 回字面源、MCP 回 markdown 原文由客户端自渲，
  不把 flint/ECharts 依赖渗进核心或 CLI。
- **\[决策P4.20-11] 渲染能力配套一个**独立**的作者 skill `flint-chart-author`，不塞进 `guanlan-wiki`。**
  与 P4.13/P4.14 的**关键差异**：mermaid/LaTeX 模型本就会写，**flint 是 2026 年的新语言、模型不会自发产出
  合法块**——没有作者侧供给，渲染器就是「通了电没有灯」。为何**独立**而非加进维护引擎的 `conventions.md`：
  - **职责正交**：`guanlan-wiki` 是知识库维护引擎（页型 / frontmatter / wikilink / 索引 / 写工作流），
    作图是「拿到结构化数据 → 出一张合法图规格」的**通用**能力，与库的领域约定无关；混进去会让维护引擎的
    触发面被一个无关能力污染。
  - **本仓已有同形态先例**：`pdf-to-markdown`（P4.6）就是一个与 wiki 约定无关的辅助 skill，
    `skill.py` 的 `AUX_SKILL_NAMES` / `install-skill` 幂等安装路径**已经泛化**——新增一个 skill 的交付成本
    ≈ 一行 `force-include` + 一个元组项，`tests/test_skill.py` 遍历 `BUNDLED_SKILL_NAMES` 自动覆盖。
  - **可复用**：它不依赖任何观澜概念，别的 KB / 别的 agent 拿去即用。
  **边界**（写进 `SKILL.md`，实现时不得越界）——输入：已有的结构化数据 / 表格 / 查询结果；职责：选图型与编码、
  必要时聚合、生成 / 修复 / 解释 / 校验 flint 规格；输出：可被 P4.20 渲染的 ` ```flint ` JSON 块；
  约束：内联对象数组、单元格只放标量、≤1000 行、画布尺寸合法（对齐决策P4.20-6，闸值必须与渲染器一致，
  否则作者产出的块会被自己人拒渲）；**不负责**：数据库连接与取数权限、wiki 维护、markdown 存放位置、浏览器渲染。
  **体量与来源**：需要教的「语言知识」很小，一页 reference 足够——① **图型 × 编码通道表**共 37 行、**1,435 B**，
  且可由 vendored 资产**确定性生成**（`ecAllTemplateDefs` 是导出的数据，升级时重跑即可、不会与钉版漂移）；
  ② `semantic_types` **可整段省略**（实测：只给 `data`+`chart_spec` 即可编译，flint 自行推断），故语义类型表
  **不是入门必需**——且它也不大：上游 README 称「70+」，`flint-chart@0.4.1` 的 `SemanticTypes` 枚举实为
  **45 个**（`Year/Quarter/YearMonth/Duration/Count/Quantity/Amount/Price/Percentage/Score/Rank/Category/…`），
  只列 AI/LLM 语境常用的十来个 + 一句「拿不准就不写」。
  **本期显式不写观澜专属规则**（「这张图值不值得进 wiki」「来源注记落在哪一节」）——那属于 `guanlan-wiki` 的
  领域约定，与作图能力正交，本相位不碰；skill 里只留一条**通用建议**：块外正文注明数据来源与取数时间
  （因为图是快照，见决策P4.20-12），**不作为 flint 规格的一部分、渲染器也不认任何自定义字段**。
  若将来观澜侧确实需要成文规则，另在 `conventions.md` 补，不占本相位。
- **\[决策P4.20-12] 图是快照：不做渲染时查库、不做自动刷新、不做交互下钻。** 数据整体内联 ⇒ 图 100% 可从那段
  markdown 重建（DESIGN 原则 1 在本相位的形态）、浏览器零出网、`check`/`graph`/`search` 全部原样复用。
  刷新数据 = 重新问答/ingest 产出新块，**不是**让前端去查库——后者会把一张图的可重现性绑死在外部库的当下状态上，
  并给前端开一条出网路径（与决策P4.20-5 直接冲突）。
- **\[决策P4.20-14] 空图守门，两半：入口查列名存在性（列集取**全表并集**）、出口查 `series[].data` 非空。**
  实测：`chartType` 拼错（`'Bar chart'` vs `'Bar Chart'`，**大小写敏感**）会**抛错**
  （`Unknown ECharts chart type: …`）→ 被 catch → 保留源码 + 徽标，安全；但
  `encodings.x.field` 写一个数据里没有的列名**不抛错**，产出 `series[].data: []` → 渲成**一张空图**。
  这是全链路上唯一「不报错也不降级」的失败模式，会**默默说谎**（读者以为「数据就是这样」），比裸 JSON 更坏——
  与决策P4.20-6 拒绝静默截断同一条理由。两处细节都是踩过才知道的：
  ①**列集必须取全表并集、不能只看 `values[0]`**——结构化库出来的行常常列不齐（NULL 列被整行省略），
  只看首行会把合法图误判成 `unknown-field`；行数已 ≤ 1000，全表并集是廉价的。
  ②**只查列名不够**——实测 `Treemap`/`Sunburst Chart`/`Tree` 在只给 `detail`+`size` 时列名全对、也不抛错，
  但 `series[0].data === undefined`。故出口再查一次「至少一个 series 带非空 data」，才真正堵死空图。
- **\[决策P4.20-13] 昼澜主题分**两半**：文字与轴走 `echarts.init(dom, THEME, opts)` 的**第二参**，
  序列色板走**按位替换**；不注册全局主题、不引 ECharts 主题 JSON、不预留深色档。** 沿决策P4.13-5：
  一个常量让图与界面同水墨澜色调即可。
  **为何主题走第二参而非 `{...opt, ...THEME}` 顶层展开**：主题要设轴线/网格色就得带 `xAxis`/`yAxis` 键，
  顶层展开会把 flint 算好的**轴字段与刻度整块盖掉**——这是浅合并的必然后果，不是配置疏忽。
  ECharts 原生支持传主题**对象**，且其 schema 用的是 `categoryAxis`/`valueAxis`，与 flint 产物的
  `xAxis`/`yAxis` **天然不撞键**（实测：flint 轴标签全在），故既不必自己深合并、也无覆盖风险。
  **为何色板还得单独来一手**（实现期实测**推翻**了设计稿「主题的 `color` 即可」的判断）：flint 把 ECharts
  默认色板**硬编码进产物**——顶层 `color: ["#5470c6", …]` **以及每个 `series[].itemStyle.color`**。
  option 永远盖过主题，故主题里写 `color` **完全无效**。改为 `applyGuanlanPalette(opt)`：只在**颜色键**
  （`color`/`borderColor`/`shadowColor`/`backgroundColor`/`areaColor`）上把那 10 个默认色**按位**换成昼澜色。
  这条边界很关键——**按位替换而非重排**保住了 flint 算好的配色分派；**限定颜色键**保证不可能碰到数据文本
  （类别名走的是别的键，哪怕某行数据的值恰好是 `"#5470c6"` 也不会被动到）。
  深色「夜澜」（决策P4-9 推后）真落地时另加。
- **\[决策P4.20-15] `replaceWith` 必须是整条链的最后一步：先在离树的临时 `<figure>` 上 `init`+`setOption`，
  成功才替换 `<pre>`；渲染期抛错则当场 `dispose` 临时实例、源码原样留树。** 反过来做（先替换再渲染）会漏掉
  一整类失败：`setOption` 抛错时 `<pre>` 已脱树，`markFlintFailed` 拿到的 `code` 其 `parentElement.parentNode`
  为 `null` → **既贴不上徽标也回不去源码**，页面留一个空 `<figure>`——这不是「降级得不好看」，是**静默空白**，
  直接违反决策P4.20-10 的「任何失败保留源码」。`init` 允许离树元素的前提是**显式给 `width`/`height`**，
  本相位正好给了（`_width`/`_height` 经尺寸闸校验），故这条修法零额外成本。
  **通用形态**：把「渲染」写成对 DOM 的**事务**——要么完整生效、要么完全没发生，中间态不落地。
- **\[决策P4.20-16] 出口断言的**误杀**边界（实现期新增）：`target` 移出黑名单、`renderItem` 改判「必须是
  函数」、另加「产物必须是 ECharts option」一条；且**37 个图型全链路扫一遍**作为常驻守门。**
  设计稿的黑名单是照着 ECharts 官方安全指南**推**出来的，没有对着 37 个图型**验**过。实现时把
  「每个图型 × 它正确的数据形状」逐个跑完整链（入口白名单 → 编译 → 尺寸闸 → 出口断言），一次揪出**四例误杀**：
  - **`Waterfall Chart`** 走 `series.type:'custom'`，其 `renderItem` 是 **flint 自己造的函数**——那是已钉版的
    vendored 代码，不是用户可控物（JSON 里造不出函数、flint 也不 eval 字符串）。⇒ 改判：`renderItem`
    **必须是函数**；一个**字符串** renderItem 才是版本漂移/注入的信号，那才拒。
  - **`Sankey Diagram` / `Network Graph`** 的 `series.links[].target` 是**节点名**（`{source,target,value}`）。
    ECharts 里 `target` 只在与 `link` 配对时才有意义（`'blank'`/`'self'`），而 `link` 已被无条件拒 ⇒
    单独的 `target` 是**惰性的**，移出黑名单。
  - **`Sunburst Chart`** 缺 `color` 通道时，flint **不装配成 ECharts option**，而是静默回吐它自己的
    Vega-Lite 形中间态（`{mark, encoding}`，无 `series`/`_width`）。⇒ 加一条形态守门
    `!("series" in opt) → not-echarts-option`，让它落到**诚实的**「渲染失败」文案上；否则尺寸闸会把它
    误报成「数据过大」，**把作者引向删数据这条错路**。
  更该记下的是**方法**：一条过滤规则的正确性有**两面**——「该拒的拒得住」和「不该拒的不乱拒」。
  前者靠打桩造危险产物来证（冒烟 5），后者**只能靠把全集跑一遍**。故 `scripts/smoke_p420.py` 里
  「37 个图型无一被误杀」是**常驻场景**，`vendor/README.md` 的 flint 升级复核清单里也钉了同一条——
  上游加图型或改产物形状时，这是唯一能在**用户遇到之前**发现「新图型被自家闸子吃掉」的地方。
- **\[决策P4.20-17] 自适应宽靠**渲染前按栏宽定尺寸**（`fitToColumn`），不靠 CSS 缩放；`viewBox` 手动补一行；
  仍不引 `ResizeObserver`。**（实现期新增，**推翻**设计稿「产物带 `viewBox`，纯 CSS 即可缩」的判断。）
  设计稿那句是拿 **SSR**（`renderToSVGString`）量出来的，搬到浏览器上两条都不成立：
  - ECharts 的**浏览器端** SVG 渲染器**不写 `viewBox`**（只写死 `width`/`height` 属性）；
  - 补上 `viewBox` 也没用——ECharts 把 `<svg>` 以 `position:absolute` 放进一个固定尺寸的容器 `div`，
    **绝对定位元素的 `max-width:100%` 是相对那个 `div` 算的**，恒等于自身宽度（实测 544px 在 377px 栏里不动）。
  也**不能**改用 CSS `transform` 缩放绕过：ECharts 的命中测试按**容器**尺寸换算坐标，容器与显示尺寸一旦不等，
  tooltip 就指错柱子——「看着对、点着错」比不缩更坏。
  故正解是在 `init` **之前**把尺寸收到栏宽：内部尺寸 == 显示尺寸 ⇒ 命中测试天然正确，且 ECharts 会按新尺寸
  **重新排版**（标签自动旋转/省略），比缩放一张定尺图更好读。量的是**待替换 `<pre>` 的边框盒宽**——它是块级、
  正好铺满所在栏，等于 `<figure>` 换上去会拿到的宽；不量父容器 `clientWidth`（含父级 padding，实测 415 vs
  真实可用 377，收窄不够、图仍溢出）。
  **仍不引 `ResizeObserver`**（沿决策P4.20-2 的「少一个状态源」）：窗口 resize 后不重排，由 `overflow-x:auto`
  兜底，下一次重绘（切语言/切页）按新栏宽重算。这条的验收也得**按基线比**——该 App 自身在 <430px 视口就有
  22px 固有溢出（`aside.wiki` 的 min-width，与本相位无关），所以冒烟 2 断言的是**含图页 ≤ 无图页**，
  不是绝对零溢出。绝对阈值会把别人的老问题记到本相位账上。

- **\[决策P4.20-18] flint **自己**的截断也不许静默：读 `_warnings`，见 `code:"overflow"` 就不渲染、
  保留源码 + 「数据被截断」徽标（第三条文案）。** 决策P4.20-6 拒绝的是**我们**静默截断；实现后才发现
  flint 内部同样会截断——`filterOverflow` 在类别/分面超预算时**整批丢掉**取值。它只对 x/y 轴画出可见的
  「...N items omitted」占位，**`color`/`column`/`row` 三个通道是无标记地丢**：30 个 color 类别的图，
  flint 只留下少数几个，读者看到的是一张「看起来完整」的图。而原实现在 `setOption` 前把所有 `_` 前缀键
  一并删掉，`_warnings` 随之丢弃——**同一条红线，在别人家的代码里破了个口子**。
  修法两点：①读 `_warnings` 必须排在剥 `_` 私有键**之前**；②文案是**第三档**而非并进「数据过大」——
  修法完全不同（前者要减**类别数**，后者要减**行数**，删行对前者一点用没有）。
- **\[决策P4.20-19] 按栏宽收窄靠 `chart_spec.canvasSize` **重编译**，不靠事后改 `init` 尺寸——
  「能让 flint 自己算的，绝不在事后改」。**（**推翻**决策P4.20-17 的做法，保留它的问题诊断。）
  P4.20-17 发现 CSS 缩放不可行、改成「渲染前按栏宽定尺寸」，但那仍是**在 flint 之外**定尺寸，
  于是撞上更深的一层：flint 把 `legend.left`/`graphic.left`/`grid` 按它自己算出的 `_width`
  **烤成绝对像素**（实测 `_width=562` 时 `legend.left=464`）。画布缩到 377 后 ECharts 照搬字面的 464，
  **整个图例被画到视口之外**，而 `grid.right` 仍占着位——绘图区塌到 137px，图还在、没有徽标、
  读者却分不清哪条线是哪个模型。窄气泡里 `grid.left+grid.right` 甚至超过画布宽，绘图区直接为负。
  正解是把尺寸这件事**交还给编译器**：拿 `canvasSize` 逐档收窄重编译（实测它是**布局提示不是硬钳位**：
  请求 377 得 492、请求 260 得 375，故取第一个真正 ≤ 栏宽的档），每一档产物内部都自洽。
  栏太窄时**放弃收窄**、用自然尺寸 + `overflow-x` 横向滚动——**宁可滚动，也不要一张图例被裁掉的图**。
  连带好处：一个荒唐的 `baseSize:{width:1e8}` 不再被判「数据过大」，而是被重编译成一张正常的图。
  **一般形态**：包装一个自己会做布局的编译器时，**参数要从入口进去**，不能在出口改结果——
  出口那边的数字彼此有约束，你只改得动其中一个。
- **\[决策P4.20-20] 画布闸**只留上界**；「非有限」与「过大」分成两档文案。** 原实现有 `minW:160/minH:120`
  下界，且把三类错误一并说成「数据过大」。两处都错：①**小画布不消耗资源**，闸子的存在理由是「别打死浏览器」，
  拒绝小图纯属误伤——flint 按语义定尺寸时小图很常见（实测 3/7/14 天的 `Calendar Heatmap` 分别只有
  96/96/114px 宽），而徽标还叫作者「先聚合再画」，那**只会让画布更小、永远修不好**；
  ②画布是 `NaN`/`Infinity` 时问题出在规格、跟数据量无关，说成「数据过大」同样把人引向删数据。
  ⇒ 只留 `maxW/maxH`，失败分档改用显式的 `flintKind` 而非 `instanceof RangeError`。
- **\[决策P4.20-22] 逐槽换色**跳过语义色图型**；名单由对 dist 穷举得出，升级时重跑。** 按色板槽位换色的前提是
  「这一槽只是第 N 个类别的颜色」。实测 waterfall 模板把颜色当**含义**用
  （`{startEnd:"#5470c6", increase:"#91cc75", decrease:"#ee6666"}`），于是按值替换把「涨」换成澜青、
  把「跌」换成海沫**绿**——**把跌画成绿的**，比配色不统一坏得多。名单不是猜的：对 `flint-chart@0.4.1`
  全包搜「非色板数组里的裸 hex 语义常量」，**只有这一处**。这条 grep 已钉进 `vendor/README.md` 的升级复核清单。
- **\[决策P4.20-24] 色板映射表从产物**自身的 `opt.color`** 现造，不硬编码 flint 的色板常量；昼澜备满 20 档。**
  原实现照抄了一份 10 色常量，而 flint 在类别数 > 10 时会切到 **cat20**（另有变体在第 10 槽就与 cat10 不同）——
  于是第 11 个序列之后原样留着 ECharts 原厂的橄榄/芥末/灰，**一半图例昼澜、一半原厂**。
  从产物自身取色板既覆盖全部变体，也不会随上游升级漂移；昼澜相应补到 20 档。
- **\[决策P4.20-23] 昼澜主题的轴档必须**五档齐**（categoryAxis/valueAxis/timeAxis/logAxis/singleAxis）。**
  ECharts 主题按**轴类型**分档合并。只给前两档时，flint 对 temporal x 产出的 `xAxis.type:"time"` 走
  `theme.timeAxis` 这一空档、退回原厂灰黑，于是同一张图两条轴不是一套色（Streamgraph 的 `singleAxis` 同理）。
  这类漏档**用一张类别轴的柱图是验不出来的**——冒烟原本就只验了那一种。
- **\[决策P4.20-25] flint 的 formatter 返回 HTML 串，须先压成纯文本再喂给 `richText`。**
  `renderMode:'richText'` 是安全铰链（决策P4.20-4）、不能撤；但 flint 给几乎每张图装的是一个**函数**
  formatter，返回 `<br/>` 分行的 HTML（部分模板还带 `<b>`）。richText **不解析 HTML**，于是标签被原样
  画成文字——hover 一张最普通的柱图会看到字面量「模型: model-a<br/>series0: 72.4」。
  ⇒ 不动铰链，改**喂给它的东西**：包一层把 `<br/>` 转成换行（richText 认 `\n`）、其余标签剥成文本。
  纯呈现修正，不放宽任何安全性质（产物仍只作为文本绘制，全程没有 HTML 解析）。
  **验收教训**：原冒烟场景 4 只断言「没造出 HTML 容器」——那条在 tooltip 全坏的情况下**照样绿**。
  「没走错通道」和「走对通道后内容是对的」是两件事，得各测各的。
- **\[决策P4.20-26] 动态 `import()` 的重试必须换 URL。** 三个前辈渲染器「失败不缓存 promise、下次可重试」
  的写法搬到 ESM 上**不成立**：按 HTML 的 module map 语义，失败的 `import()` 会把该 URL 的失败结果留在
  文档存活期内，重发同一 URL 立刻再 reject、根本不回服务端。一次网络抖动 ⇒ 整站的 flint 块在本次会话里
  **永远**显示「渲染失败」，只有整页刷新能恢复——而 mermaid/hljs/KaTeX 能自愈（它们每次新造 `<script>`）。
  ⇒ 重试时挂一个 `?retry=N`，让它成为 module map 里的新条目。**一般形态**：换了加载机制，就得重新验证
  那套「失败可重试」的假设，而不是照抄结论。

### `scripts/smoke_p420.py`（真浏览器，headless Chromium/Playwright，**不入 pytest**）

沿 `smoke_p415.py` 范式（真 socket + 预置 KB，不打真实 LLM）。验收串：

1. **渲染**：某 wiki 页含合法 flint 块 → 页面出现 `figure.flint-rendered > svg`（昼澜色板），非 JSON 源码；
2. **按栏宽渲染**（决策P4.20-17）：**先缩窄视口再开页** → 图宽 ≤ 容器宽、产物带 `viewBox`；
   随后再缩窗口（此时不重排）→ 页面横向溢出量**不超过同视口下无图页的基线**（该 App 自身 <430px 有固有溢出）；
3. **注入**：类别名塞 `<img src=x onerror=alert(1)>` → **不弹窗**，DOM 内无 `<img>`/`<script>`/`[onerror]` 元素，
   payload 以**文本**出现在 `<text>` 里；
4. **tooltip 不走 HTML**：hover 触发 tooltip → tooltip 内容作为图元绘制（`renderMode:'richText'` 生效验证），
   DOM 里**无**新增含原始 HTML 的 tooltip 容器；
5. **出口断言（键域）**：用打桩的假 `assemble` 返回一份带 `link` / `image` / 非文本 `graphic` 的 option →
   **不渲染**、保留源码 + 徽标；
5b. **断言不误伤**（决策P4.20-4 的反向用例）：类别名本身就是一条 URL（`"https://example.com/model-card"`）
    → **照常渲染**，URL 以文本出现在 `<text>` 里——证断言按键域、不扫值域；
6. **拒 `data.url`**：块写 `{"data":{"url":"http://…"}}` → 保留源码 + 徽标，**Network 面板零外部请求**；
7. **资源闸三条**：①3000 行数据块 ②`baseSize:{"width":1e8,"height":1e8}` ③`baseSize:{"width":-5,"height":null}`
   → 三者都保留源码 + `⚠ 数据过大` 徽标（**非** renderFail 文案），页面不卡死、不出现巨幅或 `NaN` 尺寸画布；
8. **坏 JSON**：块内写坏 JSON → 保留源码 + 渲染失败徽标，无未捕获异常；
8b. **空图守门两半**（决策P4.20-14）：①`encodings.x.field` 写一个数据里没有的列名 → 保留源码 + 徽标；
    ②`Treemap` 只给 `detail`+`size`（列名全对但 flint 产出空 series）→ 同样保留源码 + 徽标，
    **绝不出现一张空图**；③`chartType` 大小写写错（`'Bar chart'`）→ 同样保留源码 + 徽标；
8c. **列不齐不误杀**（决策P4.20-14 的反向用例）：首行缺某列、后续行有（模拟 NULL 列被省略）→ **照常渲染**、
    不报 `unknown-field`——证列集取全表并集；
8f. **★ tooltip 压成纯文本**（决策P4.20-25）：hover → SVG 文本里**无** `<br`/`<b>`/`</span>` 字面标签，
    且确有带数值的文本节点出现（tooltip 真出现了才算数）；
8g. **★ 语义色不被换色**（决策P4.20-22）：Waterfall → 产物里 `#91cc75`(涨) 与 `#ee6666`(跌) **原样在**；
8h. **★ flint 自己的截断也不静默**（决策P4.20-18）：`color` 通道 30 个类别 → 不渲染 + **「数据被截断」**徽标
    （与「数据过大」「渲染失败」三档可分辨）；
8e. **★ 37 个图型无一被误杀**（决策P4.20-16 的常驻守门）：把每个图型 × 它**正确的数据形状**注入页面跑
    完整链，要求 `figure.flint-rendered` **37 个、徽标 0 个**。这是「不该拒的不乱拒」这一面**唯一**的
    证法（打桩只能证「该拒的拒得住」）；首版正是在这里揪出 `Waterfall`/`Sankey`/`Network Graph`/`Sunburst`
    四例误杀。上游升级后**必跑**；
8d. **渲染期失败不留空白**（决策P4.20-15 的守门）：打桩令 `setOption` 抛错 → 页面里**仍是 `<pre>` 源码 + 徽标**、
    **不存在空 `figure.flint-rendered`**，且存活实例数不增（临时实例已 dispose）；
9. **懒加载**：含图页与不含图页交替打开 → 不含图页**不加载**两枚 vendored 资产（Network 面板核）；
10. **离线**：断网起 `guanlan web` → 图照渲（零 CDN 请求）；
11. **切语言不打回源码 + 无泄漏**（决策P4.20-7 的回归守门）：切 zh↔en 十次 → 图仍是图，且
    `echarts.getInstanceByDom` 存活实例数**不随切换单调增长**（脱树实例已被清扫）；
12. **切预览模式**：暂存区 parsed 预览 markdown↔源码 来回切 → 仍成图；
13. **CLI**：`guanlan query` 命中该页 → 回**字面 JSON**（决策P4.20-10，不渲染、不回归）。
