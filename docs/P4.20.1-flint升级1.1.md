## 3. 需要实测的风险点

### 3.1 `graphic` 增多：新版会不会自己产出 `graphic`？

0.4.1 里的 `graphic` 主要出现在模板注释和自定义系列里；README 复核项 1 要求「三条走私路径仍零残留
（无 `graphic`）」，键域出口断言也针对它。1.1.1 多出 24 处，可能来自 1.1 的版面重写，也可能来自主题的
版头装饰（`chrome`：版头横线、标签、来源行）。要实测两件事：

- 不带 `theme_spec`、不带 `chart_spec.chrome` 的普通规格，37 个图型的产物里有没有顶层 `graphic`；
- 带 `chart_spec.label` / `source` 时 ECharts 后端画成什么（`title.subtext`？`graphic.text`？）。

如果新版在普通规格下就产出 `graphic`，出口断言会**误杀**整批图（决策P4.20-16 那类问题），需要裁定 §5-4。

### 3.2 `formatter` 增多：决策P4.20-25 的 HTML 压平还罩得住吗？

决策P4.20-25 把 flint 函数 formatter 返回的 HTML 串压成纯文本再交给 `richText`。新版多出 22 处 formatter，
可能是轴标签换行、分布图的值轴格式等。要实测：

- 新增的 formatter 是否都还是函数、是否都经过我们的包装（tooltip 之外的 `axisLabel.formatter`、`label.formatter`
  也要看）；
- 返回值里有没有新的 HTML 标签（`<br/>`、`<b>` 之外的），压平后显示是否正常；
- 注入 payload（`<img src=x onerror=alert(1)>` 当类别名）仍只落成转义文本（README 复核项 2）。

### 3.3 `field_display_names` 生效了

`FLINT_TOP_KEYS` 早就放行了 `field_display_names`，只是 0.4.1 不读，所以 skill 里写着「写了不报错也不生效」。
1.1.1 开始用它作轴标题和图例名。要实测：

- 显示名里放注入 payload，仍只落成文本（轴名、图例都走 ECharts 文本绘制，预期安全，但要验）；
- 显示名进 tooltip 时同样经过 §3.2 的压平。

验过之后，skill 可以改为推荐用它（比「在数据里改列名」干净）。

### 3.4 `canvasFit` 与按栏宽重编译

决策P4.20-17/-19：渲染前按栏宽定尺寸，靠 `chart_spec.canvasSize` 让 flint **重新布局**。1.1 新增的
`options.canvasFit` 会在画不下时「换一个更小的房间再排一次」，类型注释还写了「宿主可以缩放，但不超过 70%」。
要实测：

- 我们的 `FLINT_FIT_RATIOS`（1 / 0.75 / 0.55 / 0.4）逐档重编译与上游 `canvasFit` 叠加后，窄栏下是否仍不溢出、
  不出现双重缩小；
- `baseSize` 仍不被上游钳制（README 复核项 5），尺寸闸 `FLINT_SIZE` 的结论是否要更新；
- `_warnings` 里有没有新的截断类警告需要按决策P4.20-18 显示出来。

### 3.5 与 echarts 6.1.0 的兼容

1.1.1 不再声明 echarts peer 依赖，产物可能用到 6.1.0 之后才有的 option 键。冒烟时看浏览器控制台有无
ECharts 的未知键警告，以及 37 个图型是否都正常出图。

## 5. 裁定（2026-11-22，四项均按倾向）

1. **目标版本：1.1.1，还是先到 1.0.1？**
   倾向 **1.1.1**。1.1 的版面统一正是 ECharts 侧最有用的改进；1.0.1 → 1.1.1 的安全面差别不大，分两次升要多走一遍复核。
2. **新版不读的三个字段（`theme_spec` / `interaction_spec` / `updates`）：入口静默丢弃，还是提示作者？**
   倾向 **维持静默丢弃**，在 skill 里写明「观澜的 Web 端用 ECharts 后端，这三项不生效，不要写」。入口加提示会多一个状态
   和一条文案，而作者是 Agent，skill 里说清楚就够了。
3. **`field_display_names`：skill 改为推荐使用？**
   倾向 **推荐**，前提是 §3.3 的注入实测通过。数据里的列名保持原样（便于对照原表），显示名另给，比改数据列名干净。
4. **若 §3.1 发现普通规格也产出 `graphic`：放宽出口断言，还是在入口强制 `chrome:false`？**
   倾向 **先看产出的是什么再定**：若只是版头横线、文本这类 `graphic.elements[type=line|text]`，可以在出口断言里给
   这两种元素开窄口（仍拒 `image`、拒带 `onclick` 等事件键）；若来自 `chrome`，入口强制 `chrome:false` 更简单
   （我们没有主题，版头本来就是空的）。无论哪种都要补一条「本该被拦却被放过」的用例（反例测试，防闸子被悄悄放宽）。

## 8. 实测结论（2026-11-22）

全部在 headless Chromium 里执行 vendored 的 1.1.1（经观澜 Web 宿主加载，零外部请求）。

### 8.1 冒烟

| 轮次 | 结果 |
|---|---|
| 0.4.1 基线 | 18/18 |
| 换 1.1.1，未改代码 | 17/18：场景 3「注入载荷」失败——不是被注入，而是类别名里的尖括号被剥掉（§8.2） |
| 修正 `htmlToPlainText` 后 | **18/18** |

### 8.2 发现的问题：类别名被剥坏

- **现象**：类别名 `<img src=x onerror=alert(1)>` 在轴上显示为空，`<script>alert(2)</script>` 显示为 `alert(2)`。
- **原因**：决策P4.20-25 的 `plainTextFormatters` 包住产物里**所有**函数 formatter，`htmlToPlainText` 剥任意 `<…>`。
  0.4.1 的类目轴通常不装 formatter，碰不到类别名；1.1 为长名换行 / 截断给类目轴也装了函数 formatter（dist
  3924–3939 行），类别名经过它就被剥了。flint 拼 HTML 时**不转义数据值**（dist 里没有任何转义函数），所以
  类别名里的尖括号与 flint 自己的标签混在同一个串里。
- **性质**：呈现错误、不是安全问题——产物始终只作为文本绘制，修正前后都没有活元素、没有弹窗。
- **修正**：只剥 flint 自己会拼的标签。对 dist 穷举 `<\/?[a-zA-Z][a-zA-Z0-9]*`：0.4.1 与 1.1.1 都只有 `br` / `b` / `span`
  （另有一处 `<FlintChart` 在注释里）。新常量 `FLINT_MARKUP_TAG` 只认 `b|span`，`<br>` 转换行；首版的 `p/div/li/tr` 兜底
  flint 从未输出、只会误伤数据，一并去掉（代码评审发现）。同理**不再解 HTML 实体**：dist 里没有任何实体，flint 也不转义数据，
  串里的 `&amp;` / `&lt;` 只可能来自数据本身，解了就是把「A &amp; B」改写成「A & B」（代码评审发现）。
  代价：数据值里恰好写成 `<b>` / `<span …>` 的会被剥掉，比原先「剥任意标签」窄得多。
- **补的守门**：
  - 冒烟场景 3 原来只查「文字里出现 `<img`」，`<script>…</script>` 被剥成 `alert(2)` 它照样通过。现改为两段载荷都必须**原样**出现
    （1.1 会把长类别名折成两行、分在两个 `<text>` 里，比对时两边都去掉空白）。
  - `tests/test_web.py` 静态断言 `htmlToPlainText` 里不再出现 `/<[^>]*>/`（反例守门：防止有人改回去）。
  - vendor README 的升级复核项加一条「formatter 里的 HTML 标签仍只有 br / b / span」。

### 8.3 §3 各项

| 项 | 结论 |
|---|---|
| §3.1 `graphic` | 37 图型里有 9 个产出顶层 `graphic`，**全是 `type:'text'`**（图例标题，如「组」「类别」），出口断言本来就只放行 text。不需要放宽断言、也不需要强制 `chrome:false`——§5-4 无需动作 |
| §3.2 `formatter` | 37 图型的函数 formatter 落在四处：`tooltip`（27 个图型）、`legend`（8）、`series[].label`（2）、`xAxis.axisLabel`（2）。四处都经 `plainTextFormatters` 包装；tooltip 仍是纯文本、无字面标签（冒烟 ★ 项）。问题只出在类目轴，见 §8.2 |
| §3.3 `field_display_names` | 生效：轴标题用显示名。显示名放 `<img src=x onerror=alert(1)>` 与 `<b>数值</b>`，都原样画成文字、零活元素（轴标题不经 formatter）。skill 已改为推荐（§5-3） |
